# 开源社区AI-PR危机（2026年）

2026年5月，多个知名开源项目几乎同时遭遇AI批量生成的低质量Pull Request冲击，引发开源社区对信任机制和治理模式的系统性反思。

## 事件经过

### 导火索：vLLM虚假PR事件
2026年5月中下旬，[[vllm]]核心贡献者[[游凯超]]在知乎曝光：辅导机构指导学员向vLLM提交虚假PR，针对不存在的问题通过@大量维护者博取关注，试图借助维护者善意为简历"镀金"。社区在PR合并后迅速识别并举报。

### 连锁反应
事件曝光后，多个开源项目的维护者公开表达了类似困扰：
- [[godot]]首席维护者[[remi-verschelde]]在Bluesky上坦言AI生成低质量PR"令人精疲力竭"
- [[curl]]维护者[[daniel-stenberg]]关闭运行六年多的HackerOne悬赏计划，部署AI审查机器人
- [[tldraw]]宣布自动关闭所有外部贡献者的Pull Request
- [[gentoo]]开始将仓库从[[github]]迁移至[[codeberg]]

### 平台回应
[[github]]工程师在博客中承认"大规模低质量贡献"问题，承诺推出准入门槛等工具，但刻意回避将矛头指向AI本身。

## 根本原因

事件的核心驱动力是[[贡献-审查成本不对称]]：AI消灭了"贡献"的成本，却没有消灭"审查"的成本。详见[[ai低质量pr危机]]。

## 影响

- 标志着开源治理从"信任优先"向"验证优先"的范式转折点
- 暴露了[[开源pr镀金产业链]]的存在
- 引发对GitHub平台责任的质疑
- 社区自发开发反垃圾PR工具（Anti Slop GitHub Action、PR Slop Stopper）
- 开源贡献在简历上的信号价值面临系统性贬值风险
