# 微软强制断供Claude Code事件

2026年5月，微软发布内部通知，要求"体验+设备"部门（负责Windows、Microsoft 365、Outlook、Teams和Surface）近10万工程师在6月底前停用[[claude-code]]，强制转向自家的[[github-copilot-cli]]。

## 事件背景

微软工程师大规模使用Claude Code进行代码生成、代码库修改和代理执行。[[萨蒂亚-纳德拉]]曾披露"30%代码由AI生成"。然而，Claude Code按Token计费的模式导致账单持续攀升，微软作为[[anthropic]]算力底座的提供者，却要按Token向竞品付费。

## 决策过程

- 断供被内部定义为"紧急刹车"而非有序迁移
- 决策由财务部门主导
- 工程线一致反馈Claude Code生产力提升巨大
- 管理层因账单压力选择强制下线
- 官方辞令为"战略对齐"

## 财务逻辑

核心区别在于[[内部核算成本-vs-外部账单]]：GitHub Copilot属于内部核算成本，资源在Azure内部流动，边际成本极低；Claude Code是实打实的外部账单。微软给[[openai]]砸下130亿美元，还亲手在Azure上为Anthropic搭建算力底座，但按Token付费等于给竞品输血。

## 行业意义

这是AI工具市场第一次大规模的财务纠偏，标志着[[效用经济]]危机首次冲击超大型企业。当市值3.5万亿美元的微软都觉得"用不起"时，意味着AI正在从效率工具变成财务负担。

## 讽刺性

微软投了OpenAI 130亿美元，却在Azure上为Anthropic搭建算力底座，而自家工程师大规模使用Anthropic的Claude Code，导致微软按Token向竞品付费。看完账单后，这家巨头决定不再当"冤大头"。
