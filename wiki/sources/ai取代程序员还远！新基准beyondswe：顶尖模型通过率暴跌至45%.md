# AI取代程序员还远！新基准BeyondSWE：顶尖模型通过率暴跌至45%

## 摘要
本文报道了中国人民大学高瓴人工智能学院提出的全新代码 Agent 评测基准 [[beyondswe]]。该基准旨在解决现有 SWE-bench 仅覆盖“局部函数级修改”和“仓库内部知识”的局限性，通过引入跨仓库检索、领域知识修复、依赖迁移和从零构建系统四类任务，更真实地反映软件工程全貌。实验结果显示，顶尖模型（如 Gemini 3 Pro、GPT-5.2）的整体通过率从 SWE-bench 的 80% 暴跌至 45% 以下，暴露了当前 AI 编程模型在真实工程思维和复杂系统构建上的短板。

## 核心观点

### 现有基准的局限性
- **SWE-bench 的“开卷考试”属性**：仅覆盖 12 个仓库，平均修改 1.3 个文件，答案均可在仓库内部找到，无法反映真实软件工程的复杂性。
- **OpenAI 的弃用**：OpenAI 已宣布放弃将 SWE-bench Verified 作为内部评测标准，指出其已难以区分前沿模型的能力差异。

### BeyondSWE 的评测维度
文章提出了衡量 Code Agent 能力的两个核心维度：
1. **解决范围**：从单函数修改到全仓库构建。
2. **知识来源**：从仓库内部知识到外部/领域知识。

基于这两个维度，BeyondSWE 包含四类任务：
- **[[crossrepo]]**：考察从外部仓库或社区资源获取关键信息的能力（200条样例）。
- **[[domainfix]]**：考察在缺乏特定领域（如量子物理、生物信息）专业知识背景下的代码修复能力（72条样例）。
- **[[depmigrate]]**：考察处理破坏性依赖升级（如 NumPy 1.x 到 2.0）的全局架构适应能力（178条样例）。
- **[[doc2repo]]**：考察从零开始构建系统的能力，测试架构设计与模块化思维（50条样例）。

### 实验结果：近乎腰斩
- **整体表现**：没有任何模型的整体表现突破 45%。
- **DomainFix 最难**：几乎所有模型在该任务上的通过率都低于 36%，证明领域专业知识是真实壁垒。
- **Doc2Repo 的虚高**：虽然通过率看似尚可，但能 100% 通过所有测试的完整仓库极少，暴露了 Agent 架构能力的缺失。

### 搜索并非“银弹”
文章还介绍了 [[searchswe]] 框架，用于测试联网搜索能力是否能提升编程表现。结果发现：
- **策略优于频率**：[[gemini]] 3 Pro 平均每任务仅搜索 0.8-1.1 次，却获得了最好的整体增益（+2.0%）；而 [[deepseek-v4]] (文中称 DeepSeek-V3.2) 搜索频率最高（4.2-5.4次），效果反而微降。
- **融合难点**：搜索与编码的融合面临三大障碍——信息景观鸿沟（搜索引擎索引高层文档，代码需底层细节）、版本时间错位（搜到新版 API 用在老代码上）、语义漂移与噪声污染。

## 核心启示
文章提出了 [[deep-research-for-coding]] 的概念，指出单纯的搜索能力或代码生成能力都已成熟，但两者的有效融合（即知道何时搜、搜到了怎么用）是下一阶段进化的关键。BeyondSWE 和 SearchSWE 共同旨在推动 Code Agent 从“刷题者”进化为“工程智能体”。
