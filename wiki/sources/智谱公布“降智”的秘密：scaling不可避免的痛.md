# 智谱公布“降智”的秘密：Scaling不可避免的痛

## 概述
本文详细记录了智谱在 [[GLM-5]] 模型大规模应用过程中遭遇的工程挑战，官方称之为 **[[Scaling Pain]]**。文章揭示了在高并发、长上下文的 [[Coding Agent]] 场景下，推理基础设施面临的非确定性故障（如乱码、复读），并分享了从根因分析到工程落地的完整解决方案。

## 核心发现

### 异常现象
在处理数亿次 Coding Agent 调用时，GLM-5 出现了三类难以在本地复现的异常：
1.  **乱码输出**：生成无意义内容。
2.  **重复生成**：陷入死循环。
3.  **生僻字**：出现异常字符。

### 根本原因
通过分析 [[投机采样]]（Speculative Decoding）的指标（`spec_accept_length`），智谱定位到问题源于 **[[KV Cache]]** 的管理时序错误：
1.  **PD 分离架构下的竞态条件**：请求生命周期与 KV Cache 回收/复用时序不一致，导致跨请求的数据损坏。
2.  **HiCache 加载时序缺失**：KV Cache 换入与计算重叠时，缺乏显式同步，导致读取未加载完成的数据。

### 解决方案
1.  **显式同步机制**：在 KV Cache 回收和 HiCache 读取中引入严格的时序约束，确保写入不跨越内存复用边界。
2.  **LayerSplit 技术**：提出 KV Cache 分层存储方案，每个 GPU 仅存储部分层的 Cache，通过广播机制降低单卡内存压力。在 [[GLM-5.1]] 上的测试显示，该技术在长上下文（40k-120k）场景下将吞吐量提升了 10% 至 132%。

## 意义
本文打破了“模型强则服务强”的迷思，指出随着模型进入 Agent 应用阶段，**推理基础设施的工程稳定性**（而非单纯的模型能力）成为主要瓶颈。未来的 AI 竞争不仅是算法竞争，更是分布式系统工程的竞争。
