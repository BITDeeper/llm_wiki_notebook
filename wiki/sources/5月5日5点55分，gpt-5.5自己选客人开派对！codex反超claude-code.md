# 5月5日5点55分，GPT-5.5自己选客人开派对！Codex反超Claude Code

## 摘要
本文报道了 2026 年 4 月至 5 月间 AI 编程工具市场的重大转折点。OpenAI 的 [[Codex]] 在用户量和活跃度上反超 [[Anthropic]] 的 [[Claude Code]]。文章指出，尽管 Claude Code 在代码质量基准测试中仍保持领先，但 [[Codex]] 凭借稳定的价格策略、极高的 Token 效率（约为 Claude Code 的 4 倍）以及“瑞士军刀”式的产品定位，赢得了开发者的体感偏好。与此同时，Anthropic 因 [[Sentinel String Bug]] 导致的计费风波和试图将 Claude Code 移出 $20 套餐的商业策略失误，导致用户信任受损。

## 核心事件

### GPT-5.5 的“自主”派对
- **时间**：5 月 5 日下午 5:55（由 [[GPT-5.5]] 模型自己选定）。
- **策划**：[[Sam Altman]] 让 [[GPT-5.5]] 自己策划发布会，模型甚至指定了从推文回复中挑选客人的规则（由 [[Codex]] 执行）。
- **意义**：这被视为 OpenAI 对自家产品生态的高度自信，暗示 [[Codex]] 已成为其产品体系的中央位置。

### 市场格局反转
文章引用多项数据表明市场偏好发生转移：
- **用户偏好**：65.3% 的开发者倾向 [[Codex]]（按点赞加权达 79.9%）。
- **实际用量**：2026 年 4 月，[[Codex]] 的开发者用量首次超过 [[Claude Code]]。
- **下载量**：[[Codex]] 的 npm 日下载量约为 [[Claude Code]] 的 100 倍（4433 万 vs 44 万）。
- **周活**：[[Codex]] 宣布周活突破 300 万。

### 产品哲学对比
- **Claude Code（手术刀）**：深度优先，擅长处理复杂代码库和高难度重构，SWE-bench 得分更高，但 Token 消耗巨大。
- **Codex（瑞士军刀）**：广度优先，强调极低门槛、快速交付和 Session 稳定性，[[Sam Altman]] 称其正在经历 [[ChatGPT Moment]]。

## 关键技术事故：Sentinel String Bug
文章详细记录了导致 [[Claude Code]] 用户流失的技术根因：
- **现象**：用户在发送简单 Prompt 或使用 `--resume` 时，配额瞬间被耗尽（例如 3 分钟用掉 60%）。
- **根因**：Anthropic 内部用于追踪计费的 `sentinel` 字符串破坏了 [[Prompt Cache]] 的完整性，导致每次请求都被当作未缓存处理，成本增加 10-20 倍。
- **影响**：引发了社区愤怒，迫使 Anthropic 在 4 月 22 日承认问题并回滚相关定价策略。

## 商业策略失误
Anthropic 试图将 [[Claude Code]] 从 $20 Pro 套餐中移出，以覆盖高昂的 Token 成本。这一测试虽然符合商业逻辑，但破坏了用户对“平价高性能”的信任，被批评为“无意间给 OpenAI 递了刀子”。

## 结论
文章认为，这场竞争的核心不再是单纯的模型能力比拼，而是产品节奏、工程稳定性和商业策略的较量。[[Codex]] 的胜利在于它解决了“能不能不被掐断地干完一件事”这一开发者最痛的痛点。
