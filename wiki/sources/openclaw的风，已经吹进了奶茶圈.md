# OpenClaw的风，已经吹进了奶茶圈

## 摘要
本文记录了 [[openclaw]]（OpenClaw）在实体行业（古茗奶茶、银泰百货）的落地实践，揭示了 AI Agent 从“提效工具”向“[[数字员工]]”演进过程中面临的五大核心安全风险（端口暴露、Skills 陷阱、权限失控、成本与数据失控、体系性失效），并介绍了阿里云提出的基于 [[landing-zone]] 和最小权限原则的安全解决方案。

## 核心观点
- **范式转变**：Agent 实现了从“对话交互”到“自主执行”的跨越，成为人与数字世界的连接器。
- **安全是入场券**：在 Agent 规模化落地中，安全不再是加分项，而是必备的入场券。
- **风险本质**：Agent 的自主性带来了不可控性，传统的边界防护体系难以应对 [[agent-供应链攻击]] 等新型威胁。

## 关键案例
- **古茗**：遭遇 API 成本失控（无限循环调用）和端口暴露风险（默认 18789 端口）。
- **银泰百货**：因 Agent 权限过高，误将堡垒机端口判定为漏洞并关闭，导致全司运维瘫痪。

## 解决方案
- **最小权限原则**：仅授予完成任务所必需的权限。
- **环境隔离**：使用 [[landing-zone]] 构建 Agent 独立运行环境。
- **全链路审计**：建立 Agent 行为的可追溯、可定责机制。
