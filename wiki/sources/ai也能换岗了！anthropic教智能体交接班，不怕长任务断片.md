# AI也能换岗了！Anthropic教智能体交接班，不怕长任务断片

## 摘要
本文详细介绍了 Anthropic 为解决长时运行智能体（Long-running Agents）记忆缺失问题而设计的工程化框架。针对 AI 模型缺乏真正的长期记忆、上下文窗口关闭即“失忆”的痛点，Anthropic 提出了模仿人类工程师工作习惯的“双智能体架构”，通过环境状态持久化、渐进式推进和端到端测试，实现了跨越数小时的复杂任务连续执行。

## 核心观点
- **记忆缺陷**：AI 智能体没有真正的长期记忆，一旦上下文窗口耗尽或会话结束，所有状态都会丢失，导致无法完成持续数小时的复杂任务。
- **失败模式**：
    1. **贪多嚼不烂**：试图在一个窗口完成所有功能，导致上下文耗尽，留下未完成的半成品。
    2. **过早胜利**：后续会话的智能体扫描现有代码后，误以为项目已完成而停止工作。
- **解决方案**：通过工程化框架模拟人类团队的“交接班”机制，利用外部存储（Git、JSON 文件）保存状态，让无记忆的模型能够接力工作。

## 关键技术细节

### 双智能体架构
Anthropic 将任务拆分为两个角色：
1. **初始化智能体**：负责环境搭建，生成 `init.sh` 脚本、`claude-progress.txt` 工作日志文件，以及初始 Git 提交。
2. **编码智能体**：在后续会话中接手，每次只推进一小步，并保持环境处于“干净状态”（可随时合并、无 Bug）。

### 环境管理三板斧
1. **功能列表**：将用户提示扩展为 JSON 格式的完整功能需求文件（如 200 个功能点），初始标记为 `failing`，强制智能体按清单推进，防止误判完成。
2. **渐进式推进**：强制每次只做一个小步骤改动，并通过 Git 提交和进度文件总结，确保可回滚。
3. **端到端测试**：使用 [[puppeteer-mcp]] 等浏览器自动化工具模拟真实用户操作，发现仅靠代码审查无法发现的交互 Bug。

## 局限性与挑战
- **视觉盲区**：模型的视觉能力有限，无法识别浏览器原生 `alert` 弹窗等非 HTML 元素。
- **架构选择**：目前尚不清楚是通用编码智能体足够强，还是需要更细分的“测试智能体”或“代码清理智能体”。
- **领域迁移**：该框架主要针对 Web 应用优化，在科研、金融等领域的适用性尚待验证。

## 结论
通过将 AI 智能体的工作方式从“一次性生成”转变为“工程化迭代”，Anthropic 证明了即使模型本身没有长时记忆，通过合理的外部框架设计，也能完成复杂的全栈开发任务。这一理念与人类工程师的文档化、小步提交、自动化测试习惯高度一致。
