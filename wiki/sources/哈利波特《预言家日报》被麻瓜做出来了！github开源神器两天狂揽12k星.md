# 哈利波特《预言家日报》被麻瓜做出来了！GitHub开源神器两天狂揽12k星

## 摘要
本文报道了由前 React 核心成员 [[ChengLou]] 开发的开源文本布局库 [[Pretext]]。该库通过完全绕过传统的 DOM 测量方式，利用纯数学计算实现文本布局，在处理复杂排版（如文字绕图、多栏布局）时实现了比传统方式快 300 到 600 倍的性能提升。项目上线两天即在 GitHub 获得 12k 星标。

## 核心观点

### 性能瓶颈的根源
传统的 Web 文本排版依赖于 DOM API（如 `getBoundingClientRect` 或 `offsetHeight`）。调用这些 API 会强制浏览器进行**布局回流**，即重新计算整个页面的布局。在处理大量数据（如 500 条评论的虚拟列表）时，这种同步测量每帧可能耗时超过 30ms，远超浏览器 16.67ms 的渲染预算，导致页面卡顿。

### Pretext 的解决方案
[[Pretext]] 采用了一种“预处理 + 纯数学计算”的两阶段架构来彻底解决这一问题：

1.  **prepare() 阶段（一次性预处理）**：
    -   对文本进行分词并应用排版规则。
    -   利用 Canvas 的 `measureText()` API 获取词宽数据。
    -   **关键点**：此过程不触发布局，仅从浏览器字体引擎获取数据并缓存。
    -   耗时：约 17ms（仅一次）。

2.  **layout() 阶段（纯数学热路径）**：
    -   基于缓存的数据，在给定容器宽度下进行纯数学的换行运算。
    -   **零 DOM 读取**、**零 Canvas 调用**、**零字符串分配**。
    -   可被无限次反复调用（如窗口缩放时）。
    -   耗时：约 0.10ms。

### 性能对比
-   **传统方式**：500 条文本测量耗时 > 30ms/帧。
-   **Pretext 方式**：17ms (初始化) + 0.10ms (计算)。
-   **结论**：性能提升 **300 到 600 倍**。

## 应用场景

得益于极致的性能，[[Pretext]] 使得许多以前在 Web 上难以实现的复杂排版变得流畅可行：

-   **高精度虚拟列表**：提前计算所有文本高度，实现无卡顿的海量数据滚动。
-   **自适应气泡**：根据文本内容自动计算最紧凑宽度，无需 DOM 测量即可实现类似微信聊天的气泡效果。
-   **多栏杂志布局**：文本在多列间自动流动，窗口缩放时实时重排。
-   **动态图文混排**：实现类似《预言家日报》的效果，文本能毫秒级自动避让动态移动的插画（如喷火龙、Bad Apple 文字影绘）。

## 技术细节

-   **多语言支持**：支持中文、英文、阿拉伯语（双向文本）及复杂的 Emoji 宽度处理。
-   **跨浏览器一致性**：针对 Chrome、Safari、Firefox 等浏览器的排版差异进行了专门适配。
-   **渲染无关性**：计算结果可自由输出到 DOM、Canvas 或 SVG，甚至支持未来的服务端渲染。
-   **API 设计**：
    -   基础 API：`prepare()` + `layout()`。
    -   高级 API：`prepareWithSegments()` + `layoutNextLine()`，用于逐行控制（如文字绕排）。
    -   辅助工具：`setLocale()`（设置语言）、`clearCache()`（清理缓存）。

## 关键人物
[[ChengLou]]：前 React 核心团队成员，ReasonML 的创造者，曾参与 Midjourney 前端开发。他在前端工程化领域的深厚积累使得 [[Pretext]] 能够在底层架构上实现突破。

## 行业意义
[[Pretext]] 的出现标志着 Web 前端在排版领域的一次范式转移：从“查询 DOM”转向“数学计算布局”。这不仅解决了长期存在的性能痛点，也为 AI 时代需要处理海量文本和高动态交互的应用提供了新的基础设施。
