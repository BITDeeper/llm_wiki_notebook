# 太疯了！MIT博士在Transformer里造计算机，攻破LLM终极缺陷

## 概述
本文报道了 [[Percepta]] 团队（由 [[Christos Tzamos]] 领导）的一项突破性研究：通过将 [[WebAssembly (WASM)]] 解释器硬编码到 [[Transformer]] 模型权重中，实现了 [[内部计算]]。这一技术解决了大语言模型（LLM）无法进行精确算术和逻辑运算的“终极缺陷”，使模型能够在不调用外部工具的情况下，以极高速度（每秒 33,000 Token）执行复杂算法。

## 核心发现

### 1. 终极缺陷的终结
LLM 虽然具备强大的推理能力，但在处理“9.11 和 9.9 哪个大”这类基础算术问题时经常出错。传统解决方案是调用外部工具（如 Python 解释器），但这会打断推理链并增加延迟。Percepta 团队提出了一种“全内化”的方案：让 Transformer 本身变成一台计算机。

### 2. 技术实现：无损嵌入
- **机制**：将任意 C 代码转化为 WASM 指令 [[Token]]，模型通过自回归方式生成代表虚拟机状态（指令指针、内存、栈）的轨迹。
- **载体**：利用 Transformer 的注意力机制模拟图灵机的“纸带”，每一步计算追加到序列末尾（[[只增不减的轨迹]]），不可修改历史。
- **性能**：在 MacBook M2 Pro 上实现了超过每秒 33,000 Token 的解码速度（标准约为 27 tok/s），几秒内运行数百万步程序。

### 3. 工程创新：快速解码路径
标准 Transformer 的注意力机制随序列长度增加而线性变慢，不适合长程序计算。团队发明了 [[快速解码路径]]，通过限制注意力头回看先前的位置数量（二维限制），实现了计算速度的指数级加速。

### 4. 混合架构范式
这标志着 [[混合-LLM-架构]] 的诞生：神经网络负责模糊推理和理解，嵌入式解释器负责确定性计算。类似于 DSP 芯片架构（ARM 负责逻辑，DSP 负责计算），旨在同时解决推理能力和计算精度问题。

## 任务表现
- **数独求解**：在世界最难数独求解中达到 100% 准确率。
- **优化算法**：成功解决匈牙利算法（最小成本完美匹配）等多步优化问题。

## 行业反响
- [[Karpathy]]（Andrej Karpathy）对该研究表示高度赞赏，称其“深受启发”。
- 被视为对 LLM “概率预测机”属性的根本性改变，使其进化为“数字计算机”。

## 争议与挑战
- **通用性 vs. 效率**：工程师 Aviraj 指出，通用 WASM 可能不如针对特定任务设计的极简指令集（PSVM）高效。
- **黑盒问题**：将解释器嵌入权重使得模型决策过程更难解释，与 [[场景白盒化推理]] 的理念存在张力。

## 意义
这项技术不仅提升了模型的算术能力，更重要的是改变了 LLM 的本质定义。它为 [[ai-for-science]]、物理模拟、金融建模等领域提供了新的可能性，即模型可以内部运行数值计算，而不仅仅是生成文本。
