# 企业玩不转龙虾，是人的思维出错了

## 摘要
本文深入探讨了企业落地 AI Agent 遇到的困境，指出根本原因在于“人的思维滞后”——即试图用“以人为中心”的旧体系去套“Agent 为中心”的新技术。文章通过 [[MiniMax]] 和 [[腾讯云]] 的专家视角，提出了 [[Agent Native]] 的架构思维，并介绍了 [[Agent Runtime]] 和 [[Cube 安全沙箱]] 等原生基础设施解决方案。

## 核心观点

### 1. 思维范式的错位
企业落地失败的首要原因是不改变原有工作流，强行将 Agent 作为一个“插件”嵌入现有体系。
- **旧体系**：以人为中心，充满审批节点和权限控制（如 TAPD）。
- **新需求**：Agent 需要自闭环的权限和结构化的数据。
- **比喻**：在乡镇公路上开 F1 赛车（[[MiniMax]] 首席架构师 [[阿岛]]）。

### 2. Agent Native 转型
必须从“AI 辅助人”转向“人驾驭 AI”：
- **工作流重构**：以 Git 仓库为唯一真源，消除冗余审批。
- **角色转变**：人退居为输入输出节点和监督者（[[Harness]]）。
- **案例**：腾讯内部 TAPD 接入失败后，转向以 Git 为中心的成功转型。

### 3. 基础设施瓶颈
传统云基础设施（K8s, Docker）假设应用无状态、同质化，无法满足 Agent 的有状态、异质、长时运行需求。
- **技术惯性误区**：用微服务架构硬套 Agent。
- **解决方案**：[[Agent Runtime]] 原生基础设施，消灭 [[偶然复杂度]]。

### 4. Agentic RL 的挑战
[[MiniMax]] 使用 [[Agentic RL]] 训练模型，需要海量沙盒支持。
- **需求**：十万级并发沙盒，秒级启动，高度稳定。
- **传统架构痛点**：K8s Master 节点在几万并发下崩溃。
- **腾讯云方案**：
  - **计算**：内核级锁优化，秒级并发启动。
  - **存储**：块级去重、多级缓存、CoW 快照，支持分钟级数十万沙箱拉起。

### 5. 安全观念的进化
- **误区**：因噎废食，因安全担忧限制 Agent 权限。
- **未来**：Agent 可能拥有类似“企业法人”的权限地位。
- **技术保障**：[[Cube 安全沙箱]] 提供全隔离运行环境和权限管控。

## 关键实体
- [[阿岛]]：MiniMax Agent 首席架构师。
- [[Gary]]：腾讯云 Agent Runtime 产品副总经理。
- [[MiniMax]]：大模型公司，与腾讯云深度合作。
- [[腾讯云]]：推出 Agent Runtime 和 Cube 安全沙箱。

## 关键概念
- [[Agent Native]]：以 Agent 为中心的架构思维。
- [[偶然复杂度]]：非必要的复杂性，应由基础设施屏蔽。
- [[Harness]]：人类作为 Agent 的驾驭者。
- [[Agentic RL]]：智能体强化学习，需要真实沙盒环境。
- [[技术惯性认知误区]]：用旧技术栈假设生搬硬套新技术。

## 结论
企业应破除偏见，建立 AI Native 工作模式，从解决具体小问题开始构建 Agent，而非等待系统完美。未来衡量效率的标准将是“同时让多少个 Agent 为你打工”。
