# AI助手现在认路了：谷歌地图直接「长」进大脑

## 概述
本文报道了 [[Google DeepMind]] 对 [[Gemini]] API 进行的重大更新，重点介绍了工具混用、上下文环流以及 [[Google Maps]] 原生接入三大特性。这些更新旨在解决 AI Agent 开发中的工程化瓶颈，将开发范式从繁琐的手动编排转变为高效的声明式开发。

## 核心更新

### 1. 内置工具与自定义函数混用
- **旧模式痛点**：开发者需手动编排，先调用内置工具（如 Google Search），再手动将结果传递给自定义函数（如后端 API），流程割裂且代码量大。
- **新模式**：允许在同一个 API 请求中同时调用内置工具和自定义函数。
- **优势**：[[Gemini]] 自主判断调用顺序与衔接方式，显著降低延迟和代码量。

### 2. 上下文环流
- **定义**：一种自动化的上下文管理机制。
- **功能**：每一步工具调用的结果自动保留在上下文窗口中，供后续步骤直接引用，无需开发者手动转发数据。
- **技术细节**：引入工具调用 ID（Tool Response ID），确保在并行调用场景下能精准匹配返回值，提升调试效率。

### 3. Google Maps 原生接入
- **能力**：[[Gemini 3]] 全系模型原生支持 [[Google Maps]]。
- **应用场景**：实时查询商家营业状态、通勤时间、地点详情等。
- **意义**：赋予了 AI 真实的 [[地理空间感知]] 能力，补齐了 Agent 在物理世界交互中的关键短板。

## 行业影响
- **开发范式转变**：从“手动编排工具调用顺序”转向“[[声明式Agent]]”，即开发者只需声明可用工具，模型自主处理流程逻辑。
- **基础设施竞争**：文章对比了英伟达（NemoClaw）与谷歌在 Agent 基础设施上的不同路径，前者侧重硬件，后者侧重 API 层面的软件集成。
- **生产就绪度**：虽然推出了新的 [[Interactions API]]，但目前处于 Public Beta 阶段，官方建议标准生产环境仍以 `GenerateContent` 为主。
