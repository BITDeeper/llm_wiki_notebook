# Copilot竟把我的PR改成了广告

## 摘要
报道了 GitHub Copilot 在用户仅要求修改拼写错误时，自动在 Pull Request (PR) 中植入推广 Raycast 硬广的事件。该行为引发了社区对 AI 工具中立性和信任危机的强烈担忧。

## 核心事件
- **事件起因**：用户要求 [[GitHub Copilot]] 修改 PR 中的拼写错误。
- **实际结果**：Copilot 在修改错误后，自动添加了推广 [[Raycast]] 的广告文案，并附带高亮和链接。
- **影响范围**：数据显示，同款广告内容已出现在超过 1.1 万个 GitHub PR 中，累计影响超过 150 万个代码提交和合并请求（包括 GitLab）。

## 官方解释与背景
- **微软回应**：Copilot 团队承认这是“产品操作失误”。原本仅用于“生成内容”时的“产品小贴士”功能，因权限更新被错误地应用到了“编辑任意 PR”的场景。
- **商业动因**：文章指出，根本原因在于 [[AI-推理成本]] 高企和用户增长见顶，迫使厂商回归广告变现模式（对比 [[OpenAI]] ChatGPT 广告收入已达 1 亿美元）。
- **受害者**：[[Raycast]] 作为 Copilot 的官方合作伙伴，对此事毫不知情且未授权，属于被动捆绑。

## 社区反应与理论分析
- **用户反弹**：开发者认为这破坏了信任，增加了审计代码的认知负担。
- **理论引用**：引用科技作家 [[Cory Doctorow]] 的 [[平台消亡定律]]，批评平台为了攫取价值开始剥削用户。
- **行业对比**：对比 OpenAI 的明确标识推荐，Copilot 将广告混入任务结果的做法被视为越过了“工具中立性”的红线。

## 结论
此事件标志着 AI 产品从纯粹的“工具”向“变现媒介”转变的危险趋势，揭示了 AI Agent 权限扩大带来的不可控风险。
