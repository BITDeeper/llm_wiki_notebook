# 概述
本文报道了研究人员李博杰提出的“[[不可压缩知识探针]]”框架，该框架通过黑盒 API 调用测试模型对冷门事实性知识的记忆准确率，从而逆向估算其参数规模。研究估算 [[GPT-5.5]] 拥有约 9 万亿参数，[[Claude Opus 4.7]] 约 4 万亿，[[Gemini 2.5 Pro]] 约 1.2 万亿。这一结果在技术社区引发了关于方法论有效性、模型架构差异及算力成本的广泛争议。

# 核心内容

## 研究背景与方法
- **灵感来源**：团队长期测试模型对“[[中科大 Hackergame]]”（冷门 CTF 竞赛）的了解程度，发现模型随版本迭代对该赛事细节的掌握显著提升。
- **核心假设**：逻辑推理能力可通过训练技巧压缩，但事实性知识的记忆容量主要取决于物理参数规模，难以压缩。
- **数据集构建**：利用 AI Agent 历时四天构建了包含 1400 个问题（按稀缺度分为 7 个层级）的 IKP 数据集，并在 188 个模型上进行了测试。
- **拟合关系**：基于 89 个开源模型（1.35 亿至 1.6 万亿参数）的数据，拟合出事实准确率与参数量的对数线性关系（R² = 0.917）。

## 估算结果与争议
研究给出了闭源模型的参数估算（90% 置信区间约为 0.3 至 3 倍）：
- **[[GPT-5.5]]**：约 9 万亿参数。
- **[[Claude Opus 4.7]]**：约 4 万亿参数。
- **[[GPT-5.4]]**：约 2.2 万亿参数。
- **[[Claude Sonnet 4.6]]**：约 1.7 万亿参数。
- **[[Gemini 2.5 Pro]]**：约 1.2 万亿参数。

### 主要争议点
1. **数字合理性**：[[GPT-5.5]] 的 9T 参数估算被认为过高，与其性能提升幅度及现有基础设施支撑能力不符。
2. **方法论挑战**：
   - **合成数据干扰**：针对性微调可能显著提升冷门知识掌握度，破坏“不可压缩”前提。
   - **架构差异**：[[MoE (混合专家) 架构]] 与稠密模型在知识压缩效率上可能不同，未分开统计可能导致偏差。
3. **性能鸿沟**：[[Gemini 2.5 Pro]] 与国内模型（如 Kimi k2.6）参数差距仅约 2 倍，但体验差距巨大，难以仅用参数量解释。

## 附加发现
- **记忆偏好**：模型倾向于记住产生领域性影响的工作，而非高产学者。
- **时间系数**：过去三年模型的事实记忆容量并未随时间显著提升（时间系数接近零），反驳了 [[Densing Law]] 关于效率随时间提升的预测。

# 社区反应
- **支持方**：认为高拟合优度（R² = 0.917）支持了参数规模决定知识容量的观点。
- **反对方**：指出置信区间过大，且合成数据、架构差异等因素使得估算结果极为粗糙。
- **中立建议**：应将 MoE 模型与稠密模型分开统计，以观察更准确的规律。
