## 关键概念

- **动态工作流 (Dynamic Workflows)** — Claude Code 的新能力，允许 Claude 根据具体任务即时编写定制化 JavaScript 执行框架，协调多个子 Agent 并行工作。
  - 重要性：本文核心主题，解决大规模、高并行任务中的系统性失效问题
  - 维基状态：未收录

- **智能体懒惰** — Claude 在处理复杂多步骤任务时提前停止、宣称任务完成的失败模式。
  - 重要性：动态工作流的核心设计动机之一
  - 维基状态：未收录

- **自我偏好偏差** — Claude 倾向于偏向自己的结果或发现的倾向，尤其在验证/评估场景中。
  - 重要性：动态工作流通过隔离上下文窗口来规避此问题
  - 维基状态：未收录

- **目标漂移** — 在多轮操作中任务目标逐渐偏离，细节和约束条件丢失的现象。
  - 重要性：动态工作流的核心设计动机之一
  - 维基状态：未收录

- **分类并执行** — 动态工作流常用模式，用分类器 Agent 决定任务类型后路由到不同处理 Agent。
  - 维基状态：未收录

- **分发并汇总** — 将任务拆分为多个小步骤由独立 Agent 处理后汇总结果的模式。
  - 维基状态：未收录

- **对抗性验证** — 每个子 Agent 输出由另一个 Agent 对照评判标准进行对抗性验证的模式。
  - 维基状态：未收录

- **竞赛模式** — 多个 Agent 以不同方式执行相同任务，通过评判 Agent 两两比较选出最优的模式。
  - 维基状态：未收录

- **循环直到完成** — 对工作量未知的任务循环生成 Agent 直到满足停止条件的模式。
  - 维基状态：未收录

- **隔离模式** — 禁止读取非受信内容的 Agent 执行高权限操作，将权限分离给专门 Agent 的安全模式。
  - 维基状态：未收录

- **深度研究 Skill (/deep-research)** — Claude Code 内置的基于动态工作流的深度研究技能。
  - 维基状态：未收录

- **ultracode** — 触发 Claude Code 创建动态工作流的触发词。
  - 维基状态：未收录

## 主要论点与发现

- **核心论点**：动态工作流通过为不同目标分配独立上下文窗口的 Claude 实例，从根本上解决了单上下文窗口中的三类失败模式（智能体懒惰、自我偏好偏差、目标漂移）。
- **技术机制**：动态工作流执行包含特殊函数的 JavaScript 文件，可决定模型类型和工作树隔离方式，支持断点续跑。
- **与静态工作流的区别**：静态工作流（通过 Claude Agent SDK 或 `claude -p` 创建）需兼顾所有极端情况因而更通用；动态工作流由 Claude Opus 4.8 即时生成，针对特定用例定制。
- **六大常用模式**：分类并执行、分发并汇总、对抗性验证、生成并筛选、竞赛、循环直到完成。
- **七大应用场景**：迁移与重构、深度研究、深度验证、排序、记忆与规则遵循、根因调查、大规模工单分拣。
- **证据强度**：中等偏高——来自 Anthropic 官方工程师的一手经验分享，包含具体用例（如 Bun 的 Zig→Rust 迁移）和实操建议，但缺乏系统性基准测试数据。

## 与现有维基的关联

- **直接关联**：`claude-code`（核心工具）、`anthropic`（开发方）、`agent-view`（多会话调度界面，与多 Agent 并行主题相关）
- **概念关联**：
  - `1-n-agent调度` — 动态工作流是该概念的具体工程实现
  - `agentic-engineering` — 动态工作流是智能体工程的核心工具
  - `断点续跑` — 动态工作流明确支持此功能
  - `vlm质检闭环` — 对抗性验证模式是质检闭环的更通用形式
  - `办公技能框架` / `模型-技能分离架构` — 动态工作流可打包为 Skill 分发，与商汤的技能框架理念相通
  - `tokenmaxxing` — 文中明确警告滥用工作流会导致 Token 消耗远超预期
  - `ai-subscription-crisis` — Token 预算设定功能直接回应了订阅制危机

## 矛盾与张力

- **无直接矛盾**，但存在重要张力：
  - 动态工作流的强大能力与 Token 消耗之间的张力——文中多次警告"并非每项任务都需要工作流"，暗示过度使用的风险
  - 自动化程度提升与人类监督之间的张力——隔离模式下权限分离的设计反映了对 Agent 自主行动的安全顾虑
  - 文中提及的"自我偏好偏差"与维基中已有的"认知投降"概念形成呼应——两者都涉及 AI 输出的可信度问题，但从不同角度切入
