# 具身龙虾，上车理想

## 摘要
本文报道了理想汽车发布的全新流式视频理解与具身智能统一 Agent 框架——[[StreamingClaw]]。该框架在保持与 [[OpenClaw]] 兼容的基础上，原生支持实时多模态流式交互，解决了传统视频 Agent 在具身智能场景下延迟高、被动响应和难以处理长视频的痛点。

## 核心内容

### 技术背景与挑战
传统的视频 Agent 在处理实时感知（流式感知）时面临延迟较高的问题，主要原因包括：
- 将视频视为完整文件处理，长视频计算量呈指数级爆炸。
- 难以持续追踪长时程信息，导致决策草率或遗忘。
- 大多为被动触发，缺乏对环境风险的主动感知。

### StreamingClaw 架构
[[StreamingClaw]] 采用高度协同的 [[多代理架构]]，通过标准化流水线打破硬件壁垒：
1. **输入标准化**：通过 [[时间戳对齐]] 与 [[共享流式缓存]] 处理多模态输入。
2. **核心组件**：
    - [[StreamingReasoning]]（主代理）：负责实时感知与规划。
    - [[StreamingMemory]]（从代理）：提供长效记忆支撑。
    - [[StreamingProactivity]]（从代理）：负责主动交互决策。
3. **执行闭环**：决策指令驱动工具箱与技能库，形成“感知—决策—执行”闭环。

### 关键技术
- **[[流式推理]]**：在极低延迟约束下，对连续视频流进行即时分析。通过 [[增量计算]] 和 [[流式KV-Cache]] 优化，避免延迟堆积。
- **[[层级记忆演化]]**：将碎片记忆演化为“行动”和“事件”等高层级结构化经验，提升检索效率。
- **[[主动多代理调度]]**：实现从“被动响应”到“主动闭环”的转变，支持全天候在线监控与即时触发。

### 应用场景
- 驾驶中监控驾驶员（哈欠、玩手机）并主动预警。
- 取车时主动打招呼。
- 实时识别手持物品并解题。

## 局限性与展望
- 当前系统仍以“视觉+文本”为核心，对音频输入、精细时序对齐及跨模态联合推理的支持有限。
- 未来计划演进为统一的全模态代理框架，强化长时程建模与空间理解能力。
