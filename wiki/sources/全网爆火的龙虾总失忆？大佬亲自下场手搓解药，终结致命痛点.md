# 全网爆火的龙虾总失忆？大佬亲自下场手搓解药，终结致命痛点

## 摘要
本文报道了 TiDB 团队针对 [[openclaw]]（代号“龙虾”）记忆痛点推出的解决方案 [[mem9]]。文章指出，OpenClaw 虽然爆火，但其基于本地文件的记忆系统极其脆弱，容易在上下文压缩时丢失数据。TiDB 联合创始人 [[黄东旭]] 亲自下场，利用 [[tidb]] Cloud 的弹性与 HTAP 能力，构建了“一虾一库”的云端永续记忆服务，并深度集成了 OpenClaw 3.8 的 [[contextengine]] 接口，实现了记忆的可视化与全生命周期管理。

## 核心观点

### OpenClaw 的“失忆”痛点
- **原生缺陷**：OpenClaw 原生依赖本地 `MEMORY.md` 和 JSONL 日志，本质是“预算管理”而非真正的记忆系统。
- **上下文压缩风险**：Compaction 机制为了防止 Token 爆炸会裁剪上下文，导致 Agent 在任务中途“失忆”。
- **数据孤岛**：多 Agent 之间记忆无法同步，且依赖本地设备，换设备即“失忆”。

### mem9 的解决方案
- **云端永续记忆**：提供不依赖本地文件的持久化存储，支持跨设备同步。
- **一虾一库架构**：利用 TiDB Cloud 为每个 Agent 分配独立的数据库实例，确保数据隔离与安全。
- **零门槛接入**：无需注册或配置 API Key，通过一句话 Skill 即可安装。
- **记忆可视化**：上线 Memory Space Dashboard，让用户直观查看和管理 Agent 的记忆条目。

### 技术拐点：ContextEngine
- **接口开放**：OpenClaw 3.8 开放了 [[contextengine]] 接口，允许外部插件介入上下文生命周期（bootstrap, assemble, compact 等）。
- **深度集成**：mem9 不再是外挂存储，而是通过 ContextEngine 主导记忆的写入、召回和压缩逻辑，解决了多 Agent 协作中的记忆隔离与继承问题。

### 商业与架构逻辑
- **HTAP 优势**：Agent 记忆需要同时支持向量搜索（语义）、全文检索（关键词）和分析查询（模式识别），TiDB 的混合负载能力成为关键底座。
- **云端 vs 本地**：文章认为云端记忆体验优于本地，且 TiDB Cloud 的弹性伸缩能力支撑了百万级实例的低成本运行。
