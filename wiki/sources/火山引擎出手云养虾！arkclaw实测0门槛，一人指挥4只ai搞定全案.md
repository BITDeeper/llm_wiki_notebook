# 火山引擎出手云养虾！ArkClaw实测0门槛，一人指挥4只AI搞定全案

## 摘要
本文详细报道了火山引擎推出的云端 AI 智能体托管平台 [[ArkClaw]]。文章指出，随着本地部署 AI 智能体（“养虾”）热潮的退去，用户面临着配置门槛高、安全隐患大（如 CVE-2026-25253）和场景落地难等问题。ArkClaw 试图通过“云化”方案解决这些痛点，提供 0 门槛的浏览器端体验、四层安全防护体系以及与 [[飞书]] 的深度集成。

## 核心观点

### 本地“养虾”的困境
文章列举了本地部署 OpenClaw 等框架面临的“三无”问题：
1.  **无安全门槛**：引用了 CVE-2026-25253 漏洞（CVSS 8.8），该漏洞允许攻击者通过恶意链接窃取认证 Token。此外，安全研究员发现公网上有超过 4 万个实例未设认证，且 ClawHub 技能商店中存在大量恶意技能（感染率约 12%-20%）。
2.  **无成本优势**：本地部署需要服务器资源，且 Token 消耗不可控。
3.  **无场景落地**：用户往往不知道如何将智能体融入工作流。

### ArkClaw 的解决方案
ArkClaw 定位为“云上的 OpenClaw”，主要特点包括：
-   **0 门槛部署**：无需配置服务器或命令行环境，打开浏览器即可使用。
-   **模型支持**：默认搭载 [[Seed 2.0]] 系列（Pro/Lite），兼容 DeepSeek、Kimi 等主流模型，并支持生图模型 Seedream 和生视频模型 Seedance。
-   **深度集成**：与飞书实现“操作系统级”打通，支持扫码授权，允许 AI 直接操作文档、日历、任务及群聊回复。
-   **结构化搜索**：内置火山引擎联网搜索，直接返回结构化数据（如股票行情表格），而非非结构化网页片段，降低了 Agent 的处理成本。

### 安全架构
针对本地部署的安全风险，ArkClaw 构建了四层防护体系：
1.  **平台安全**：默认不暴露公网，强制认证，用户环境隔离。
2.  **供应链安全**：建立官方 Skills Hub，对所有上架技能进行代码审计和持续巡检，防止恶意软件注入。
3.  **运行时安全**：实施“事前预防、事中拦截、事后审计”。高危操作（如删文件、群发消息）需二次确认，防止失控。
4.  **身份与权限管理**：托管 API 密钥，仅向 Agent 提供临时令牌；遵循 [[最小权限原则]]，支持即时撤销授权。

### 实测案例
文章展示了三个具体应用场景：
1.  **编辑流**：从选题、开会（自动创建日历）、写稿（多轮修改）到配图，全程在飞书内闭环完成。
2.  **投资流**：自动抓取 A 股数据，生成包含涨跌停、板块热点的结构化简报，并定时同步至飞书文档。
3.  **调研流**：一人指挥 4 只 AI（3 名调研员 + 1 名文档专家）协同工作，生成深度调研报告。

## 结论
文章认为，“云养虾”是 AI 智能体从极客玩具走向普通人工具的必然趋势。ArkClaw 通过兜底安全和定义场景（如办公、投资），试图解决本地模式的痛点。
