# DeepSeek不惜代价保住它！V4关键特性被挖出来了

本文深入分析了 [[DeepSeek V4]] 技术报告中的一个核心工程哲学：为了保留 [[批次不变性]] 而不惜牺牲 GPU 利用率和推理速度。

## 核心发现

文章指出，DeepSeek V4 为了实现工程上的极致确定性和可复现性，坚持保留“批次不变性”设计。这意味着对于同一个 token，无论其在批次中的位置、批次大小或批次组合如何变化，模型的输出都能保持逐比特完全一致。

## 技术代价

为了实现这一特性，DeepSeek V4 放弃了常见的 GPU 性能优化手段：
- **放弃 Split-KV**：在注意力计算中，不再将计算分摊到多个流多处理器（SM）上，以避免改变并行归约路径。
- **限制 Split-K**：在矩阵乘法中，避免切开归约维度并行计算，以防止浮点加法归约顺序变化导致结果不一致。
- **自研 DeepGEMM**：在大多数场景中替代通用的 cuBLAS，以支持更受约束的批次不变矩阵乘法。
- **Dual-Kernel 方案**：为同一个注意力解码任务准备两套计算程序（分别处理高负载和低负载情况），同时保证结果逐比特一致。

## 工程价值

这种设计虽然增加了工程复杂度并降低了硬件利用率，但带来了关键优势：
1.  **全流程可复现**：确保预训练、后训练（SFT、RL）和推理全流程的数值对齐。
2.  **调试便利性**：消除了因 batch 组织方式或 kernel 路径变化导致的数值扰动，使异常更容易复现和定位。
3.  **复杂系统稳定性**：作为长上下文、MoE、量化等复杂组件的底座，锁定了底层执行系统的稳定性。
4.  **训练信号稳定**：在 RL 和蒸馏过程中，减少随机数值扰动，保证训练信号的稳定。
