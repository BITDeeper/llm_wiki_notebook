## 关键概念

### Agent = Model + Harness
- **定义：** Agent 的本质是模型（Model）加上外部框架/编排层（Harness），harness 已成为 Agent 生态的关键一环。
- **重要性：** 本文的核心架构观，强调 Agent 能力不只来自模型本身，更来自推理-执行-反馈的循环设计。
- **维基状态：** 不存在

### ReAct 循环
- **定义：** Agent 的核心架构：Reasoning（推理规划）→ Action（工具调用）→ Observation（环境反馈），本质是一个 while 循环。
- **重要性：** nanobot 的设计哲学基础，"大道至简"的体现。
- **维基状态：** 不存在

### CLI 作为 Agent 原生交互范式
- **定义：** 相比 GUI（为人类认知设计），CLI 更适合作为 Agent 与软件交互的原生语言，将软件包装为命令行接口让 Agent 直接驱动。
- **重要性：** 本文最核心的范式主张——"让世界适应 Agent，而非教 AI 做人"，从拟人化转向 AI 原生化。
- **维基状态：** 不存在，与现有 `runtime-agent-os` 概念互补

### Agent 自进化（Internal vs External）
- **定义：** Internal 模式优化 Agent 内核（框架、参数、推理链路），泛化性差；External 模式通过技能积累（skill）扩展工具库，泛化性强。
- **重要性：** 黄超团队选择 External/skill-based 路线，与 EvoMap 的自进化引擎形成不同技术路径。
- **维基状态：** `自进化架构` 已存在，但本文提供了更细致的 Internal/External 分类框架

### Agent Swarm 的 Scaling Law
- **定义：** Agent 集群协作存在最优临界规模，超过阈值后边际收益递减甚至产生负收益。实验显示 3-5 个 Agent 即达最优，8 个 Agent 协调开销可能超过性能增益。
- **重要性：** 对行业盲目堆 Agent 数量的趋势提出警示，揭示了协作瓶颈在于任务分解和冲突协调而非沟通成本。
- **维基状态：** 不存在

### Token 经济性 / Agent 自负盈亏
- **定义：** Agent 研究不应只追求能力上界，必须考虑 token 消耗成本，实现"自负盈亏"——在复杂任务中保持高成功率的同时大幅降低计算成本。
- **重要性：** 连接了 `tokenmaxxing` 和 `ai-subscription-crisis` 等现有概念，从 Agent 设计角度提出成本约束。
- **维基状态：** 不存在，与 `token作为生产资料` 强相关

### 长程任务鲁棒性
- **定义：** 长程任务的核心挑战不是时间长度，而是复杂性的指数级增长和错误传播。成功的 Agent 需要预期错误并实现优雅降级。
- **重要性：** 定义了 Agent 从"玩具"到"工具"转变的关键门槛。
- **维基状态：** 不存在

## 主要论点与发现

### 核心主张
1. **交互范式重构：** 不应让 Agent 适应人类界面（GUI），而应为 Agent 重新设计数字世界的交互协议（CLI），"让世界适应 Agent"。
2. **Agent 架构大道至简：** 通用 Agent 的核心是简洁的 ReAct 循环，不需要数十万行代码（nanobot 以极轻量实现同等功能）。
3. **Skill-based 自进化是最优路线：** 相比优化 workflow 或模型参数，通过技能沉淀实现自进化具有最强的泛化性。
4. **Agent Swarm 存在最优规模：** 不是越多越好，3-5 个 Agent 可能是最优协作规模。

### 支撑证据
- **nanobot 数据：** 连续100天日更，20万+下载量，DeepSeek 全球15个推荐 Agent 之一，OpenRouter 榜单第四。
- **CLI Hub 数据：** 80个软件、31个分类已包装为 CLI 接口。
- **Open Space 实验：** 44个行业、220个任务测试，进化后 token 消耗显著减少、任务完成度明显提升。
- **Swarm 实验：** 8个 Agent + 8张 H100，23小时内模型性能提升6%，相当于一个博士3周工作量；但3-5个 Agent 即达最优。
- **马里奥游戏开发：** 用 nanobot 开发完整游戏，验证长程任务中的测试和评估需求。
