# GPT-5.4据传下周上线！200万上下文窗口+持久化状态，告别频繁遗忘

## 概述
本文报道了关于 [[gpt-5.4]] 即将发布的传闻，基于 GitHub 代码泄露和社交平台截图。文章指出 OpenAI 可能跳过 GPT-5.3 版本，直接推出具备 200 万上下文窗口和 [[状态化-ai]] 能力的新模型，旨在从“聊天机器人”向“全自动代理”转型。

## 核心泄露证据
- **代码泄露**：OpenAI 工程师在 Codex 的 GitHub 仓库中提交了包含 `gpt-5.4` 标识的代码，随后被迅速改为 `gpt-5.3-codex`。
- **端点截图**：社交平台出现带有 `alpha-gpt-5.4` 标识的公共模型端点截图，原帖随后被删除。
- **版本跳跃**：种种迹象表明 OpenAI 可能跳过 5.3 版本，直接发布 5.4。

## 关键特性传闻

### 1. 状态化 AI (Stateful AI)
- **跨会话记忆**：模型能够在不同会话之间保留工作流、开发环境和工具调用状态。
- **解决痛点**：旨在解决传统大模型“金鱼般的记忆”，避免用户在每次新建对话时重复输入背景信息。
- **意义**：实现从“对话工具”到“全自动代理员工”的转变，提供持久的认知连续性。

### 2. 200 万上下文窗口
- **容量**：支持高达 200 万 Tokens 的上下文长度。
- **战略转移**：不再局限于常规推理基准测试的竞争，而是转向内存与上下文架构的比拼。

### 3. 全分辨率视觉直读
- **技术细节**：代码中发现针对 `gpt-5.4` 的功能开关，允许绕过图像压缩机制，直接读取原始字节。
- **应用场景**：支持对精细 UI 设计图或复杂工程原理图的像素级分析，解决多模态模型在处理高分辨率图像时的细节丢失问题。

## 硬件与成本影响
- **内存之战**：海量 [[KV 缓存]] 的增长对高带宽内存（HBM）和 SRAM 的调配提出了极限挑战。
- **光学互连**：为了应对算力需求，光学互连技术的引入可能从理论变为现实。
- **成本隐忧**：虽然文章未明确提及定价，但硬件成本的飙升可能加剧 [[ai-subscription-crisis]]。

## 竞争格局
- **对比竞品**：文章将 GPT-5.4 的野心与 [[Gemini]] 3.1 Pro 和 [[Claude]] 4.6 进行对比，指出后者仍在争夺基准测试的小数点优势，而 GPT-5.4 旨在重塑工作流。
- **代理化趋势**：强调 AI 正在从单纯的对话交互向后台自主执行多步复杂任务的代理进化。
