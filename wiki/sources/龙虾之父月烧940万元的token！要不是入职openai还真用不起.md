# Source: 龙虾之父月烧940万元的token！要不是入职openai还真用不起.md

## 关键实体

- **Peter Steinberger（龙虾之父/虾爹）** — 人物，核心实体。OpenClaw 的创建者，现已被 OpenAI 收购，领导 3 人团队使用 100 个 Codex 实例进行开发。已存在于 wiki（`peter-steinberger`）。
- **OpenAI** — 组织，核心实体。承担 Steinberger 全部 API 费用，计划将员工扩展至 8000 人。已存在于 wiki（`openai`）。
- **OpenClaw** — 产品/工具，核心实体。由 Steinberger 团队开发的开源 AI 智能体工具，是 130 万美元月度 token 消耗的主要去向。已存在于 wiki（`openclaw`）。
- **CodexBar** — 工具，外围实体。Steinberger 开发的 macOS 菜单栏工具，用于追踪 token 消耗，本次用于展示费用截图。已存在于 wiki（`codexbar`）。
- **GPT-5.5** — 模型，外围实体。Steinberger 最常使用的模型。已存在于 wiki（`gpt-5.5`）。
- **Clawpatch.ai / Vercel Deepsec / Codex Security** — 工具，外围实体。用于漏洞和安全分析的辅助工具。未存在于 wiki。
- **量子位（QbitAI）** — 媒体，外围实体。本文来源。已存在于 wiki（`量子位`）。

## 关键概念

- **多 Agent 群体协作** — 将任务拆分给大量小型 Agent 并行执行，而非构建单一超级 Agent。本文中 Steinberger 同时运行约 100 个 Codex 实例，彼此互相 Review、监督、补漏洞。可能未独立存在于 wiki（相关概念 `1-n-agent调度` 已存在）。
- **流水线化 Agent 协作** — 软件开发流程中，人类负责目标设定，Agent 负责执行，形成类似软件公司的分工结构。未独立存在于 wiki。
- **快速模式与成本权衡** — 激进的推理调度可提升 Agent 响应速度但大幅推高 token 消耗；关闭快速模式可降低 70% 成本。未存在于 wiki。
- **Agent 长时间稳定运行挑战** — Agent 持续在线面临上下文冗余、记忆臃肿、多 Agent 互相干扰等工程难题。未独立存在于 wiki。
- **token 作为生产资料** — 已存在于 wiki（`token作为生产资料`）。本文提供了该概念的极端案例：单人月消耗 6030 亿 token。
- **AI 订阅制危机** — 已存在于 wiki（`ai-subscription-crisis`）。本文从另一角度佐证：按量计费模式下，重度用户的实际成本远超订阅制承受范围。

## 主要论点与发现

- **核心主张：** AI 编程的规模化使用已进入"数字员工军团"阶段，3 人团队 + 100 个 Codex 实例可替代传统大型工程团队的部分职能。
- **关键数据：** 月消耗 130.5 万美元 API 费用、6030 亿 token、760 万次请求、每日 20.6 万次请求（约每秒 2.4 次），全部由 OpenAI 承担。
- **成本逻辑：** Steinberger 不将 token 费用与"工具成本"比较，而是与"旧金山高级工程师年薪"比较——关闭快速模式后月费约 40 万美元，仍低于一名高级工程师的年薪。
- **证据强度：** 强。基于 Steinberger 公开的 CodexBar 后台截图和 𝕏 上的直接陈述，数据具体且可验证。
- **次要信息：** Steinberger 同时在筹备多个新创业项目；OpenAI 计划将员工扩展至 8000 人（路透社 3 月消息）。
