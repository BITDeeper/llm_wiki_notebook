# Claude凭空造假强行部署，比黑客更可怕的入侵者！Vercel CEO紧急预警

## 摘要
Vercel CEO [[Guillermo Rauch]] 亲自披露了一起基于 [[Claude Opus 4.6]] 的 [[AI编程智能体]] 造成的安全事故。该智能体在执行部署任务时，未调用 GitHub 查询接口，而是凭空编造了一个 9 位数的仓库 ID，并成功将一份无关的学生作业部署到了企业生产环境中。这一事件揭示了 [[AI失效模式]] 与人类逻辑的根本差异，并引出了 [[包幻觉攻击]] 这一新型供应链安全威胁。

## 核心事件
- **肇事者**：基于 Anthropic [[Claude Opus 4.6]] 模型的 AI 编程智能体。
- **事故过程**：AI 在需要传入 GitHub 仓库 ID 时，没有进行查询，而是直接“脑补”了一个随机数字。
- **后果**：该 ID 恰好对应 GitHub 上的一个真实仓库（某学生的课程作业），导致错误代码被部署到生产环境。
- **关键特征**：AI 在犯错时表现出与正确时毫无二致的自信，没有任何犹豫或报错提示。

## 关键概念与论点

### AI失效模式
Rauch 指出，人类犯错通常是在正确答案附近波动（如拼写错误、逻辑偏差），而 AI 犯错是在整个解空间中随机选择。这种“自信的幻觉”使得下游系统无法区分正确参数和凭空捏造的参数。

### 包幻觉攻击
文章提出了一种新的攻击向量：攻击者无需主动入侵，只需注册大量潜在的包名或仓库 ID，并植入恶意代码，等待 AI 幻觉撞上门来。这标志着供应链攻击进入了“AI 诱导”的新阶段。

### 安全护栏
针对 AI Agent 的风险，文章建议：
1. 使用经过深度安全设计的集成工具（如 [[Claude Code]]）。
2. 增加 [[护栏]]（Guardrails）：在 AI 和真实系统之间增加验证层，检查参数来源的合法性。
3. 遵循最小权限原则：严格隔离读写执行权限。

## 相关背景
- 文章还提及 [[OpenAI]] 正在秘密开发代码平台以挑战 [[GitHub]]，反映了 AI 基础设施层面的竞争与动荡。
- 提及 [[OpenClaw]] 等工具面临的 [[提示注入]] 风险。

## 结论
当 AI 从“建议者”转变为“执行者”时，其幻觉风险从单纯的效率问题转变为结构性安全问题。开发者必须在赋予 AI 执行权限的同时，重新审视并构建严格的安全边界。
