# Claude Code源码首爆高危漏洞，偷拍毫无察觉！8100个库连夜封杀

## 概述

本文报道了 Anthropic 意外泄露 Claude Code 源代码（51.2 万行）后引发的一系列危机事件，包括 GitHub 大规模误删仓库风波、源码审计发现的高危安全漏洞（CVE-2025-59536）以及激进的用户数据采集策略。

## 核心事件

### 1. 源码泄露与误删风波
- **起因**：Anthropic 因内部疏忽，意外将 Claude Code 核心源代码打包发布。
- **扩散**：韩国开发者 Sigrid Jin 将代码上传至 GitHub，引发疯狂 Fork（超 10 万次）。
- **应对失误**：Anthropic 依据 DMCA 发起下架请求，但因 GitHub 操作失误，导致 **8100 个仓库被封杀**，而实际目标仅为 97 个（1 个原仓库 + 96 个 Fork）。
- **后续**：Anthropic 撤回了大部分请求，恢复了无关仓库的访问权限。

### 2. "无责备"文化的危机公关
- **回应**：Claude Code 之父 [[boris-cherny]] 承认这是人为和基础设施失误，强调团队拥有 **[[无责备文化]]**（Blameless Culture）。
- **观点**：错误源于流程、文化或基础设施，而非个人责任。团队已改进自动化流程以防止重演。
- **评价**：这种不追责个人、注重系统改进的态度赢得了舆论好评，被称为"体面"的危机处理。

### 3. 高危漏洞：供应链投毒
- **发现**：安全研究员和 B站 UP 主 [[jack-cui]] 审计源码，发现 **[[cve-2025-59536]]** 漏洞。
- **机制**：Agent 对当前目录下的配置文件缺乏防御。攻击者可通过修改 JSON 配置文件，在用户无感知的情况下调用摄像头、窃取密钥。
- **风险**：传统的防毒直觉（警惕可执行程序）已失效，纯文本配置文件同样具备杀伤力。

### 4. 激进的数据采集
- **明文存储**：所有被读取的文件、Bash 命令输出均以明文 JSONL 格式存储在本地。
- **自动上传**：启动时会发送用户 ID、会话 ID、邮箱、终端类型及功能标志至 Anthropic 服务器。
- **autoDream 功能**：后台扫描会话记录，提取信息写入 MEMORY.md，并注入未来的系统提示词回传 API。
- **保留期限**：Free/Pro 用户数据默认保留 30 天，共享训练数据的保留 5 年。

## 影响与建议

- **安全建议**：用户应立即升级至最新版本（`sudo claude update`），并检查本地环境中的恶意网络请求。
- **行业警示**：AI Agent 时代，便利性与安全性（供应链投毒）及隐私保护（数据裸奔）之间存在巨大张力。
