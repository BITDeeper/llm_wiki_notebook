# 摘要

本文报道了 [[Andrej Karpathy]] 关于 AI 编程时代开发工具演进方向的最新观点。Karpathy 认为，尽管 AI 已承担了大部分代码编写工作（他个人 80% 的代码由 AI 生成），但 [[IDE]] 并不会消亡，而是需要进化为管理 [[智能体编排]] 的“命令中心”。

# 核心观点

## 编程基本单元的转移
- **过去**：编程的核心是操作 `.py`、`.js` 等代码文件，IDE 用于编辑和编译这些文件。
- **现在**：[[智能体]] 成为开发中的核心执行单元。开发者只需定义目标和约束，Agent 即可生成可执行程序。
- **结论**：编程的基本单元已从“文件”转变为“Agent”。

## IDE 的新角色：组织架构设计师
Karpathy 通过对比亚马逊（层级制）、谷歌（网状）、微软（内部竞争）等大厂的组织架构图，提出了 **[[组织架构即代码]]** 的概念。
- 在人类公司中，组织架构难以复制（无法“Fork”谷歌的管理模式）。
- 在 AI 时代，开发者可以随意“Fork”并部署不同的 Agent 协作架构（如亚马逊式的层级管理或谷歌式的网状协作）。
- 未来的 IDE 将用于构建、运行和管理这些“数字组织架构”。

## 下一代 IDE 的功能需求
Karpathy 指出，现有的终端复用工具（如 [[tmux]]）仅能勉强满足需求，新一代 IDE 应具备以下特性：
1. **全局视图**：一键显示/隐藏任意 Agent，快速收起或展开视图。
2. **状态监控**：实时识别 Agent 状态（空闲、执行中、异常）。
3. **工具集成**：支持针对特定 Agent 快速弹出终端或调试工具。
4. **资源统计**：详细展示 Token 消耗量、计算资源占用、运行时长及任务完成率。
5. **指挥中心布局**：支持全屏或多显示器布局，提供宏观监控体验。

# 相关背景
- Karpathy 是 AI 编程领域的先锋，其开源项目 [[AutoResearch]] 主要由 AI 编写。
- 这一观点与 [[任务执行范式]] 的行业趋势相呼应，即从单纯模型开发转向智能体工程化系统。
- 文中提到的对 Token 消耗和计算资源的管理需求，与 [[ai-subscription-crisis]] 背景下的成本控制密切相关。
