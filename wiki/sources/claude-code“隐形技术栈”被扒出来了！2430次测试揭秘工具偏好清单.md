# Claude Code“隐形技术栈”被扒出来了！2430次测试揭秘工具偏好清单

## 概述

本文报道了 [[Amplifying.ai]] 针对 [[Claude Code]] 进行的一项系统性基准测试研究。该研究通过 2430 次测试，量化分析了 AI 编程代理在未被明确指示情况下的工具选择偏好，揭示了 AI 正在形成一套“隐形技术栈”。

## 核心发现

### 1. 倾向“自建”而非选用第三方工具
[[Claude Code]] 更倾向于编写自定义解决方案，而非直接推荐现成的第三方工具。[[自定义/DIY偏好]] 方案占所有主要选择的 12%（2073 次中的 252 次），成为最常见的选择。人工抽查确认约 80% 为真实的从零搭建场景。

### 2. 默认技术栈已然形成
Claude Code 在选择第三方工具时表现出高度集中性，核心工具包括：
- **部署**：[[Vercel]]（JS 生态 100%）、Railway（Python 生态 82%）
- **支付**：[[Stripe]]（91.4%）
- **UI 组件**：[[shadcn/ui]]（90.1%）
- **CI/CD**：[[GitHub Actions]]（93.8%）
- **数据库**：PostgreSQL
- **样式**：Tailwind CSS
- **包管理**：pnpm
- **监控**：Sentry
- **邮件**：Resend
- **状态管理**：Zustand

此外，模型会根据技术栈选择专属工具，例如 JS 项目用 Drizzle 做 ORM，Python 项目用 SQLModel。

### 3. 模型版本决定技术“年龄”
研究对比了 [[Claude Sonnet 4.5]]、[[Claude Opus 4.5]] 和 [[Claude Opus 4.6]] 三款模型：
- **Sonnet 4.5**：决策最果断，风格最保守，强烈偏好成熟、主流的工具。
- **Opus 4.5**：介于保守与求新之间，备选方案更多。
- **Opus 4.6**：最青睐最新、前沿的工具，同时最倾向于推荐自定义/DIY 方案。

这验证了 [[版本迭代梯度]] 现象的存在。

### 4. 上下文 > 指令
Claude Code 的工具选择高度依赖 [[项目上下文依赖性]]。在同一项目中用 5 种不同方式提问，选择稳定性平均达 76%；而在不同项目类型中（如 JS vs Python），选择会随技术栈切换。

## 实验方法

- **测试规模**：覆盖 3 款模型、4 种项目类型、20 个工具类别，累计 2430 次工具选择行为。
- **控制变量**：每条指令执行前均执行 `git checkout . && git clean -fd` 以确保环境纯净。
- **提示词策略**：采用开放式提示词（如“我应该用什么？”），完全不包含工具名称。
- **评估机制**：使用专门的子智能体提取核心工具推荐。

## 行业影响

1. **对工具厂商**：Claude Code 正在重塑行业工具的默认选择。若工具未进入 AI 助手的推荐列表，其在开发者工作流中的存在感可能逐渐弱化。
2. **对开发者**：一套由 Claude Code 主导的新兴技术栈正在形成。这些工具未必是“最优解”，却是模型最一致的推荐选项。
3. **对 AI 团队**：不同版本模型的行为特征差异真实存在且可量化，训练数据构成会直接影响工具推荐倾向。

## 相关概念

- [[隐形技术栈]]：指 AI 编程代理通过模型内在偏好形成的默认工具选择集合。
- [[自定义/DIY偏好]]：AI 倾向于编写自定义代码而非推荐现成库的现象。
- [[版本迭代梯度]]：不同版本模型在工具推荐上表现出的行为差异。
- [[项目上下文依赖性]]：AI 工具选择受项目类型影响大于指令措辞的特征。
