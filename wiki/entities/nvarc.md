# NVARC

NVARC 是英伟达特级大师团队（KGMoN：Ivan Sorokin 和 Jean-Francois Puget）在 Kaggle ARC Prize 2025 竞赛中的夺冠方案。该方案以 27.64% 的分数夺得冠军，击败了 Claude Opus 4.5 等巨型模型，且单次任务推理成本极低（约 20 美分）。

## 核心策略

NVARC 方案的成功建立在“合成数据”、“测试时训练”和“严谨工程化”的基础上，证明了在推理任务中，高质量数据和针对性微调比单纯扩大模型参数量更有效。

### 1. 合成数据流水线
团队没有依赖原本稀缺的几百个训练题，而是构建了一个包含 **320 万个增强样本** 的超级数据集。
- **收集描述**：收集 ARC 题目的人类自然语言描述。
- **混合重组**：利用 LLM 将不同谜题的描述“杂交”，生成 26 万+ 个新创意。
- **生成输入逻辑**：让 LLM 编写 Python 代码来生成输入网格，而非直接生成像素图，以捕捉逻辑本质。
- **生成输出逻辑**：让 LLM 编写将输入变换为输出的 Python 代码（即解题规则）。

### 2. 模型选择与训练
- **基础模型**：选用 **Qwen3 (4B 参数)**，而非巨型模型。
  - **原因**：推理速度快，且在海量高质量合成数据微调下表现优异。
- **训练框架**：使用 [[NeMoRL]] 框架和 [[Megatron]] 后端进行全量微调（SFT）。
- **资源消耗**：使用 4 个 8xH100 节点运行 27 小时。

### 3. 推理时优化
- **测试时训练 (TTT)**：对于每个新谜题，先利用其提供的示例通过 LoRA 快速微调模型，使其适应当前任务风格。
- **深度优先搜索 (DFS)**：模型生成 Python 代码作为答案，通过运行代码验证结果。使用 Batch DFS 算法批量生成多种可能的代码路径。
- **精度与优化**：推理时使用 bfloat16 精度，配合 Unsloth 框架和 FlashAttention2。

## 技术创新
- **代码即逻辑**：通过生成代码而非直接生成像素，使得推理过程可验证且逻辑更严密。
- **微型递归模型 (TRM)**：在比赛后期尝试引入 TRM，将递归推理与大模型直觉结合。

## 意义
NVARC 的胜利是对 [[scaling-law]] 的一种补充修正——Scaling 的对象从“参数”转向了“高质量的合成推理数据”和“推理时计算”。它展示了通过高效工程化（合成数据+小模型+TTT）可以大幅降低 AI 推理成本。
