# autoresearch

[[autoresearch]] 是由 [[Andrej Karpathy]] 开发并开源的一个自动化科研系统（及约 630 行代码的 Python 工具），旨在利用 AI Agent 在无需人类持续干预的情况下，长时间自主运行并完成模型训练、优化与迭代任务。该项目被视为 [[科研自动化]] 领域的一个里程碑，使得个人开发者仅凭一块 GPU 即可运行一个「永不下班的 AI 研究实验室」。

## 核心机制

### [[固定计算预算]]
项目的核心设计是强制每一轮训练精确控制在 **5 分钟**。无论 AI Agent 如何修改模型大小、批量大小或架构设计，训练时长必须固定。这一机制带来了两个好处：
1. **可比性**：所有实验结果在相同的计算预算下直接可比。
2. **硬件优化**：迫使 AI Agent 自动为特定的硬件环境寻找最优配置。

### 工程策略：锁定机制
为了在自动化与控制之间取得平衡，项目采用了严格的文件锁定策略：
- **规则**：Agent 只能修改 `train.py` 这一个文件。
- **其余文件**：全部锁定，禁止修改。
- **目的**：保持 diff 可审查，确保人类监督者能读懂 Agent 的操作，防止不可控的蔓延。

### 核心逻辑循环
autoresearch 的基本循环逻辑包括：
1. **设定目标**：明确研究目标。
2. **明确指标**：定义评估指标（如验证损失）。
3. **定义边界**：明确智能体的行为边界（如固定计算预算、文件锁定）。
4. **自主执行**：智能体自主执行实验并优化结果。

## 工作流程

项目逻辑基于一个自动化的循环流程，结合了人类指令与 AI 自主执行：

1. **人类角色**：编辑 `program.md` 文件，用自然语言描述研究目标和约束条件（即迭代提示词）。
2. **AI 角色**：在 Git 特性分支上自主循环运行：
    - 修改 `train.py` 代码。
    - 运行训练（固定约 5 分钟）。
    - 检查结果（如验证损失）。
    - 决定保留（提交）或丢弃（回滚）修改。
3. **结果**：一晚上可运行约 100 轮实验，第二天早上即可获得经过验证的改进模型。

## 项目结构

- `prepare.py`：数据准备（固定，AI 不修改）。
- `train.py`：训练代码（包含 GPT 模型定义、优化器等，AI 可修改）。
- `program.md`：人类写给 AI 的指令书。

## 实际成果

autoresearch 展示了极高的实验效率与优化能力：

- **单机运行**：在 Karpathy 的演示中，Agent 在他睡觉期间（约 12 小时）对 [[nanochat]] 仓库进行了 **110 次修改**，验证损失从 0.862415 降至 0.858039。
- **自主发现**：系统在一夜之间发现了 Karpathy 忽略的"值嵌入权重衰减"问题，并找到了更优的参数组合，证明了在目标明确、可量化的任务中，AI 往往能超越人类直觉。
- **扩展实验**：在初始运行中，AI 在两天内自主完成 276 次实验，将语言模型训练效率提升了约 11%。
- **超越人类表现**：在 Karpathy 完全放手不管的情况下，Autoresearch 在短短数天内超越了人类表现 **18%**。这一案例成为 [[递归式自我改进]] 从理论走向实证的重要标志——即使是人类智能的顶尖代表，在特定任务上也被自己创建的 AI 智能体快速超越。

## 衍生项目与社区

该项目的开源激发了社区的广泛参与，验证了 Karpathy 关于"模拟研究社区"而非"单个博士生"的哲学理念。主要的衍生项目包括：

- **[[autoresearch-at-home]]**：一种分布式协作网络模式，Karpathy 设想让互联网上不受信任的算力节点协同工作（类似 SETI@home），共同优化大语言模型，打破顶尖实验室的算力垄断。
- **[[auto-discovery]]**：专注于科学发现的衍生版本。

## 局限性

Karpathy 强调，自动化模式**只适用于目标明确、评估指标易于量化的任务**（如编写高效的 CUDA 核心代码或模型调优）。对于评估标准模糊或需要"软性判断"的任务，当前的自动化系统仍无能为力，人类往往是科研流程的瓶颈。

## 意义与愿景

autoresearch 被视为 [[agentic-engineering]] 范式的典型案例，展示了未来的科研工作流可能从「手动实验」转向「Agent 自主迭代 + 人类监督」。它降低了 AI 研究的门槛，将前沿研究从"碳水化合物计算机"（人类研究员）转移到了 AI Agent 身上，标志着 [[元优化]] 与 [[递归式自我改进]] 范式的落地。

Karpathy 认为，未来的科研组织本质上是一组定义角色和关联的 Markdown 文件（program.md），可以通过优化这些代码来提升研究效率。他希望通过打破传统的 [[git-master-branch-paradigm]]，让成千上万个智能体在不同分支上并行探索，从而模拟类似 [[seti-home]] 的分布式计算模式，实现科研效率的指数级提升。
