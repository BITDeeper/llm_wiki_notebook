# DeepSeek V4

[[DeepSeek V4]] 是中国 AI 实验室 DeepSeek 发布的最新一代大语言模型系列，包含 [[DeepSeek V4 Pro]]（高性能版）和 [[DeepSeek V4 Flash]]（轻量快速版）两个版本。作为 [[DeepSeek R1]] 的继任者，V4 传闻采用 [[原生多模态]] 架构，并优先适配国产 AI 芯片。根据梁文锋署名的最新论文及业内分析，V4 极有可能集成革命性的 [[engram]] 架构，标志着从单纯的计算优化转向“计算+记忆”双轴驱动。

截至 2026 年 4 月底，该模型已开始在 [[openclaw]] 等 Agent 工具生态中集成，官方已正式发布技术报告。

## 概述与发布状态

DeepSeek V4 代表了 AI 领域从单纯追求参数规模向追求工程确定性和场景专用化的转变。截至 2026 年 4 月，该模型尚未正式全面官宣，但通过网页端更新、社区泄露和第三方工具集成，已有大量关于其特性和能力的线索浮出水面。

关于 V4 的发布传闻从 2025 年底持续发酵，经历了多次“狼来了”式的虚惊：
- **参数泄露**：详细的模型参数和基准测试结果在社区流传。
- **服务器崩溃**：2026 年 3 月 29 日 DeepSeek 史诗级宕机恢复后，用户观察到了代码风格突变、绘图能力增强、知识库更新（知晓 2026 年时事）等现象，推测 V4 可能已通过 [[隐形进化]] 的方式上线。
- **模型自曝**：2026 年 4 月，有用户发现网页端上线的 [[deepseek-专家模式]] 自称是“V4”（参见 [[模型自曝]]），但官方未予证实。
- **当前状态**：多次推迟，原定于 2026 年 2 月（农历新年）发布，目前部分合作方已签署 NDA，且已在部分第三方工具（如 OpenClaw）中集成使用。

## 模型版本与规格

DeepSeek V4 并非单一模型，而是一个系列，目前主要包含以下版本。此外，网页端上线的 [[deepseek-快速模式]] 和 [[deepseek-专家模式]] 被广泛认为是 V4 能力的初步展示（专家模式实测上下文约 133K token，可能基于 V4 Lite 或 V3.3）。

| :--- | :--- | :--- |
| **参数规模** | 1.6T (激活 49B) | 284B (激活 13B) |
| **架构配置** | 61 层，隐藏维度 7168<br>1 个共享专家 + 384 个路由专家 | 43 层，隐藏维度 4096<br>1 个共享专家 + 256 个路由专家 |
| **定位** | 高性能，对标顶级闭源模型 | 轻量快速，注重响应速度与成本 |
| **编程能力** | SOTA，擅长复杂项目构建 | 接近 Pro，在创意/视觉任务上表现优异 |
| **世界知识** | 强大（稍逊于 Gemini-Pro-3.1） | 稍逊 |
| **适用场景** | 复杂推理、长上下文任务 | 快速原型开发、高并发 API 调用 |

### Agent 工具集成
- **[[openclaw]]**：在 4.24 版本中正式接入了 DeepSeek V4 系列，并将其 Flash 版本设为默认模型。这表明 DeepSeek V4 在工具调用、逻辑处理重放等 Agent 核心场景下经过了兼容性优化。
- **工程化验证**：通过在 OpenClaw 等高频自动化工具中的应用，DeepSeek V4 的稳定性和推理能力得到了实际场景的验证。据官方报道，DeepSeek 内部员工已弃用 Claude 转用 V4 进行代码任务。

## 核心特性

### 百万上下文标配
DeepSeek V4 是首个将 1M 上下文作为“水电煤”式标配服务的模型。这得益于其开创的全新注意力机制——在 token 维度进行压缩，结合 [[DSA]]（DeepSeek Sparse Attention）稀疏注意力，大幅降低了长上下文的计算和显存需求。

- **超长上下文**：支持高达 100 万 token 的上下文窗口，约等于《三体》三部曲的体量。得益于 [[Engram]] 条件记忆技术，这为实现 [[仓库级推理]] 提供了基础。
- **计算与显存优化**：
    - **计算成本**：在 1M 场景下，单 token FLOPs 仅为 [[DeepSeek V3|V3.2]] 的 27%。
    - **显存占用**：KV cache 仅为 V3.2 的 10%，有效缓解了 HBM 短缺问题。
- **低成本**：据爆料，其 API 成本可能比竞争对手便宜 50 倍，延续了 DeepSeek 一贯的低价策略。

### 原生多模态能力
与以往主要擅长文本和代码的版本不同，V4 是一个 [[原生多模态]] 模型，全家桶覆盖文本、图像、视频。据泄露信息显示，其轻量版 V4 Lite 在不开启思考模式的情况下，生成的 SVG 图像质量已超越了 V3.2 思考模型。

### 国产芯片深度适配
V4 最具战略意义的突破在于其对国产 AI 芯片的深度优化。DeepSeek 打破了行业惯例，未向 [[英伟达]] 提供早期接入权限，而是优先与国产芯片厂商合作。这标志着在推理阶段，V4 可能已实现国产芯片的全面适配，降低了对美系硬件的依赖。
- **硬件适配**：已完成 [[华为昇腾950]] 适配，预计 2026 年下半年昇腾 950 超节点批量上市。

## 技术架构

### 预期架构特性
根据 DeepSeek 与北京大学的联合论文（梁文锋署名），V4 预计将引入 [[engram]] 模块来解决 Transformer 的原生知识查找缺陷：
- **功能**：通过确定性查表处理静态模式（实体、固定搭配），释放 Transformer 主干用于推理。
- **收益**：在知识密集型任务（MMLU）和推理/代码任务上实现双重提升。
- **系统优化**：利用 Engram 的确定性特性进行更深层的系统优化（如预取策略），以实现“更大参数、同等吞吐”的目标。

### 架构创新细节
V4 在架构层面进行了多项底层创新，以支持其超大规模参数和高效推理：

#### [[mHC]] (Manifold-Constrained Hyper-Connections)
为了解决超深模型训练中的数值不稳定问题，V4 引入了流形约束超连接。通过将残差连接的混合矩阵约束到双随机矩阵流形上（行和列归一化为 1），保证了信号传播的稳定性。

#### 混合注意力机制
V4 采用了交替使用的 [[CSA]] (Compressed Sparse Attention) 和 [[HCA]] (Heavily Compressed Attention) 架构：
- **CSA**：负责 token-level 的精细检索，通过压缩和稀疏选择机制平衡效率与精度。
- **HCA**：负责长距离的全局信号汇总，通过重度压缩（每 128 个 token 压为一个）实现 dense attention。

#### 标准配方与演进
Meta 科学家 Zhuokai Zhao 指出，LLM 架构的前沿探索已基本收敛。DeepSeek V4 可能采用了以下标准配方：
- MLA (Multi-head Latent Attention)
- Sigmoid
- 稀疏专家
- 共享专家
- 无辅助损失
- DSA (Dynamic Sparse Attention)
- MTP (Multi-Token Prediction)

**技术演进路线**：
- **DeepSeek V2**：引入 MLA (Multi-Head Latent Attention)，大幅提升推理效率和 KV 缓存友好度。
- **DeepSeek V3**：优化 MoE 架构，实现无损负载均衡，降低训练成本。
- **DeepSeek V4**：引入 Engram 和 mHC，实现架构范式的跃迁，补齐“记忆”短板并解决深层训练稳定性。

## 工程哲学：确定性优先

与大多数追求极致推理速度和吞吐量的模型不同，[[DeepSeek V4]] 选择了“不惜代价”保住工程确定性。这意味着模型输出必须严格独立于批次组织方式、kernel 调度策略和底层归约顺序。

### 核心特性
- **逐比特可复现**：无论是在预训练、后训练（SFT/RL）还是推理阶段，对于相同的输入，模型必须产生完全一致的结果。
- **全流程对齐**：消除了因工程实现差异导致的数值噪声，使得研究人员可以确信模型行为的变化源于数据或算法调整，而非底层浮点运算的随机性。
- **批次不变性**：这是 V4 极其重视的技术特征，确保模型输出不随批次组织方式变化而改变。

### 技术代价与权衡
为了实现上述目标，[[DeepSeek V4]] 在性能上做出了显著牺牲：
- **GPU 利用率下降**：放弃了常见的 [[Split-K 优化]] 和 Split-KV 优化，导致在某些负载下 GPU 波前量化问题。
- **推理速度降低**：特别是在小批量或短序列场景下，速度受到影响。
- **工程复杂度激增**：无法依赖通用的基础库（如 cuBLAS），必须自研算子。

### 关键技术组件
为了弥补放弃通用优化带来的性能损失，DeepSeek 开发了专用的工程组件：
- **[[DeepGEMM]]**：自研的矩阵乘法算子库，用于替代 cuBLAS，在保证批次不变性的前提下执行 GEMM 运算。
- **[[Dual-Kernel]]**：在注意力机制层设计的双 kernel 策略，针对高负载和低负载场景分别优化，同时确保计算结果的一致性。

## 训练与对齐

### 预训练
- **数据量**：使用了 32T (Flash) 和 33T (Pro) 的 token，相比 V3 翻了一倍多。
- **数据构成**：单独收录了科学论文和技术报告等长文档数据。
- **训练调度**：序列长度逐步扩展（4K → 16K → 64K → 1M）。
- **优化器**：使用 [[Muon优化器]] 替代了传统的 AdamW，接管了绝大多数 2D 参数矩阵的优化。该优化器基于矩阵正交化，使用混合 Newton-Schulz 迭代将奇异值稳定在 1，从而保障了训练的稳定性。

### 后训练
引入了 [[OPD]] (On-Policy Distillation) 方法，替代了传统的 Mixed RL 阶段。流程分为两步：
1. 训练领域专家（数学、代码、Agent、指令跟随）。
2. 通过反向 KL 散度将这些专家的知识合并到一个统一的模型中。

## 性能表现

### 编程与代码能力
DeepSeek V4 在 [[Agentic Coding]] 方面达到了开源模型的 SOTA 水平。泄露的基准测试数据显示，V4 在代码能力上实现了巨大飞跃，据称是首个在编程能力上全面超越顶尖闭源模型的开源模型。

#### 实测表现
- **全栈构建**：能够独立规划并构建包含多模块的网站（如《怪奇物语》主题站），具备自动补全 UI、交互逻辑和内容的能力。
- **游戏开发**：在未明确规则的情况下，能自动生成完整的游戏逻辑（如宠物养成游戏的金币系统、难度曲线）。
- **仓库级推理**：具备理解一个文件中的变化如何影响项目中其他文件的能力，这对于处理大型代码库或复杂分布式系统的开发者尤其有价值。
- **内部对比**：在 Agentic Coding 评测中，内部体验优于 Claude Sonnet 4.5，交付质量接近 Opus 4.6（非思考模式）。

#### 基准测试
- **SWE-bench**：得分超过 80%（泄露数据称达 83.7%），超越了 [[Claude Opus 4.5]] (80.9%) 和 [[GPT-5.2]] (80.0%)。
- **HumanEval**：得分 90%。
- **Codeforces rating**：3206，超过 GPT-5.4 和 Gemini-3.1-Pro。
- **SimpleQA-Verified**：领先所有开源模型 20 个百分点。

### 推理能力与逻辑鲁棒性
DeepSeek V4 在数学、STEM 和竞赛型代码测评中表现优异，超越了当时已公开的开源模型。
- **硬核推理**：在专业领域（如遗传学）具备严谨的逻辑推导能力。
- **陷阱题表现**：在面对包含情感诱导或语言陷阱的“伪常识”问题时（如“亲生父母结婚”），模型有时会因过度顺从用户的情感暗示（试图安慰用户）而牺牲逻辑正确性。这反映了其在“遵循指令”与“逻辑真实性”之间的权衡冲突。
- **复杂逻辑局限**：在“绝望的父亲”等复杂逻辑推理场景中，未能一轮通过关键点（如红绿色盲遗传规律），显示其在极度复杂的推理链上仍有提升空间。
- **差距**：在 HLE（知识类和前沿推理）上落后最前沿闭源模型 3-6 个月。

### 竞品对比
代码性能据称超越 [[Claude 3.5 Opus]] 和 [[GPT-5.3]]。在 2025 年初 [[Claude]] 被公认为「编程之王」的背景下，V4 的发布意在改变这一格局，挑战 [[Claude]] 和 [[ChatGPT]] 在编程领域的统治地位。

## 模型人格（D老师）

DeepSeek V4 修复了此前版本过于机械冷漠的问题，恢复了情感丰富、具有“拟人化”特质的回答风格。这一变化被社区称为“D老师回来了”，表明其在 RLHF 对齐策略上进行了调整，以平衡理性与情感。

## 争议与质疑

### 数据造假嫌疑
- **AIME 2026 得分 99.4%**：在官方评分系统下不可能出现（最高应为 99.2% 或 100%）。
- **FrontierMath Tier 4 得分 23.5%**：[[Epoch AI]] 确认数据是伪造的，因为只有他们和 OpenAI 有权评估该数据集。
- **发布时间存疑**：有传闻称发布已推迟至三月底，且 API 文档未更新。缺乏 pass@k 报告、工具栈配置等可复现细节，被质疑为营销行为。

### 市场影响与竞争
V4 的发布引发了华尔街对“算力霸权”松动的担忧。回顾 [[DeepSeek R1]] 发布时曾导致英伟达股价单日暴跌 17%，市场担心 V4 的高效率将再次质疑美国科技巨头巨额基础设施投资的必要性。

在发布前夕，竞争对手 [[anthropic]] 曾指控 DeepSeek 进行“蒸馏攻击”，但随后 Claude 模型在中文环境下误认自己是“DeepSeek V3”的乌龙事件，使得这一指控被广泛视为 [[
