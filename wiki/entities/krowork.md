# KroWork

**KroWork** 是由 [[快手]] 推出的首个“打工人 Agent”产品。它允许用户通过自然语言对话，将重复性的工作流转化为可独立运行、可反复调用的本地桌面应用程序。

## 核心功能

### 1. 对话生成应用
用户只需用自然语言描述需求（如“帮我做一个股票分析台”），KroWork 会自动完成以下步骤：
-   理解需求并规划任务（如发现 API 收费并主动建议替代方案）。
-   安装 Python 依赖。
-   编写后端服务和前端界面。
-   启动进程并弹出应用窗口。

### 2. 应用固化
这是 KroWork 区别于传统 Agent 的核心特性。一旦生成，应用即被“固化”：
-   **本地托管**：应用运行在用户本地电脑上，无需消耗 Token 即可重复使用。
-   **系统集成**：支持创建桌面快捷方式、开始菜单项及开机自启。
-   **确定性执行**：逻辑由代码执行，避免了传统 Agent 每次运行结果的不确定性。

### 3. 持续迭代
应用并非生成即“死”。用户可以通过“继续改进”功能，使用自然语言追加功能（如“加一个导出按钮”），KroWork 会读取现有代码并进行修改。

### 4. Browser-Use
对于需要深层网页交互的任务（如抓取论文详情），KroWork 具备模拟人类操作浏览器的能力，可以自动点击、翻页、读取 PDF 并提取信息。

## 解决的问题
KroWork 旨在解决当前 AI Agent 领域的四大顽疾：
1.  **[[提示词疲劳]]**：无需重复描述需求。
2.  **成功率赌博**：提供确定的代码级稳定性。
3.  **Token 成本**：本地运行逻辑，仅在必要时调用模型。
4.  **数据隐私**：数据不出域，在本地沙箱中处理。

## 潜在风险与局限
-   **安全边界**：虽然强调数据不出域，但允许 AI 自动安装依赖和运行代码本身引入了新的安全风险（如供应链攻击）。
-   **调试难度**：虽然声称“零代码”，但当生成的应用出现复杂逻辑错误时，非技术用户可能难以修复。
-   **资源消耗**：本地运行多个 Agent 应用可能对硬件资源（内存、CPU）造成压力。

## 未来规划
据报道，KroWork 未来将支持**应用分享**功能，允许用户将生成的应用一键分发给同事，无需配置环境即可使用，这将使个人生成的工具成为可流通的资产。
