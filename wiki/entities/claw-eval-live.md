# Claw-Eval-Live

[[claw-eval]] 的升级版，提出了「活的」Benchmark 概念，旨在解决评测任务与现实需求脱节的问题。

## 核心机制

Claw-Eval-Live 通过两层分离的设计实现动态演进：

1.  **信号层**：
    *   从 [[clawhub]] Top-500 热门技能等公开源采集需求信号。
    *   观察并判断当前哪些工作流更值得关注，作为任务分布的先验知识。

2.  **发布层**：
    *   每次发布的 Benchmark 是一个固定的、带时间戳的快照。
    *   包含任务定义、执行环境、数据夹具和评分脚本，确保学术上的可复现性和模型间的稳定比较。

## 构建流程

连接信号层与发布层的五阶段流水线：
1.  **信号采集**：抓取热门技能快照。
2.  **模式聚类**：将技能聚合为稳定的工作流模式。
3.  **家族加权**：根据信号强度调整各任务家族在 Release 中的占比。
4.  **种子扩展与筛选**：生成可执行任务候选并筛选。
5.  **区分度优化选取**：使用 [[milp-任务筛选]] 在满足发布规模、家族覆盖和模型区分度约束下选出最终任务。

## 评测发现

基于当前公开 Release（105 道任务，13 个模型）的评测结果：
*   **天花板低**：没有模型通过率超过 70%。
*   **反直觉难度**：终端/环境修复任务接近满分，但 HR/管理/跨系统工作流任务通过率极低（HR 平均仅 6.8%）。
*   **成本差异**：[[claude-opus-4-6]] 准确率最高但成本昂贵（约 $31.6），[[glm-5]] 展示了极高的性价比。

## 意义

标志着 Agent 评测进入「下半场」，从单纯的能力比拼转向对齐真实世界业务价值的验证。
