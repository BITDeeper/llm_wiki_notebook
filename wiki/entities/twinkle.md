# Twinkle

[[Twinkle]] 是由 [[ModelScope (魔搭社区)]] 团队开源的大模型训练框架，采用 [[Client-Server 架构]]，旨在实现 [[训练即服务]] (TaaS)。它通过 [[算法语义抽象]] 和组件化设计，允许开发者用约 150 行代码编排复杂的强化学习（RL）训练循环，同时底层处理调度和资源分配。

## 核心特性

### 算法语义抽象
Twinkle 将训练过程分解为符合算法逻辑的 API，而非仅关注工程实现。这使得开发者可以像写本地 PyTorch 代码一样控制训练流程，而无需关心底层分布式细节。

### Client-Server 架构
支持多种运行模式：
- **本地一体化部署**：适合单机或小规模调试。
- **远端集群部署**：基于 Ray 等分布式引擎。
- **Serverless 训练服务**：直接使用公用训练服务，实现算力与算法解耦。

### 多租户训练
通过“LoRA 池 + 租户应用”架构，支持在共享基础模型上进行并发多租户训练。不同用户（租户）可以在同一基础模型上执行不同的训练任务（如 SFT、RL、PT），互不干扰。这是提升算力利用率的关键技术。

### 兼容性与扩展性
- **Tinker API 兼容**：支持 [[Thinking Machine Lab]] 的 Tinker API 标准。
- **国产硬件支持**：原生支持 [[昇腾]] 硬件，并在特定测试中效率优于基准框架 [[veRL]]。

## 技术架构
Twinkle 采用组件化设计，将 Dataset、Model、Sampler 等解耦为独立模块。其 Infra 组件负责将这些模块装饰并适配到单卡、torchrun 多机多卡或 Ray 等不同运行环境中。

## 应用场景
- **复杂 RL 训练**：如 [[GRPO]] 等算法的快速实现。
- **模型自进化**：结合 Agent 框架（如 [[evolver]]）实现模型的自我迭代。
- **多租户服务**：为云服务商提供高利用率的训练基础设施。

## 开发背景
Twinkle 由 ModelScope 团队开发，是该团队继 [[ms-swift]] 之后推出的新一代框架。其开发过程中与 [[招商银行信息技术部]] 进行了深度技术合作，确保了框架在实际生产环境中的可用性。
