# Managed Agents

**Managed Agents** 是 [[anthropic]] 于 2026 年 4 月推出的一种云原生 AI 智能体架构标准。它通过将“大脑”（模型逻辑）与“双手”（执行环境）彻底解耦，解决了传统 [[openclaw]] 架构中的耦合、安全和成本问题，被视为对旧有架构的“降维打击”。

## 核心架构

Managed Agents 将智能体拆解为三个标准组件，这种设计思路致敬了 Unix 操作系统的哲学：

1.  **Session（会话层）**
    -   **定义**：一个“仅追加”的日志系统。
    -   **功能**：记录发生的一切交互，独立于模型存在。
    -   **优势**：即使系统重启，记忆也不会丢失；通过外部存储和按需查询，突破了上下文窗口的限制。

2.  **Harness（框架层）**
    -   **定义**：智能体的“循环逻辑”层。
    -   **功能**：负责调用 Claude 模型，并将指令分发给工具。
    -   **优势**：围绕稳定接口构建，即使模型升级（如从 Sonnet 到 Opus）或底层逻辑变化，接口依然保持稳定，避免了代码冗余。

3.  **Sandbox（沙箱层）**
    -   **定义**：一个绝对隔离的计算环境。
    -   **功能**：运行代码、修改文件，执行实际操作。
    -   **优势**：物理隔离防御了 [[prompt-injection]] 攻击；敏感 Token 永远保存在沙箱外部，AI 只需发起调用请求而无需直接接触密钥。

## 关键特性

### 解耦与牲畜化
Managed Agents 引入了 [[宠物与牲畜]] 的概念，将计算资源从“宠物”（独特、难以替换、需精心维护）转变为“牲畜”（可批量替换、无状态、标准化）。这种解耦使得：
-   **大脑**不需要知道**手**在哪里运行。
-   **容器**和 **Harness** 本身都变成了可随时替换的“牲畜”。

### 性能优化
通过解耦和按需分配资源，Managed Agents 实现了显著的性能提升：
-   **p50 TTFT**（首字生成时间）降低了约 **60%**。
-   **p95** 延迟降低了 **90%** 以上。

### 集群效应
架构支持“多脑与多手”的协同：
-   一个 Claude 模型可以同时对多个执行环境进行推理。
-   系统可以智能决定将任务发送到哪一个沙箱（“手”）。

## 与 OpenClaw 的对比

| 特性 | OpenClaw (旧架构) | Managed Agents (新架构) |
| :--- | :--- | :--- |
| **耦合度** | 高（模型与 Harness 深度耦合） | 低（彻底解耦） |
| **状态** | 有状态（类似“宠物”） | 无状态（类似“牲畜”） |
| **安全性** | 依赖插件，易受注入攻击 | 沙箱物理隔离 |
| **记忆** | 受限于上下文窗口 | 外部日志存储，无限制 |
| **成本** | 闲置时仍消耗 Token | 按需调用，效率更高 |

## 意义
Managed Agents 的出现标志着 AI 行业从“工具嫁接”向“AI 原生系统”的范式转移。它不仅解决了工程上的痛点，还重新定义了智能体的安全标准和资源管理方式。
