# ClawManager

[[ClawManager]] 是业内首个针对 [[OpenClaw]] 的企业级服务器部署管理方案，由 [[Yuan-lab-LLM]] 团队开发并开源。它旨在补齐 OpenClaw 在企业环境中缺失的管理能力，将“单机版”的智能桌面转化为可管理的“企业级集群”，使其能够从个人工具平滑过渡到组织级生产力平台。

## 核心功能

ClawManager 的功能架构分为两层，旨在解决 AI 桌面 Agent 在大规模企业落地时面临的运维、安全与治理难题。

### 实例管理层
负责处理用户与计算环境的关系，提供统一的管理平面：
- **统一控制台**：提供单一管理后台，实时监控所有用户实例的状态（在线、离线、资源占用），解决了传统管理入口缺失的问题。
- **批量部署**：支持 CSV 批量导入用户名单，实现分钟级的实例自动分配，极大降低了批量部署门槛。
- **资源隔离与配额**：基于 [[Kubernetes]] 原生的 Namespace、Pod 和 PVC 机制，实现 CPU、内存、GPU 的硬隔离。针对资源设置硬上限，防止单个用户抢占集群资源（即解决“一只虾吃撑饿死全家”的问题），保障大规模团队环境下的稳定性。
- **数据持久化与资产保护**：支持用户记忆、对话历史和个性化配置的统一备份与跨实例迁移，防止因实例删除或重置导致的 [[ai-资产流失]]。
- **生命周期管理**：支持一键回收实例以释放资源。
- **安全访问控制**：所有实例运行在 Kubernetes 集群内部网络（内网隔离），不直接暴露公网；用户通过基于令牌的 WebSocket 连接（Portal View 或 Desktop Access）安全访问实例。

### AI 治理层
负责处理模型调用与企业合规的关系，内置 [[AI Gateway]]：
- **统一模型入口**：作为所有模型请求的统一入口，支持多模型接入和分级路由（例如区分普通模型与高安全级别模型）。
- **全链路审计**：为每次 LLM 调用生成唯一 `trace_id`，并对 SSE 流式响应进行持久化记录，支持事后按用户、模型或实例维度检索，满足合规审计要求。
- **精细化计费**：支持按 Prompt、Completion、Reasoning、Cached 等 Token 类型分类统计，并提供多币种计费支持，实现精细化成本核算。
- **安全风控**：内置规则引擎，可自动检测并拦截敏感内容，或进行路由重定向，提供主动风险控制能力。

## 技术架构

- **底层依赖**：基于 [[Kubernetes]]，利用其容器编排和隔离能力。
- **技术栈**：Go 1.21+, React 19, TypeScript, MySQL。
- **部署方式**：云原生架构，支持 YAML 配置文件一键部署。
- **接口标准**：提供 RESTful API 和 OpenAI 风格的模型接口，便于与企业现有系统集成。
- **最低配置**：1 个 Kubernetes 节点，4 核 CPU，8GB 内存，20GB 磁盘。
- **支持镜像**：OpenClaw, Webtop, Ubuntu, Debian, CentOS 等。
- **开源协议**：MIT 协议，代码完全可审查，保障企业数据主权。

## 解决的痛点

ClawManager 专门针对 OpenClaw 在企业应用中的“五大隐形屏障”：
1.  **管理入口缺失**：缺乏全局视图，难以监控状态。
2.  **批量部署门槛高**：手动配置繁琐，无法快速扩容。
3.  **资产流失风险**：数据散落本地，缺乏统一备份。
4.  **资源利用率低**：缺乏配额控制，容易出现资源争抢。
5.  **安全合规盲区**：公网暴露风险，缺乏调用审计。

## 应用场景

- **AI 研究机构**：快速为新入组研究员分配隔离的 GPU 资源和环境。
- **培训机构**：课程结束后一键回收所有学员实例和资源。
- **企业 IT 部门**：满足合规审计要求，实现全员推广时的统一鉴权与成本管控。

## 意义

ClawManager 通过开源方式降低了企业级 AI 基础设施的门槛，使得中小团队也能以极低的成本构建起可管理、可追溯、可扩张的 AI 智能体运行环境。它解决了 [[OpenClaw]] 从“玩具”走向“工具”过程中的关键工程化短板。
