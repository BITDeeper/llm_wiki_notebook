# ContextBench

**ContextBench** 是由南京大学与伦敦大学学院（UCL）团队联合发布的首个面向过程的代码上下文检索评测基准。它旨在解决现有基准（如 [[swe-bench]]）仅关注端到端成功率而忽视中间推理过程的问题，通过量化 Agent 的检索与利用行为，揭示代码智能体的真实能力瓶颈。

## 核心特性

### 1. 过程可解释性
不同于传统评测只看“修好了吗”，ContextBench 追问“在解决问题时，Agent 究竟检索并使用了哪些代码上下文”。它将评测维度拆解为：
- **找上下文**（检索能力）
- **用上下文**（利用能力）

### 2. 黄金上下文
ContextBench 的核心度量标准是 [[黄金上下文]]。这些上下文由人类专家基于 1,136 个真实问题修复任务（涵盖 66 个代码库、8 种编程语言）进行标注。专家通过逆向分析真实补丁，沿函数调用、类引用与变量依赖关系回溯，确定了解决问题不可或缺的最小代码依赖集。

### 3. 细粒度追踪
评测框架能够记录 Agent 的每一步操作轨迹，并在三个层级上计算检索的精确率和召回率：
- **文件级**（File）
- **代码块级**（Block）
- **行级**（Line）

## 关键发现

基于 ContextBench 的评测揭示了当前代码 Agent 的三大痛点：
1. **复杂架构无效性**：复杂的 Agent 脚手架（如基于图的检索）在检索质量上并未显著优于简单方案，体现了 [[苦涩的教训]]。
2. **高召回低精确**：主流模型（如 GPT-5）倾向于“多捞少漏”，导致噪音干扰推理。
3. **信息整合瓶颈**：Agent 经常出现“检索成功但推理失败”的现象，即中间步骤找到了关键代码，但最终补丁未使用。

## 影响
ContextBench 推动了代码 Agent 评测从“结果验证”向“过程可解释”的范式转移，为改进检索与推理链路提供了可观测、可度量的数据支持。
