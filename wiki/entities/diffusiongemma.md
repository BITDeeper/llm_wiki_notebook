# DiffusionGemma

谷歌开源的26B参数文本扩散 MoE 实验性模型，基于 [[gemma-4]] 家族构建，吸收了 Gemini Diffusion 的前沿研究成果。采用 Apache 2.0 许可证发布。核心创新在于将图像扩散模型的去噪范式应用于文本生成，实现比同规格自回归模型快4倍的推理速度。

## 模型规格

| 属性 | 值 |
|------|-----|
| 总参数量 | 26B |
| 激活参数量 | 3.8B（MoE 稀疏激活） |
| 架构 | 混合专家模型（MoE） |
| 每次前向计算生成 | 256 token |
| 量化后显存占用 | 18GB（单张4090可本地运行） |
| 许可证 | Apache 2.0（允许商用） |
| 权重下载 | Hugging Face |
| 定位 | 实验性模型 |

## 性能数据

| 平台 | 速度 | 对比基准 |
|------|------|----------|
| H100 (fp8, batch=1) | 1000+ tokens/s | Gemma 4 26B A4B+MTP: 300+ tokens/s |
| RTX 5090 | 700+ tokens/s | — |

速度优势约为同规格自回归模型的**4倍**。

## 技术原理

DiffusionGemma的工作流程：

1. **铺开画布**：初始化256个token的随机占位符画布
2. **多轮去噪**：高置信度token先锁定，再作为上下文线索修正其余部分
3. **收敛输出**：整段文字同时收敛为最终输出

核心优势在于天然并行——GPU一次性接到大块并行计算任务，Tensor Cores火力全开，计算瓶颈从"内存带宽不够"变为"算力够不够"。

### 核心技术特点

- **扩散式输出头**：不沿用逐 token 顺序生成，而是一次性生成整块文本
- **[[双向注意力]]**：256个token同时生成，每个token可看到画布上所有其他token，前后文同时可见
- **[[自我修正能力]]**：多轮迭代精炼输出，可实时发现并修正错误
- **解码瓶颈转移**：从内存带宽转向计算本身，提升本地推理硬件利用率

### 双向注意力的验证

双向注意力带来了**实时自我纠错**能力——模型边生成边评估整段文字一致性，发现不对立刻修正。

验证实验：**Unsloth** 对 DiffusionGemma 进行微调，使其学会解数独，成功率从0%飙到80%。数独本质是"后面的数影响前面的数"，自回归模型只能往前看，做起来极痛苦。这展示了双向注意力在非线性任务上的潜力。

## 适用场景

- 行内编辑
- 快速迭代
- 非线性文本结构生成（数独、代码补全、氨基酸序列、数学图结构）
- 本地推理和低并发场景
- 速度敏感的本地交互场景

## 局限性

- **实验性模型**，整体输出质量低于标准版 [[gemma-4]]，多项基准存在差距
- **去噪步数权衡**：步数少则快但质量差，步数多则质量好但速度优势消失
- 高 QPS 云端场景中并行解码优势被削弱，可能带来更高服务成本
- 吞吐优势主要体现在单个加速器上的低到中等 batch size 场景
- 官方仍推荐标准版 Gemma 4 用于高质量生产级输出

## 生态支持

[[英伟达]]全线护航：RTX到H100到DGX Spark全覆盖。推理框架支持vLLM、MLX、Unsloth、NeMo，llama.cpp在开发中。

**Hugging Face** 制作了 text-to-3D SVG 演示，展示逐步生成过程。

## 行业定位

谷歌CEO[[sundar-pichai|皮猜]]称DiffusionGemma为"赛马"。[[inception-labs|Inception Labs]]于2026年2月发布的[[mercury-2|Mercury 2]]是业内首个投产的扩散语言模型。谷歌2025年I/O展示Gemini Diffusion实验（采样速度1479 tokens/s）后沉寂一年，DiffusionGemma代表从实验验证到工程落地的完整周期。
