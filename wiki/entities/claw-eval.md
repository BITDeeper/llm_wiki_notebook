# Claw-Eval

[[claw-eval-live]] 的前身，专注于解决「如何确认 Agent 真的做成了任务」这一核心问题。

## 核心贡献：执行轨迹审计

Claw-Eval 将 Agent 评测从「只看答案」推进到「看行动」。其核心机制是让 Agent 的执行过程变成可审计的证据。

### 证据链
评测不再仅依赖最终输出，而是基于三条独立证据链：
1.  **执行轨迹**：Agent 的操作步骤。
2.  **服务端审计日志**：后端 API 调用记录。
3.  **环境快照**：执行后的系统状态。

### 关键实验
团队进行了严格对照实验：仅让 LLM Judge 查看对话记录和评分脚本，屏蔽审计日志和环境快照。
*   **结果**：LLM Judge 漏掉了 **44% 的安全违规** 和 **13% 的鲁棒性问题**。
*   **结论**：只看结果的评测会系统性高估模型能力，必须引入过程审计。

## 评测规模

*   包含 300 道人工验证任务。
*   覆盖通用服务编排、多模态感知与生成、多轮专业对话三大群组。
*   定义了 2,159 个可独立验证的评分细则。

## 局限性与演进

虽然解决了评分可信度问题，但 Claw-Eval 的任务集合是固定的，无法跟随现实工作流需求的变化。这一局限直接催生了 [[claw-eval-live]] 的诞生。
