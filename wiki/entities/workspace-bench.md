# Workspace-Bench

**Workspace-Bench** 是一个将AI Agent放入包含复杂文件依赖关系的真实办公环境中进行评测的基准，旨在测试Agent是否具备 [[工作空间学习]] 能力。

## 规模参数

| 指标 | 数值 |
|------|------|
| 文件总数 | 20,476 |
| 文件类型 | 74种 |
| 目录数 | 3,299 |
| 最大目录深度 | 8 |
| 最大单工作站文件数 | 11,020 |
| 任务数 | 388 |
| 评价标准（Rubric） | 7,399条 |
| 平均每任务依赖边 | 5.1条 |
| 平均每任务跨文件数 | 4.7个 |
| 平均每任务Rubric数 | 19.1条 |

## 工作角色覆盖

构建了五类真实工作角色的工作空间：

- 运营经理
- 物流经理
- 产品经理
- 后端开发
- 研究员

## 核心发现

### 整体表现
- 27种Agent配置的平均Rubrics通过率约 **43.3%**
- 最佳组合接近 **60%**
- 人类专家配合工具达到 **80.7%**

### 难度梯度衰减
- Easy：**51.4%**
- Medium：**46.0%**
- Hard：**35.7%**

Hard任务引入文件关系发现、长程规划、状态跟踪和错误恢复，Agent一旦进入复杂依赖网络就容易迷路。

### Node F1 > Edge F1
Agent相对容易找到相关文件（Node F1较高），但难以判断文件间关系（Edge F1较低）。它们不知道哪个是源数据、哪个是派生报告、哪个是历史版本。

### 高交互≠高质量
某些配置产生40-60轮交互、消耗大量token，准确率仍停留在30%-45%。更高效的系统能用更少交互轮次找到关键证据。

## 代表性任务

运营经理生成全球市场产品策略报告：需要遍历全球市场数据，比较五个市场的销售额和利润率，分析产品类别盈利能力，评估物流成本影响，比较客户细分贡献。要求找到9个核心文件，连接订单CSV、物流PDF、产品信息Excel、客户分层表、销售计划PDF等多源材料，通过25条rubric验证。
