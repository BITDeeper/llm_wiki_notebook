# LiOS

LiOS（端云协同具身智能操作系统）是由 [[招商局狮子山人工智能实验室]]（[[狮子山人工智能实验室]]）自研的具身智能基础设施，定位为 OS 级统一平台，旨在将具身智能从分散的系统集成推进到统一基础设施。LiOS 覆盖训练、部署、轨迹采样与 Real2Sim 遥操作的完整数据迭代闭环。

## 设计理念

LiOS 面向具身智能实践中的核心系统挑战：

1. **系统复杂度爆炸**：机器人技术栈（硬件、传感器、运动控制、安全执行）与大模型技术栈（分布式训练、数据治理、推理优化、模型服务）深度交叉后带来的工程复杂度。
2. **端侧资源瓶颈**：端侧本体必须轻量、低功耗、实时安全，无法独立承载大规模基础模型。
3. **规模需求**：具身模型持续进化对算力、数据和模型规模的更高需求。

团队的核心思路是将分散的机器人集成、仿真评估、模型训练、真机部署和数据回流，统一纳入端云协同的基础设施体系。

## 三层架构

### 云侧——面向智能的规模扩展

- 多模态大模型分布式训练与推理优化
- 多模态数据湖仓管理
- 高并发仿真评估
- 支持在 Qwen3-VL-30B-A3B、Qwen3-VL-235B-A22B、Wan2.2-T2V-A14B、DINOv3、V-JEPA-2 等前沿预训练模型基座上构建具身基础模型（VLA、WAM、WM）
- 大模型能力、数据湖仓和训练推理资源，稳定进入物理世界任务

### 端侧——面向真实机器人稳定执行

- LiOS Runtime 接入异构机器人本体、传感器、末端执行器和边缘计算单元
- 传感器同步、运动控制、安全执行、接管恢复及本地状态管理
- Real-time Chunking 优化策略：将大规模模型生成的动作指令转化为可实时执行的动作序列
- 保障执行的实时性与安全性

### 端云协同——释放云端资源的关键

- [[低延迟图传]]：约 30ms 本地相机到云端显存延迟
- 控制信令与状态同步
- WebRTC/GStreamer 稳定传输
- GPU 直编直解减少 CPU-GPU 往返搬运
- 近网中继方案适配复杂网络环境

## 数据闭环与关键能力

LiOS 将具身操作模型迭代统一纳入基础设施，形成训练-部署-采样的完整闭环：

1. **采集阶段**：多种方案接入，完成真实轨迹获取、标注与质检。
2. **训练阶段**：云端算力和多模态数据湖仓，完成策略训练、微调、评估与版本管理。
3. **部署阶段**：LiOS Runtime 接入机器人本体，真机验证稳定性。
4. **强化与闭环优化**：云端图传支持远程观察、人工接管和动作纠偏，沉淀数据资产。

### Real2Sim 遥操作数据闭环

从真实机器人操作中采集数据回流至仿真环境，形成训练-部署-采样的迭代闭环。这是 [[sim2real]] 方向的具体工程实践。

### 策略迁移

将仿真阶段积累的策略能力成功迁移到真实场景，应对硬件误差、夹爪稳定性、动作偏移、长尾状态恢复和现场不确定性等挑战。
