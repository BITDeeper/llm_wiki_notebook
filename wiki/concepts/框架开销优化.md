# 框架开销优化

通过 profiling 定位瓶颈并逐项消除的工程方法论。在 [[hermes-agent]] 的案例中，团队通过三项针对性优化将启动时间从 701ms 降至 258ms，降幅 63%，直接导致基准测试战绩从 5:6 反转为 6:5。

## 三项优化

### 1. Bitwarden磁盘缓存（L2缓存）
- **问题**：每次启动调用 Bitwarden Secrets Manager API 拉取凭据，耗时 380ms；缓存为纯进程内，连续执行仍需重新拉取
- **方案**：增加 L2 磁盘缓存，文件权限 0600，存放于 `<hermes_home>/cache/bws_cache.json`，默认 TTL 300s；访问 token 本身不落盘
- **收益**：砍掉 380ms

### 2. PEP 562 模块级`__getattr__`懒加载
- **问题**：`hermes_cli.models._PROVIDER_MODELS` 巨型字典在模块加载时急切导入，耗时约 55ms
- **方案**：使用 Python PEP 562 模块级 `__getattr__` 实现懒加载，仅在真正访问模型目录时才付出开销
- **收益**：省下 55ms

### 3. 配置文件去重
- **问题**：`main.py` 顶部读取两次 `config.yaml`——一次 `yaml.safe_load` 用于密钥脱敏桥接，一次完整 `load_config()` 只为检查一个布尔值
- **方案**：合并为一次原始加载
- **收益**：省下 17ms

## 方法论

核心方法是"纯靠 profiling 找到瓶颈，一刀一刀切掉冗余"——不依赖模型升级或算力堆叠，而是通过系统性的性能分析定位框架层面的每一处浪费。
