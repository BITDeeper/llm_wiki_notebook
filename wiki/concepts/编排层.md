# 编排层

[[编排层]]（Orchestration Layer）是 AI Agent 技术栈中位于大模型（“大脑”）与实际工具/环境（“手脚”）之间的关键软件层。

## 定义与作用

如果说大模型负责理解任务、推理路径和生成决策，那么编排层则负责让 AI 真正“把事情做完”。其核心职能包括：

1.  **步骤拆解**：将用户的宏观目标分解为可执行的原子步骤。
2.  **工具调用**：根据步骤需求，动态调用 API、数据库查询或本地应用操作。
3.  **上下文衔接**：在多步骤执行过程中，管理和传递上下文信息。
4.  **异常处理**：处理执行过程中出现的错误、重试或回滚逻辑。

## 行业竞争格局

当前，谷歌、Anthropic 和 OpenAI 在编排层上采取了截然不同的战略路径，被称为“编排层三国杀”：

### 1. 谷歌：重编排（平台化）
-   **策略**：提供完整的框架和可视化工具（如 [[Agent Designer]]），强调企业级多 Agent 协作。
-   **优势**：门槛低，易用性强，依托 Google Workspace 等产品矩阵拥有强大的分发能力。
-   **哲学**：通过强大的编排层封装模型能力，让普通用户也能通过拖拽生成 Agent。

### 2. Anthropic：轻编排（工具化）
-   **策略**：模型原生支持工具调用和环境交互（如 [[Claude Cowork]]），编排的事交给开发者或模型自身决定。
-   **优势**：灵活性高，上限高，不依赖特定平台框架。
-   **哲学**：模型本身足够强，无需厚重的编排层，直接与桌面环境交互。

### 3. OpenAI：中间路线（生态并举）
-   **策略**：通过 Assistants API 提供适度的编排抽象，同时通过 GPT Store 构建生态。
-   **特点**：试图在易用性和灵活性之间寻找平衡。

## 重要性转移

随着 AI 行业从 [[任务执行范式]] 的“聊天”阶段进入“干活”阶段，竞争焦点已从“谁的模型智商更高”转移到了“谁的编排层更易用、生态更丰富”。编排层的工程落地能力正成为决定 Agent 产品成败的关键因素。
