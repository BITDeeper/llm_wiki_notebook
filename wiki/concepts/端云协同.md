# 端云协同

[[端云协同]]（Edge-Cloud Collaboration）是一种结合端侧隐私安全与云端强大算力的混合计算架构。它旨在解决单一依赖本地算力导致模型能力受限，或单一依赖云端算力导致数据隐私泄露及成本高昂的矛盾。

## 背景与动机

在 AI Agent 的实际应用中，开发者常面临“两头堵”的困境：
- **纯云端模式**：存在数据隐私泄露风险（“不敢用”），且频繁调用顶级 API 导致成本高昂（“用不起”）。
- **纯本地模式**：受限于端侧硬件算力和模型参数规模，难以处理复杂推理任务（“用不好”）。

端云协同试图打破这种二元对立，通过智能路由机制，让端侧和云侧各尽其能。

## 核心逻辑

在端云协同架构中，计算任务在终端设备（端）与云端服务器（云）之间进行智能分配。其核心原则是：
- **端侧**：负责敏感数据的预处理、感知及行动等隐私敏感任务，确保原始数据不离开本地域。
- **云端**：负责复杂的计算推理、理解及规划等需要大规模算力的任务。

这种模式既利用了云端大模型的强大能力，又确保了原始隐私数据的安全。

## 实现方式

典型的实现方式采用 [[三段式隐私脱敏]] 流程：
1.  **本地脱敏**：在本地提取特征并替换敏感信息。
2.  **云端处理**：将脱敏数据发送至云端进行推理。
3.  **本地回填**：在本地将推理结果中的占位符还原。

此外，[[ClawXRouter]] 是端云协同理念的典型工程实现。它通过 [[三级隐私路由]] 和 [[性价比感知路由]]，在 [[PinchBench]] 测试中实现了成本降低 58% 且性能提升 6.3% 的效果。

## 优势
- **隐私保护**：原始数据（如视频、语音、财务数据）无需上传至云端。
- **能力无损**：依然可以调用云端最先进的大模型进行复杂任务处理。
- **成本优化**：通过端侧处理部分任务，显著减少云端 API 调用的成本或带宽消耗。

## 挑战
- **同步延迟**：端云之间的数据传输可能增加响应延迟。
- **端侧算力要求**：本地仍需具备运行多模态大模型进行脱敏和回填的算力。
- **一致性保证**：需要确保脱敏和回填过程不会导致语义丢失或上下文错误。

## 进化形态

随着 [[AI主机]] 等新硬件品类的引入，端云协同架构正在向 [[端-边-云一体]] 架构演进，以进一步优化成本和效率。
