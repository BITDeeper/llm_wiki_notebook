# 隐式信任链

**隐式信任链** (Implicit Trust Chain) 是一种常见的系统设计模式，指在微服务或流水线架构中，下游服务默认上游传入的数据是经过清洗和验证的，从而不再进行校验。

## 问题所在
在 [[GitHub]] 的 Git Push 处理流水线中，[[babeld]] -> [[gitrpcd]] -> Hook 形成了一条信任链。[[gitrpcd]] 和 Hook 完全信任来自 [[babeld]] 的 `X-Stat` 头。一旦上游服务（如 babeld）出现过滤疏忽（如未过滤分号），恶意数据就会顺着信任链一路畅通无阻，直达核心执行环境。

## 后果
这种设计虽然提高了系统效率（避免了重复校验），但也极大地放大了单点故障的影响范围。一个组件的漏洞可能导致整个链路的崩溃。

## 防御建议
- **零信任原则**：无论数据来自内部还是外部服务，每个组件都应进行独立的校验。
- **深度防御**：在流水线的多个关键节点设置安全检查，确保即使上游被绕过，下游仍能拦截攻击。
