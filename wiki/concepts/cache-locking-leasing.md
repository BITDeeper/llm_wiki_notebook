# Cache Locking/Leasing (缓存锁定/租约)

缓存锁定或租约机制是一种防止缓存穿透和缓存雪崩的并发控制策略。在高并发系统中，它用于确保当缓存未命中时，只有一个请求去后端数据源（如数据库）查询并回填缓存，其他请求则等待结果。

## 工作机制
1. **请求到达**：大量并发请求查询同一个 Key。
2. **缓存未命中**：系统发现缓存中没有该 Key 的数据。
3. **获取锁/租约**：系统尝试获取一个针对该 Key 的锁。只有一个请求能成功获取锁。
4. **回填缓存**：持有锁的请求去数据库查询数据，并将结果写入缓存。
5. **释放锁**：锁被释放，其他等待的请求直接从缓存中读取数据。

## 重要性
如果没有这种机制，在缓存失效的瞬间，所有并发请求都会同时击穿缓存，直接打到后端数据库。这种“缓存雪崩”可能导致数据库瞬间负载过高，甚至宕机。

[[openai]] 在支撑 8 亿用户的 [[postgresql]] 架构中使用了这一机制，成功保护了后端数据库免受瞬间高并发的冲击。

## 相关概念
- **缓存穿透**：查询不存在的数据，导致请求直接打到数据库。
- **缓存击穿**：热点 Key 过期的瞬间，大量请求打到数据库。
- **缓存雪崩**：大量 Key 同时过期，导致数据库压力骤增。
