# 基础设施滞后

[[基础设施滞后]]（Infrastructure Lag）描述了 AI 时代的一种新矛盾：**AI 的处理和推理速度已经极快，但现有的基础设施（如 API 接口、网络带宽、服务器承载能力）跟不上 AI 的效率，从而成为系统的瓶颈。**

## 典型案例
在 [[clawsweeper]] 的运行中，尽管 [[gpt-5.5]] 模型能够快速处理大量 Issue，且系统启动了 50 个并行实例，但整体速度被 [[github]] 的 API 速率限制强行拖慢。系统状态显示 `Apply throttled`，意味着 GitHub 服务器无法响应 AI 的并发请求。

## 影响
这种滞后不仅仅是技术性能问题，更意味着：
1.  **资源浪费**：昂贵的 GPU 算力和模型推理时间在等待 API 响应中被空耗。
2.  **规则冲突**：为防止传统网络攻击而设计的 API 限流规则，现在反而限制了合法的高效自动化工具。

## 未来展望
随着 AI Agent 的普及，现有的软件基础设施架构（API 设计、数据库连接数限制等）可能需要针对 AI 的高并发特性进行重构。
