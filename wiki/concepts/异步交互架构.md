# 异步交互架构

异步交互架构是一种用于解决计算密集型 AI Agent（如大语言模型）与高频实时环境（如游戏引擎、物理模拟器）之间速度不匹配问题的系统设计模式。

## 核心问题
在实时应用场景中，环境通常以固定的高频率运行（例如 25Hz，即每 40 毫秒一帧）。然而，LLM 的推理时间是不确定的，可能从几百毫秒到数秒不等。如果强制 Agent 必须在每一帧都做出响应，会导致系统崩溃或严重超时。

## 工作原理
该架构的核心思想是将 **Agent 的计算循环** 与 **环境的执行循环** 解耦。

1.  **环境层**：游戏引擎按自身节奏（如 25Hz）持续运行，维护游戏状态。
2.  **桥接层**：通过 gRPC 或其他通信协议，传递环境状态给 Agent，并接收 Agent 的指令。
3.  **Agent 层**：在接收到状态后进行异步计算。在此期间，环境可以选择暂停、快进或执行默认逻辑。
4.  **指令同步**：Agent 计算完成后，指令被提交并在下一个环境 tick 生效。

## 在 OpenRA-RL 中的应用
[[openra-rl]] 是该架构的典型案例。为了弥合 LLM 的慢推理与红警的快节奏，系统提供了 `advance(ticks=N)` 工具。
-   **机制**：LLM 可以一次性发出指令让游戏快进 N 个 tick，从而在“思考”时不让游戏实时流逝，或者在思考结束后通过快进追上进度。
-   **数据**：在实战测试中，约 57% 的工具调用是 `advance`，证明了异步机制在弥补推理延迟中的核心作用。

## 优势
-   **兼容性**：允许推理速度各异的 Agent（从毫秒级的脚本 Bot 到秒级的 LLM）在同一个环境中公平竞技。
-   **鲁棒性**：消除了因网络抖动或计算负载波动导致的 Agent 超时失败。
