# PD分离架构

**PD分离架构**（Prefill-Decode Decoupling Architecture，亦称 Prefill-Decode Disaggregated）是指将大语言模型（LLM）推理过程中的两个核心阶段——**预填充** 和 **解码**——分配给不同计算节点或计算资源处理的架构设计。

## 核心阶段与组件

在传统的单体推理中，同一个 GPU 既处理预填充又处理自回归解码。PD 分离架构将这两者解耦，针对各自的特点进行硬件优化和调度：

1.  **Prefill（预填充）**：
    *   **功能**：处理用户输入的 Prompt，计算所有输入 Token 的 KV Cache。
    *   **特点**：计算密集，通常需要较高的算力。
    *   **组件**：由**预填充引擎 (PE)** 负责，专门处理高并发的输入计算。
2.  **Decode（解码）**：
    *   **功能**：根据已有的上下文逐个生成输出 Token。
    *   **特点**：内存带宽密集（需要频繁读写 KV Cache），且对延迟（首字延迟 TTFT 和生成延迟 TPOT）极其敏感。
    *   **组件**：由**解码引擎 (DE)** 负责，专门处理长序列的生成，对内存带宽需求大。

## 架构优势

*   **资源隔离**：避免长文本 Prefill 任务阻塞短文本的 Decode 任务，从而保证在线服务的响应速度。
*   **专用优化**：Prefill 节点可以配置高算力 GPU，Decode 节点可以配置高显存带宽 GPU。
*   **整体吞吐**：通过解耦处理，理论上可以提高系统的整体吞吐量。

## 挑战与优化

尽管 PD 分离架构带来了性能红利，但也引入了网络传输、时序控制和数据一致性等方面的挑战。

### I/O 瓶颈与网络传输

在智能体长文本场景下，PD 分离架构面临严重的 I/O 瓶颈，即“墙的转移”：随着 GPU 算力的增长远快于网络带宽和 HBM 容量的增长，推理性能的瓶颈已经从“计算”转移到了“搬运”上。

具体表现为**存储网络利用率不均衡**：
*   **负载拥堵**：由于 KV Cache 通常存储在外部存储或 CPU 内存中，所有的 KV-Cache 加载任务都拥挤在预填充引擎（PE）的存储网卡（[[SNIC]]）上，导致带宽瞬间饱和。
*   **资源闲置**：与此同时，解码引擎（DE）的存储网卡却在闲置，造成了严重的资源错配。

[[DeepSeek]] 的 [[DualPath]] 架构正是为了解决这一问题而生。它通过引入“存储至解码”的第二路径，利用 DE 侧闲置的存储带宽来缓解 PE 侧的压力，从而均衡了网络负载，消除了 I/O 瓶颈。

### 时序控制与数据一致性

PD 分离架构引入了复杂的时序控制问题。在智谱披露的 [[GLM-5]] **[[Scaling Pain]]** 案例中，该架构被指为导致 [[KV Cache]] 竞态条件的根本原因之一：

*   **请求生命周期与 KV Cache 回收时序不一致**：当解码阶段复用已被预填充阶段写入但尚未完全同步的内存块时，可能导致跨请求的数据损坏。
*   **显式同步需求**：为了消除这种竞态，必须在请求终止和 KV Cache 写入完成之间建立严格的显式同步机制。

智谱通过在推理引擎中引入更严格的时序约束（如确保 RDMA 写入完成后才回收槽位），解决了 PD 分离架构下的数据一致性问题。
