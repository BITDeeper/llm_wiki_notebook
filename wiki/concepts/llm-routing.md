# LLM Routing

[[LLM Routing]]（大模型路由）是指根据输入 Query 的复杂度、成本预算或性能需求，动态将请求分配给最合适的大模型（或多模型协作）的系统层能力。

## 核心问题
随着模型数量激增，应用不再依赖单一模型。LLM Routing 旨在解决“用哪个模型回答这个问题”这一核心决策，在**性能**（Quality）、**成本**（Cost）和**延迟**（Latency）之间寻找最优平衡点。

## 主要策略分类
根据 [[LLMRouter]] 框架的分类，路由策略通常分为以下几类：

### 1. 单轮路由
- **定义**：一次性决定将 Query 发送给哪个候选模型。
- **典型算法**：KNN、SVM、MLP、基于评分的打分融合。
- **适用场景**：任务边界清晰，复杂度可预判的场景。

### 2. 多轮路由
- **定义**：通过多轮试探、反馈或推理来决定最终的模型调用或结果聚合。
- **特点**：类似于“思考一下再决定”，适合复杂任务。

### 3. 个性化路由
- **定义**：将用户偏好（如历史评分、交互风格）纳入路由决策逻辑。
- **价值**：实现“同题不同人，不同模型”，提升用户体验的精准度。

### 4. Agentic 路由
- **定义**：具备 Agent 特性的路由流程，能够自主规划、调用工具或协调多个模型进行协作。
- **趋势**：被视为未来 AI 系统的高级形态。

## 架构意义
LLM Routing 正从单纯的“模型选择”演变为**多模型协同**的指挥中心。OpenAI GPT-5 的架构（快速模型 + 深度推理模型 + 路由器）验证了这一趋势：Router 不再只是分发器，而是决定系统资源分配和任务流转的核心组件。

## 与成本优化的关系
在 [[ai-subscription-crisis]] 的背景下，LLM Routing 是降低推理成本的关键技术。通过将大量简单请求分流给廉价的小模型，系统可以在保证整体体验的前提下大幅降低 API 调用成本。
