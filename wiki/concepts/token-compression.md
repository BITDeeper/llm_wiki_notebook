# Token压缩

**[[Token压缩]]**（Token Compression）是指在保留关键信息的前提下，减少模型输入序列长度（Token 数量）的技术。对于大型视觉语言模型（LVLM）而言，这是解决算力爆炸、显存占用高和延迟大问题的关键技术。

## 背景与动机
随着 LLaVA-NeXT 等模型采用多尺度视觉输入以提升细粒度理解能力，视觉 Token 的数量呈指数级增长。由于 Transformer 的注意力机制计算复杂度与序列长度呈平方关系，海量 Token 导致：
*   生成延迟显著升高。
*   显存占用居高不下。
*   在多轮对话中，[[KV缓存]] 的复用成本随 Token 数量线性增长。

## 主要方法分类
1.  **Prompt 依赖型**：
    *   代表方法：[[FastV]]。
    *   原理：根据当前文本 Prompt 筛选 Token。
    *   缺陷：在 [[多轮视觉问答]] 中，容易丢弃后续轮次所需的通用视觉信息。
2.  **Prompt 无关型**：
    *   代表方法：[[PruMerge]]。
    *   原理：基于视觉 Token 之间的相似性或 [[启发式注意力准则]] 进行压缩。
    *   缺陷：依赖人工先验规则（如注意力分数），在多轮场景下往往不是最优策略。
3.  **学习式压缩**：
    *   代表方法：[[MetaCompress]]。
    *   原理：通过神经网络（如元生成器）端到端地学习最优压缩映射。
    *   优势：数据驱动，能自适应保留对未来多轮提问有用的通用信息。

## 关键挑战
在多轮视觉问答场景中，模型无法预判用户的后续提问。因此，压缩策略不能仅关注当前问题的相关性，必须保留那些“当前看似无用但未来可能被问及”的通用视觉信息。这要求压缩算法具备更强的泛化和预判能力。
