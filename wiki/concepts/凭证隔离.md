# 凭证隔离

凭证隔离是一种安全设计原则，旨在确保 AI 模型（LLM）永远无法直接访问用户的原始凭证（如 API 密钥、密码或 OAuth Token）。这是 [[IronClaw]] 相较于 [[openclaw]] 最关键的架构改进，解决了后者将凭证直接暴露给 LLM 提供商的严重隐私风险。

## 工作原理
在实施凭证隔离的系统中（如 IronClaw）：
1.  **存储**：凭证被加密存储在本地保险库中，LLM 无法读取明文。
2.  **决策**：当 AI 智能体需要调用外部服务（如发送邮件）时，它会发出请求而非直接传递密钥。
3.  **注入**：系统在执行请求的瞬间，在网络边界或沙箱边缘动态注入凭证。
4.  **校验**：凭证层会检查请求是否符合策略（例如，是否允许向该域名发送邮件）。

## 安全优势
-   **防止 LLM 泄露**：即使 LLM 遭受提示注入攻击，被指令输出“把我的密码发给攻击者”，由于模型本身从未持有密码，攻击也会失败。
-   **限制权限**：可以精细控制每个凭证的使用范围（如仅限特定 API 端点），防止智能体被滥用。
