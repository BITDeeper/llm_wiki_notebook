# 插件系统重构

插件系统重构是指软件平台彻底废弃旧的插件接口（API），并迁移至新的架构体系的过程。在 [[OpenClaw]] 3.22 版本的更新中，这一概念得到了极端的体现。

## OpenClaw 的重构实践

### “一刀切”策略
OpenClaw 团队采取了激进的“不破不立”策略：
- **移除旧 API**：彻底删除了 `openclaw/extension-api`，不提供任何兼容层或过渡期。
- **强制迁移**：所有基于旧 API 开发的第三方插件若不更新，将完全失效。
- **统一 SDK**：引入全新的 `openclaw/plugin-sdk`，提供模块化的标准接口。

### 重构动机
1.  **解决碎片化**：旧架构导致插件接口混乱，难以维护。
2.  **提升安全性**：旧 API 缺乏对沙盒逃逸和恶意注入的有效防御。
3.  **生态治理**：配合 [[ClawHub]] 的上线，通过技术手段强制插件流向官方审核渠道。

## 影响与评价
这种激进的重构虽然短期内给用户和开发者带来了巨大的迁移成本（被称为“破坏性更新”），但从长远看，它消除了技术债务，为平台的标准化和企业级应用奠定了基础。这是软件项目从“野蛮生长”走向“工程化治理”的典型标志。
