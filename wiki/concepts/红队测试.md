# 红队测试

红队测试（Red Teaming）是一种安全评估方法，测试者从攻击者视角出发，设计对抗性样本来探测系统的安全边界。在 AI 领域，红队测试是模型发布前的关键安全评估环节，通过模拟恶意用户攻击来发现模型的安全漏洞、偏见和滥用风险。红队成员会尝试通过各种方式触发模型的有害输出、绕过安全限制或发现潜在风险。

## 在 AI 行业中的实践

主流 AI 公司（如 [[anthropic]]、[[openai]]、[[google-deepmind]]）通常在模型正式发布前 7 天左右，向经过筛选的红队测试人员开放新模型的 API 访问权限，要求他们尝试突破模型的安全防护。

在 AI 智能体安全领域，红队测试被用于发现和修复智能体在面对恶意输入时的漏洞。

红队测试已成为大模型发布流程的标准环节，是 AI 安全治理的重要组成部分。测试结果可能影响模型的发布时间、使用限制和配套安全措施。

## 在 Claude Mythos 5 中的应用

据匿名消息人士透露，[[claude-mythos-5|Claude Mythos 5]] 已被交给红队成员进行测试，这通常意味着模型处于发布前的最后阶段。红队测试的启动被视为 Mythos 发布"迫在眉睫"的重要信号。

## 在 OpenClaw 安全攻防挑战赛中的应用

[[openclaw安全攻防挑战赛-ijcai-2026|OpenClaw 安全攻防挑战赛]]采用红队测试模式，参赛选手以"红队"视角，围绕给定目标业务场景，设计并构造能够检验 [[openclaw]] 安全边界的攻击样本。

### 测试流程

1. 主办方提供统一的 OpenClaw 镜像环境，内置标准化基础工具集
2. 配套提供各类目标场景的模拟服务接口（Mock Service）
3. 参赛者构建完整任务场景、行为规则与触发输入
4. 探索智能体在复杂任务处理中的安全边界

### 评分标准

- 目标覆盖度
- 攻击成功率
- 隐蔽性与杀伤力的平衡

## Oceanus 事件暴露的风险

2026 年 6 月的 [[oceanus-api泄密事件-202606|Oceanus API 泄密事件]] 暴露了红队测试机制的内在脆弱性：

- **信任假设被打破**：红队测试员签署了保密协议，但仍有人出于商业利益将 API 权限转售
- **权限管控困难**：测试需要给予接近正式产品的 API 访问权限，难以完全防止滥用
- **矫枉过正风险**：泄密事件可能导致未来红队测试规模缩小、限制增多、审查变慢，反而降低安全测试的有效性

## 与其他安全机制的关系

红队测试与 [[平台完整性检查]]、[[kyc|KYC 实名认证]] 等平台风控措施形成互补，但各有局限。红队测试侧重于模型能力边界的安全评估，而平台风控侧重于使用层面的滥用防范。
