# 多智能体工作流

多智能体工作流是一种利用多个 AI 智能体协同解决复杂问题的协作模式。在攻克 [[高德纳]] 提出的 [[哈密顿分解]] 难题中，这种工作流发挥了关键作用。

## 核心架构

### Orchestrator（编排者）
-   **角色**：人类引导的 AI（如 [[Claude]] Opus 4.6）。
-   **职责**：负责判断“何时传、传什么、以什么格式传”，在 Agent 之间传递信息和工具。
-   **重要性**：这是连接不同智能体的桥梁，解决了智能体之间无法直接有效沟通的问题。

### Agent O（符号证明者）
-   **任务**：负责处理符号证明，例如解决奇数 $m$ 的情形。
-   **特点**：擅长逻辑推理和数学证明。

### Agent C（数据生成者）
-   **任务**：负责生成具体数据，例如找到 $m=4,6,8,10,12$ 的具体解。
-   **特点**：擅长计算和模式识别。

## 协作流程示例
1.  Agent C 在偶数情况卡在 $m=10$，无法推进。
2.  Orchestrator 将 Agent C 的解传递给 Agent O。
3.  Agent O 收到数据后，立即识别出模式：$m-2$ 层“批量层” + 2 层“修复层”。
4.  最终，两个智能体的协同攻克了困扰人类几十年的“奇偶情形全解”。

## 意义
这种工作流展示了“人类圈定战场，机器填补深渊”的新科研范式。人类负责定义边界和设计逻辑，AI 负责在无限的试错中寻找路径。
