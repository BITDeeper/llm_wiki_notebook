# 角色归因错误

**角色归因错误**（Speaker Attribution Error），又称**说话者归因错误**，是指AI将自身输出、系统事件或不可信文本误判为用户指令的结构性错误。这一概念由软件工程师 [[gareth-dwyer]] 在2026年1月首次系统记录并提出命名。

## 与幻觉的区别

- **幻觉**（Hallucination）：AI编造了一个不存在的事实
- **角色归因错误**：AI搞混了消息来源——不是内容错了，而是"谁说的"搞反了

这一区分至关重要：幻觉影响输出质量，角色归因错误动摇的是AI智能体最基本的可靠性前提。

## 技术根因

GitHub #44778 Bug报告揭示了 [[claude-code]] 中的具体机制：

1. 系统事件（后台任务完成通知、队友空闲提醒、定时器触发）以 `role: "user"` 的消息形式送入模型
2. Anthropic的Messages API仅按user与assistant两类组织会话历史，缺乏独立的系统事件角色
3. 模型在等待用户回复时收到系统事件，可能将其误判为用户新输入，继而"脑补"出用户已同意

## 学术验证

2026年3月，MIT团队（Charles Ye、Jasmine Cui、[[dylan-hadfield-menell|Dylan Hadfield-Menell]]）在arXiv发表《Prompt Injection as Role Confusion》预印本，核心发现：

- 模型判断"谁在说话"时更依赖**文本风格**而非**文本来源**
- 角色混淆在模型理解输入时即发生，而非在生成过程中
- [[cot-forgery|CoT Forgery]] 攻击在多个前沿模型上成功率达约60%

## 长上下文放大效应

角色归因错误在长上下文场景下被显著放大：

- [[上下文腐烂]] 导致模型在长对话中准确率和召回率下降
- 四级压缩流水线中，恶意指令可通过摘要被"洗白"为合法用户指令
- 一个在第50000个token处产生的角色归因错误，可能在第80000个token时触发自动部署

## 行业普遍性

[[openai|OpenAI]] 发布的指令层级论文印证了这是行业层面的系统性挑战，而非仅限于 [[anthropic|Anthropic]] 的问题。OpenAI建立的权威等级为：System > Developer > User > Tool。
