# Attention Sink

**Attention Sink**（注意力汇聚/注意力沉没/注意力陷阱/注意力沉积）是指在模型推理过程中，注意力机制异常地将大量的概率质量过度集中在少数特定 Token 上的现象。

这种现象广泛存在于各类长序列自回归模型中，包括大语言模型（LLM）、视觉-语言模型（VLM）以及视觉几何模型。

## 问题表现

Attention Sink 的具体表现形式取决于模型类型，但本质都是模型未能有效利用上下文信息，转而依赖默认或初始锚点。

### 在大语言模型 (LLM) 中
- **锚点依赖**：模型倾向于将注意力堆积在序列开头的特殊标记（如 BOS Token）上。
- **成因**：通常认为是因为模型在当前上下文中找不到真正需要关注的信息，或者由于信息检索路径受阻，导致注意力“无处可去”，从而堆积在默认位置。

### 在视觉-语言模型 (VLM) 中
- **关注无效区域**：模型错误地将大量注意力分配给图像的 **Padding 区域**（为统一输入尺寸而添加的填充）。
- **成因**：Padding 区域在语义上虽然是空白的，但其隐藏状态可能出现异常激活，导致模型被误导。

### 在视觉几何与 3D 重建中
- **忽视局部约束**：在处理长序列视频流时，模型过度依赖序列起始部分（通常是首帧 Token）的信息，而忽视了对局部几何一致性更重要的时空邻近帧。
- **性能退化**：这种对首帧的过度关注违背了局部几何约束，导致：
    - **相对位姿误差（RPE）快速增长**。
    - **长程预测稳定性下降**。
    - **重建精度退化**。

## 成因机制

Attention Sink 的产生机制在不同场景下虽有差异，但核心都与上下文信息的利用效率及训练-推理的错位有关：

1.  **语义空白与异常激活**：
    在 VLMs 中，无意义的 Padding Token 因隐藏状态异常而吸引了非自然的注意力权重。

2.  **信息检索路径受阻**：
    在 LLMs 中，当模型无法从上下文中有效检索信息时，注意力会“沉没”到 BOS Token 等默认锚点上。

3.  **训练与推理的错位**：
    在视觉几何任务（如 3D 重建）中，模型在训练时主要处理短序列，习惯于关注首帧作为锚点；但在推理阶段需要处理长序列时，这种习惯就变成了“陷阱”，导致模型无法适应流式数据的时序依赖特性。

## 后果与影响

Attention Sink 现象对模型性能和计算效率有显著的负面影响：

-   **资源浪费**：大量的计算资源被浪费在无意义的关注上（如 Padding 或 BOS Token），表明模型的信息检索效率低下。
-   **剪枝干扰**：如果直接使用注意力分数进行 [[visual-token-pruning]]，这些无意义的 token 可能会被错误地判定为“重要信息”而被保留，从而挤占了宝贵的计算资源预算。
-   **几何精度损失**：在 3D 重建等任务中，导致长序列跟踪的精度和稳定性崩塌。

## 解决与改善

针对 Attention Sink 问题，可以通过架构调整、训练策略优化或后处理修正来缓解：

### 1. 显式抑制与去偏
-   在剪枝阶段显式抑制 Padding Token 或 BOS Token 的权重。
-   使用 [[注意力去偏置]]（[[attention-debiasing]]）方法进行修正，防止模型关注无效区域。

### 2. 架构优化（深度检索）
-   引入 [[深度注意力]] 和 [[MoDA]] 架构。实验表明，当模型获得通过深度 KV 从特定层进行选择性检索的能力后，Attention Sink 现象显著减弱。这证明模型开始更精准地利用历史信息，而非依赖默认的填充行为。

### 3. 缓存一致训练
-   针对 3D 重建等长时序任务，[[LongStream]] 提出了 [[缓存一致训练]]。
-   **机制**：在训练阶段显式传递并裁剪 KV Cache，强制模型在训练时就适应流式推理的上下文状态。
-   **效果**：引导模型学习稳定的局部时序依赖，从而解决因训练-推理错位导致的 Attention Sink 问题。
