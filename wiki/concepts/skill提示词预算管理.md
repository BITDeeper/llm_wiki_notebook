# Skill提示词预算管理

对 AI Agent 加载的所有技能提示词占用的 token 空间进行量化核算、分析和优化的工程方法论。核心目标是避免技能占用过多上下文资源，从而降低运行成本、减少延迟、提升技能调用准确率。

## 核心问题

Skill 提示词过长是当前 AI Agent 系统的普遍问题，影响体现在三个维度：

- **成本**：多加一句描述，Agent 每次调用就多付一笔 token 账单
- **延迟**：更长的上下文意味着更长的处理时间
- **注意力质量**：Agent 看到的信息越多，选择时的噪声也越多

社区实证表明，将 90 词描述砍到 40 词以内后，Agent 从"不能好好调用"变为"一次选对"。

## "路标"理念

[[peter-steinberger]] 提出的核心设计原则：**Skill 要像路标，不该把整本说明挂在路标上**。技能描述的目的是让 Agent 找到正确的技能，而非在描述中包含完整的执行逻辑。执行逻辑应放在代码中，描述仅作为指引。

[[skill-cleaner]] 工具本身践行此理念：Skill.md 仅 56 行提示词，调用脚本近千行代码。

## 预算核算逻辑

采用工程化的 token 成本计算方法：

- **计费规则**：UTF8 字节数/4 向上取整（与 [[codex]] 官方源码同款）
- **预算基数**：模型上下文窗口的 2%（如 [[gpt-5.5]] 的 272k token 窗口，预算约 5440 token）
- **核算指标**：全量技能原始占用令牌、最小渲染令牌、预算内可用令牌、预算使用率、剩余预算、上下文占用比例

## 技能优先级排序

当预算不足时，按以下四级优先级决定哪些技能被保留：

1. **系统技能**（最高优先级）
2. **内置技能**
3. **插件技能**
4. **仓库自定义技能**（最低优先级）

低优先级技能在预算不足时会被截断或省略。

## 描述精简方法

通过标准化短动作词组替换冗长描述：

1. 文本预处理（统一格式、小写化、剔除标点）
2. 基于预设场景关键词词库识别业务领域
3. 调用标准化短动作词组替换原有描述

例如：调试类 → debug, inspect, fix；部署发布类 → deploy, release, verify。
