# 扩散模型插件标准化

扩散模型插件标准化是指将扩散模型的 [[可控生成]] 能力从碎片化的工具生态（ControlNet、LoRA、IP-Adapter 等）向统一的、可组合的插件框架演进的技术趋势。

## 行业痛点

当前扩散模型插件生态面临严重的碎片化问题：

- **互不兼容**：ControlNet、LoRA、IP-Adapter 等工具各自为政，代码结构差异大
- **底层冲突**：叠加多个控制条件时，插件之间在特征层频繁"打架"
- **手工拼接**：每次组合都需要开发者深入底层代码进行适配

## 解决方案

[[diffusion-templates]] 框架代表了这一方向的探索：

- 设计标准化的 Template Cache（含 KV-Cache 等媒介格式）作为中间表示层
- Template Pipeline 负责多模型调度，实现插件与基础框架解耦
- 每个 Template 独立存储、独立加载，可像搭积木一样自由组合

## 跨领域关联

这一趋势与 LLM 生态中的标准化插件机制形成呼应：

- **LLM 生态**：MCP（Model Context Protocol）、Skills 等标准化接口
- **办公场景**：[[办公技能框架]] 将办公能力拆解为可编排的标准化模块
- **架构理念**：[[模型-技能分离架构]] 将能力层与模型层解耦

扩散模型插件标准化可以视为"技能化/插件化"范式从语言模型向视觉生成领域的自然延伸，验证了 [[模型-技能分离架构]] 的跨领域普适性。

## 开放问题

- 标准化框架能否覆盖不同架构的扩散模型（DiT、UNet 等）？
- Template Cache 的 KV-Cache 媒介格式与 ControlNet 等现有方案的具体技术差异
- 标准化是否会限制模型能力的表达上限？
