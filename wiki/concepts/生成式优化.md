# 生成式优化

生成式优化（Generative Optimization）是由 [[einsia-ai]] 旗下 Navers Lab 在 [[frontier-eng-bench]] 论文中提出的一种新的 AI 评测范式。

## 核心理念

传统的 Agent 评测大多采用二元评估逻辑——"对就是对，错就是错"。但真实世界的科研与工程从来不是这样的。很多时候，一个方法已经能跑，结果也说得过去，但真正决定竞争力的是后续持续的迭代优化。

生成式优化要求 Agent 不再只"交一次答案"，而是真正进入一个**工程闭环**：

1. **提出方案** — 基于领域知识生成初始解
2. **运行仿真** — 在仿真器或真实环境中执行
3. **获取反馈** — 读取详细的运行日志和指标
4. **修改方案** — 根据反馈调整代码或参数
5. **逼近最优** — 在固定预算内不断迭代

## 与传统评测的区别

| 维度 | 传统评测 | 生成式优化 |
|------|---------|-----------|
| 评估标准 | 对/错二元判断 | 优化程度（连续分数） |
| 交互模式 | 单次提交 | 多轮迭代闭环 |
| 能力要求 | 单点知识 | 领域知识 + 编码 + 反馈理解 + 搜索决策 |
| 现实对应 | 答题 | 真实工程优化 |

## 能力组合要求

生成式优化对 Agent 提出了复合能力要求：

- **领域知识**：理解电池为什么会析锂、机械臂为什么会撞、库存策略为什么会失效
- **编码能力**：把优化想法变成可执行方案
- **反馈理解**：读懂 simulator 给出的结果意味着什么
- **搜索决策**：在有限预算里决定是大改一版还是小修一刀

## 意义

生成式优化将 AI 评测的尺度从"能不能答对"转变为"能优化到什么程度"，填补了 [[auto-research]] 中"从可行到最优"这一关键迭代环节的评测空白。它与 [[递归式自我改进]]、[[自进化架构]] 和 [[agentic-engineering]] 等概念方向高度契合，指向下一代能在长程反馈里持续迭代、自我进化的 Agent 系统。
