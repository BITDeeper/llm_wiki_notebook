# Operator 机制

[[Operator 机制]] 是 [[OpenWorldLib]] 框架中用于连接原始输入（或环境信号）与核心执行模块（如 Synthesis、Reasoning）的中间层组件。它负责处理真实世界中复杂、异构的多模态数据，将其转换为模型可以理解的标准格式。

## 核心功能

Operator 机制主要承担两个核心功能：

### 1. 校验
在数据进入核心模型之前，Operator 会检查数据的：
- **格式**：确保数据类型（如张量、列表、字符串）符合预期。
- **形状**：验证图像尺寸、序列长度等维度是否匹配模型要求。
- **类型**：确认输入模态（文本、图像、动作等）是否被当前模型支持。

### 2. 预处理
将原始信号转换为标准化的内部表示，常见的操作包括：
- **图像处理**：尺寸调整、归一化、颜色空间转换。
- **文本处理**：分词、Token ID 转换。
- **动作处理**：归一化、离散化。

## 工作流程
当 [[Pipeline]] 被调用时，系统首先将原始输入传递至 Operator 的 `process()` 方法。处理完成后，干净、标准化的数据才会被送入 [[四大核心模块]] 进行推理或生成。

## 设计意义
- **解耦**：将数据清理逻辑与核心模型逻辑分离，提高代码可维护性。
- **鲁棒性**：在入口处拦截错误数据，防止模型崩溃。
- **扩展性**：新增数据类型只需添加新的 Operator，无需修改核心框架。
