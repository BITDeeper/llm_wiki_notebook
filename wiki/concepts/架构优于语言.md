# 架构优于语言

在 AI Agent 赛道上，框架层面的架构决策比语言层面的原始性能更重要。这一洞见由 [[hermes-agent]] 用 Python 击败用 Rust 编写的 [[codex]] 这一事件所验证。

## 核心论点

1. **语言性能差异在Agent场景中被稀释**：底层语言的性能差异（毫秒级）相对于 LLM 调用延迟（数百毫秒至数秒）几乎可以忽略。[[hermes-agent]] 优化砍掉的 443ms 已是框架层能挤出的极限，而一次 LLM 调用的延迟动辄更高。

2. **可编辑性 > 原始速度**：Python 的"活"（可编辑、可实时改进迭代）比 Rust 的"快"更有价值。[[teknium]] 指出，迁移到 Rust 将丧失实时改进和迭代的能力。

3. **架构决策决定上限**：开发者 netrunner 评论指出，"Python 在多轮任务上打赢 Rust，本质上是架构决策的胜利，而不是语言速度的胜利"。

## 实例验证

- [[hermes-agent]]（Python）通过 [[框架开销优化]] 在基准测试中以 6:5 击败 [[codex]]（Rust）
- 优化前 Hermes 5:6 落后，优化后 6:5 反超——翻盘靠的是架构优化而非语言替换

## 局限性

报道本身承认 443ms 的优化已是"框架层能挤出的极限"，这意味着语言选择在实际 Agent 使用中的影响可能被夸大。该论点更适用于 Agent 框架场景，不一定适用于所有软件工程领域。
