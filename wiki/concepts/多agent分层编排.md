# 多Agent分层编排

多 Agent 分层编排是一种将智能体系统划分为不同功能层级（如调度、配置、执行）的架构设计模式，旨在实现复杂任务的分工协作与微服务隔离。

## 架构层级
根据 [[scienceclaw]] 的实现，该架构通常包含以下三层：

### 1. 调度层
- **角色**：Lead Agent。
- **职责**：作为系统的决策中枢，负责统筹规划。它将模糊的用户需求拆解为具体的执行计划，并将任务细分发送给专业的 SubAgent。
- **类比**：相当于项目中的“项目经理”或“指挥官”。

### 2. 配置层
- **角色**：SubAgent 注册表。
- **职责**：连接顶端 Lead Agent 和子 Agent 工厂。主要负责对 Agent 进行注册配置，确保每个 Agent 都拥有独立的工具调用权限、清单和行为配置。
- **作用**：实现权限管理和行为定制。

### 3. 执行层
- **角色**：子Agent工厂。
- **职责**：多 Agent 系统的执行终端。所有 Agent 都必须通过该统一入口创建。
- **特性**：
    - 支持 Soul 文件热更新，无需重启系统即可进行配置实时变更。
    - 支持通过功能开关灵活搭配中间件。

## 优势
- **微服务隔离**：每个 SubAgent 只能看到自己该看的内容，不同任务之间实现了隔离，提高了安全性。
- **执行效率**：相比于单体 Agent 或简单的链式调用，分层编排能显著提升复杂任务的执行效率。
- **弹性扩缩容**：结合微服务架构，可以实现算力资源的动态调整。

## 应用场景
这种架构常见于需要处理复杂、长链路任务的 AI4S（人工智能用于科学）和企业级智能体平台，如 [[scienceclaw]]。
