# Vibe Graphing

[[Vibe Graphing]] 是一种利用大语言模型（LLM）将自然语言指令转化为结构化工作流的技术范式。它被视为对 [[Vibe Coding]]（直接让 AI 生成代码）的改进与重构，特别适用于多智能体系统（MAS）的编排。

## 核心原理

[[Vibe Graphing]] 的本质是一个“自然语言意图 -> 结构化中间表示（IR） -> 可执行工作流”的编译器。它不直接生成冗长的底层代码（如 Python），而是生成一种高抽象级的拓扑配置（如 JSON），从而大幅降低 Token 消耗并提高逻辑的稳定性。

## 三阶段设计流程

1.  **角色分配**
    系统首先剥离代码实现细节，仅关注任务中的“人”。根据自然语言指令（如“构造一个文献综述工作流”），将意图映射为一组候选智能体（如检索员、写作员），并划定严格的责任边界。

2.  **拓扑设计**
    确定角色后，系统构建一个有向图拓扑骨架。此阶段仅定义节点间的消息依赖和执行顺序（串行、并行、循环），不涉及具体的 Prompt 或工具调用细节。

3.  **语义补全**
    最后，系统对拓扑骨架进行参数化实例化，为每个节点精准配置指令、输入输出约束，使其成为可执行的节点。

## 优势对比

| 特性 | Vibe Coding | Vibe Graphing |
| :--- | :--- | :--- |
| **输出形式** | 底层代码 (如 Python) | 结构化配置 (如 JSON/图) |
| **Token 成本** | 高 (需生成大量语法代码) | 低 (仅需生成拓扑结构) |
| **DSL 兼容性** | 差 (模型常缺乏小众 DSL 训练) | 好 (通过中间层解耦) |
| **可维护性** | 低 (代码逻辑分散) | 高 (拓扑结构清晰) |

## 应用场景
该范式在 [[MASFactory]] 框架中得到了完整实现，特别适合需要复杂逻辑编排、多角色协作以及动态路由控制的 AI 应用开发。
