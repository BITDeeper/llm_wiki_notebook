# Token 吞噬陷阱

**Token 吞噬陷阱**（Token Trap）是指 AI 智能体在执行任务时，因架构设计缺陷或缺乏优化，导致 API 调用成本（Token 消耗）呈现非理性指数级增长的现象。这通常使得 AI Agent 的运行成本远超其替代的人类劳动成本，导致经济上的不可行性。

## 形成原因
该现象通常发生在缺乏独立“中枢大脑”或状态管理机制的 Agent 架构中（如 [[OpenClaw]]）：
1.  **循环调用**：Agent 在处理复杂任务时，陷入与自身或工具的反复对话循环，无法有效终止。
2.  **上下文堆积**：长期记忆模型或缓存机制处理不当，导致每次交互都重复读取大量历史 Token。
3.  **缺乏规划**：Agent 未能进行有效的步骤规划，导致重复尝试和无效操作。

## 典型案例
在 [[Moltbook]] 事件中，[[OpenClaw]] 被称为“Token 熔炉”：
- 有用户报告单晚消耗 **5000 万 Token**（约 150 美元）。
- 有用户在 20 小时内耗尽 100 美元预算。
- 仅仅说一声“Hi”或进行 5 次简单互动，就可能耗尽所有额度。
- 据估算，使用 OpenClaw 的月薪成本高达 3000 美元，甚至超过雇佣真人秘书的成本。

## 影响
Token 吞噬陷阱直接导致了 [[ai-subscription-crisis]]（AI 订阅制危机）的加剧。它证明了在当前模型成本下，无限制的自主 Agent 在经济上是不可持续的，迫使行业转向更严格的资源管理、本地推理或分层定价模式。
