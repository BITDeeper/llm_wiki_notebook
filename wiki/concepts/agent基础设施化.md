# Agent基础设施化

Agent竞争从框架本身转向运行基础设施建设的行业趋势。当通用Harness框架（如[[openclaw]]）的技术底座已经普及后，行业竞争的焦点从"谁的框架更好"转向"谁能让更多人真正用起来"。

## 核心论点

- 限制Agent普及的已经不是模型能力，而是缺乏让普通用户真正用起来的基础设施
- Agent的价值已被验证，卡点不在于"要不要用"而在于"能不能落地"
- Foundation Capital的Context Graphs观点：Agent公司护城河不在框架本身，而在执行过程中沉淀的决策经验

## 基础设施化的具体方向

1. **云端运行环境**：云主机、云盘、云浏览器（[[agent云端化]]）
2. **安全沙箱**：隔离运行环境，避免本地部署风险
3. **扩缩容能力**：按需调度算力资源
4. **配置自动化**：[[agent教练模式]]降低使用门槛
5. **专家预制**：覆盖高频场景的即用型Agent

## 行业印证

- Anthropic、微软、Google等云厂商均在将Agent运行层平台化
- [[360公司]]的[[安全龙虾云端版]]踩的正是这条线
- Gartner预测2026年底40%企业应用将内置任务型AI Agent
- 这标志着Agent行业进入[[产业深水区]]，从技术验证走向应用闭环
