# 端到端测试

端到端测试（E2E Testing）是指模拟真实用户行为，从头到尾完整运行应用程序流程的测试方法。在 AI 智能体开发中，它是确保 [[渐进式推进]] 不破坏现有功能的关键手段。

## 为什么需要 E2E 测试？
AI 智能体（如 Claude）在默认情况下的“测试行为”往往停留在代码层面：
- 阅读代码逻辑。
- 运行单元测试。
- 使用 `curl` 测试 API 端点。

然而，这些方法无法发现交互层面的 Bug（例如按钮点击无响应、页面布局错乱）。只有通过真实的浏览器操作，才能验证整个用户流程是否顺畅。

## 实施方式
- **工具**：使用 [[Puppeteer MCP]] 等浏览器自动化工具。
- **流程**：
    1. 启动本地开发服务器。
    2. 打开浏览器并执行用户操作（如“打开新对话 -> 输入消息 -> 查看 AI 回复”）。
    3. 截图或检查 DOM 元素以验证结果。

## 局限性
- **视觉盲区**：AI 模型的视觉能力可能无法识别浏览器原生元素（如 `alert` 弹窗），导致相关功能测试覆盖不全。
- **维护成本**：随着应用复杂度增加，维护自动化测试脚本的难度也会上升。

## 在智能体工作流中的角色
E2E 测试充当了“守门员”的角色。在智能体尝试添加新功能之前，强制其先通过 E2E 测试，确保项目始终处于可运行状态。
