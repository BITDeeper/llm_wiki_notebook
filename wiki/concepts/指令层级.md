# 指令层级

**指令层级**（Instruction Hierarchy）是 [[openai|OpenAI]] 在2026年4月发布的前沿LLM论文中提出的模型指令信任等级框架，为大模型设定了一套"权力秩序"规则，规定了当不同来源的指令发生冲突时的优先级排序。

## 权威等级

框架建立了四级信任等级，从高到低为：

1. **System（系统）** — 最高优先级/最高权威，通常包含平台预设的安全规则和核心原则。
2. **Developer（开发者）** — 次高优先级，包含产品特定的功能要求和格式约束。
3. **User（用户）** — 普通用户的输入请求。
4. **Tool（工具）** — 最低优先级/最低信任度，包括模型调用的外部工具返回的内容、网页抓取的数据等。

## 核心问题

论文明确指出：如果模型把一条不可信的指令当成了权威指令来执行，就会产生安全风险。这印证了 [[角色归因错误]] 是整个行业层面的系统性挑战——"模型是否会错误地信任不该信任的指令"已被视为需要专门训练和评估的安全问题。

## 运作机制

- **高优先级优先**：当低优先级指令与高优先级约束冲突时，模型必须遵循高优先级指令。
- **补充原则**：低优先级指令仅在与高优先级指令不冲突时生效，主要用于补充细节而非覆盖规则。

## 应用场景

随着 AI 进入 [[智能体]] 时代，模型需要处理来自多方且可能相互矛盾的输入。指令层级主要用于解决以下问题：

1. **防御 [[提示词注入]]**：忽略隐藏在工具输出或网页内容中的恶意指令。
2. **防止数据泄露**：拒绝用户试图通过"越狱"绕过系统安全限制的请求。
3. **确保行为一致**：保证模型在面对复杂的交互环境时，始终遵守开发者和系统设定的核心规则。

## 反面案例：Claude Code Bug

[[claude-code]] 的 #44778 Bug报告揭示的问题恰好是指令层级的反面案例：系统事件（应属于低信任度的Tool级别）被标记为 `role: "user"`（较高信任度），导致模型错误地将其视为权威指令执行。

## 训练挑战

建立有效的指令层级面临以下难点：

- **区分能力**：难以区分模型是"不懂规矩"还是单纯"没看懂"复杂的指令冲突。
- **评估误差**：作为裁判的大模型本身也可能误判指令的优先级。
- **过度拒绝**：模型可能为了安全而学会拒绝所有请求，导致可用性丧失。

## 解决方案

OpenAI 通过 [[IH-Challenge]] 数据集，利用极简任务和客观评分的强化学习方案，成功训练出遵循指令层级的模型（如 [[GPT-5 Mini-R]]），在提升安全性的同时保持了模型的帮助率。
