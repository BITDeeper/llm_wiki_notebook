# Dogfooding（吃自己的狗粮）

**Dogfooding**（又称"吃自己的狗粮"）是软件开发中的一种实践方法，指开发者或公司使用自己开发的产品，以便从用户角度发现问题和进行改进。这一术语源自"狗粮公司应该吃自己生产的狗粮"的通俗说法。

## 核心原则

1. **真实使用环境**：在真实场景中使用产品，而非模拟环境
2. **用户视角**：以用户而非开发者的角度体验产品
3. **快速反馈**：第一时间发现产品缺陷和改进空间
4. **建立信任**：向市场展示对产品的信心

## AI 时代的极致实践

在 AI Agent 领域，[[boris-cherny]] 将 Dogfooding 推向了极致：

### 编程领域
- **不再手写代码**：完全依赖 [[claude-code]] 进行开发
- **验证模型能力**：通过实际编程任务验证 AI 的代码生成能力
- **发现边界情况**：在真实开发中发现模型的长处和局限

### 生活自动化
- **全面接管**：让 [[claude-cowork]] 处理工作和生活的方方面面
- **任务授权**：包括预定航班、支付罚单、催办同事等
- **信任建立**：通过深度使用建立对 AI Agent 的信任

## Dogfooding 的价值

### 产品开发角度
1. **快速迭代**：第一时间发现并修复问题
2. **需求验证**：验证产品是否真正解决用户痛点
3. **性能优化**：在真实负载下优化性能

### 市场推广角度
1. **建立信任**：开发者自己使用是最好的背书
2. **案例展示**：自身使用经历是最好的营销案例
3. **社区影响**：影响早期采用者和开发者社区

## 风险与挑战

### 过度依赖风险
- **认知投降**：可能过度依赖 AI 输出，放弃独立判断
- **系统失控**：如 [[openclaw]] 事件所示，Agent 可能做出意外行为
- **技能退化**：长期不手写代码可能导致基础技能退化

### 产品盲区
- **开发者偏见**：开发者可能无法代表所有用户群体
- **使用场景局限**：个人使用场景可能无法覆盖所有用户需求
- **容忍度差异**：开发者对 bug 的容忍度可能高于普通用户

## 最佳实践

1. **平衡使用**：在 Dogfooding 与保持独立判断之间找到平衡
2. **多样化测试**：结合内部测试和外部用户反馈
3. **记录观察**：系统记录使用过程中的问题和洞察
4. **渐进式依赖**：逐步增加对 AI Agent 的依赖程度，建立信任

## 相关案例

- **Microsoft**：早期在内部大量使用 Windows 和 Office
- **Google**：员工在产品正式发布前使用测试版本
- **Boris Cherny**：完全依赖 Claude Code 和 Claude Cowork 进行工作和生活管理
