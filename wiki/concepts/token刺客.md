# Token刺客

「Token刺客」是一个行业俚语，特指由于 AI 系统底层故障（如缓存失效、上下文重复处理）导致 Token 消耗量非正常、成倍增长的现象。这种隐形故障往往在用户未察觉时迅速耗尽预算配额。

## 典型案例：Claude Code 额度危机

2026年3月，[[claude-code]] 在上线「计算机使用」功能后，大量用户报告额度在极短时间内耗尽。开发者 [[felixrieseberg]] 通过逆向工程揭露了两个导致 Token 消耗暴涨 10-20 倍的底层 Bug：

1. **Bun 运行时字符串替换 Bug**：CLI 自带的二进制文件导致缓存频繁失效。
2. **Resume 缓存崩溃**：使用 `--resume` 恢复会话时，缓存机制 100% 失效。

## 成因分析

### 缓存机制失效
大模型 API 通常利用缓存来避免重复处理相同的输入（如系统提示词或大型代码库上下文）。一旦缓存失效，每次请求都需要重新处理海量输入 Token，导致成本呈指数级上升。

### 上下文循环
在某些 Agent 任务中，如果模型陷入循环（如反复读取相同的错误日志而不采取行动），也会导致 Token 消耗失控。

## 影响

### 对用户
- **经济损失**：按量计费用户面临意外的高额账单。
- **服务中断**：订阅制用户（如 Claude Pro/Max）迅速触及额度上限，导致工作中断。

### 对商业模式
「Token刺客」现象加剧了 [[ai-subscription-crisis]]。它暴露了固定月费模式在面对高消耗 Agent 任务时的脆弱性，迫使厂商重新审视计费策略和系统稳定性。
