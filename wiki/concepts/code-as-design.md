# Code as Design（设计即代码）

一种设计理念，主张设计产物与代码产物合二为一，从根本上消除从设计稿到代码的"翻译链"。

## 问题背景

传统设计到开发的流程存在一条漫长且有损的翻译链：设计师在Figma里精心调好的界面，交到研发手上还原出来走了样。间距不对、圆角不对、颜色不对，一个页面来回三五轮返工是常态。设计师超过30%的工时消耗在"盯还原"上。从设计工具到代码之间，设计到代码的还原度普遍不足70%。

已有的解决方案尝试：
- **Design-to-Code插件**：生成的代码不可维护
- **低代码平台**：牺牲设计品质换速度，两头不讨好

## 核心理念

Code as Design跳过了设计到代码的翻译距离。设计师在画布上操作的每一个元素、产品经理在Preview中点击查看的每一个交互、研发最终接手的那份文件——从第一步起，就是同一份可运行的工程文件。

不是先画图再翻译成代码，不是先出视觉稿再让研发"照着做"。设计产物即代码产物，"翻译链"不再存在，因为不再需要翻译。

## 实践案例

[[qoderwork]] 设计工作台是这一理念的代表性实践。其生成的设计产物可以一键交付至 [[qoder-ide]] 等开发工具，研发打开的就是一个可以继续写业务逻辑的项目。

## 与Vibe Coding的关系

Code as Design结合 [[vibe-coding]]（零代码氛围编程），使用户无需理解代码原理，通过自然语言描述即可生成可运行工程文件，进一步降低了设计到开发的门槛。

## 当前挑战

设计产物如何融入已有项目上下文仍是未解决问题。目前一键交付默认打开新workspace，但实际开发中团队往往已有现有项目工程。
