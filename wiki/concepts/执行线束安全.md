# 执行线束安全

执行线束（Execution Harness）是指 Agent 运行所在的执行环境，它决定了模型能调用哪些工具、访问哪些资源、信息如何流动、何时终止执行。执行线束安全关注的是这一层面的安全属性，区别于传统的模型层安全（如对齐、jailbreak 防御）。

## 核心观点

真正被部署的 agent 并不是裸模型。无论是 [[claude-code]] 自动提交 PR、[[codex]] 修复 issue，还是能够直接操作资金的客服助手，它们都运行在 execution harness 之中。模型只是提出动作，**真正决定行为边界的是 harness**。

## 模型安全 vs. Harness 安全

| 维度 | 模型安全 | Harness 安全 |
|------|---------|-------------|
| 关注点 | 模型是否对齐、是否容易被 jailbreak | 工具调用是否合规、资源访问是否越权、信息流是否安全 |
| 评测对象 | 最终输出 | 完整执行轨迹 |
| 失败模式 | 拒绝回答、生成有害内容 | 越权操作、敏感信息泄露、未授权副作用 |
| 当前状态 | 已有大量研究和 benchmark | 长期被忽视，[[harnessaudit]] 首次系统化定义 |

## Harness 设计的双刃剑效应

原生 harness 的设计既可能提升安全，也可能放大风险：
- [[claude-code]] 的原生 harness 同时提升了任务完成率和安全性
- [[codex]] 的原生 harness 提高了完成率却降低了安全性

Harness 的设计本质上决定了 agent 能够被"安全部署"的上限，不同厂商在这些设计上的差异非常大。

## 多 Agent 系统中的特殊挑战

在多 agent 系统中，信任边界从 agent 的工具调用变成了 message bus。每一次 agent 间的交接都是信息可能流向不该去的地方的风险点。单 agent 到多 agent 切换时：
- 工具合规性从 >0.85 降至 0.64
- 资源合规性从 >0.85 降至 0.63
- 信息流合规性首次成为可见问题，仅为 0.58
