# 面向 Agent 的软件重设计

面向 Agent 的软件重设计是 [[saas-bench|SaaS-Bench]] 评测引发的一个重要共识：今天的 SaaS 是给人设计的——菜单、按钮、表单，都在服务人类的眼睛和手指。但当 Agent 成为主要用户，这些界面就变成了累赘。

**未来不是让 Agent 学会操作人类的软件，而是软件本身要为 Agent 重新设计。**

## 背景

[[saas-bench|SaaS-Bench]] 揭示的四种结构性失败模式（越往后越做不对、一步错步步错、做完不检查、执行极不稳定）不只是 Agent 的技术债，也反映了当前软件形态与 Agent 操作方式之间的根本性不匹配。GUI 对 Agent 而言是低效且容易出错的信息传递方式，面向人类的 SaaS 可能都要为 Agent 重做一遍。

## 开放问题

- **API 优先还是新 UI 范式？** 软件为 Agent 重设计的具体技术路径尚不明确
- **工程量极其庞大**：需要重构整个 SaaS 生态，与短期困境形成张力
- **过渡期策略**：在"为人类设计"和"为 Agent 设计"之间如何平滑过渡
- **底层能力问题**：即使软件重设计，Agent 的底层能力（状态推理、闭环验证、错误恢复）仍需解决
- **张力**："软件为 Agent 重做"与"Agent 底层能力不足"之间存在张力

## 与 Wiki 概念的关联

- **[[任务执行范式]]**：软件重设计是任务执行范式从"模拟人类操作"向"原生 Agent 接口"演进的方向；AI 行业正从单纯模型开发转向智能体工程化系统
- **[[领域驱动ai办公]]**：AI 办公从"对话驱动"向"领域驱动"的范式转移
- **[[产业深水区]]**：软件重设计代表了产业深水区中"应用闭环"的深层重构需求
- **[[场景白盒化推理]]**：为 Agent 重设计的软件天然具备更好的可观测性和可干预性
- **[[应用闭环]]**：当前 Agent 在真实业务流程中远未跑通应用闭环，部分原因可能在于软件本身的设计
