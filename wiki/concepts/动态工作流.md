# 动态工作流

动态工作流（Dynamic Workflows）是 [[claude-code]] 中处于"研究预览"阶段的新功能，允许模型自主规划工作流、启动数百个并行子智能体、持续运行数天并支持断点续跑，最终自行验证输出。

## 核心机制

1. **自主规划**：Claude 能够自主规划工作流程，无需人工逐步指导。
2. **并行子智能体**：在单次会话中同时启动数百个并行运行的子智能体（Subagents）。
3. **长时间运行**：得益于 [[claude-opus-4-8]] 的加持，智能体可持续运行数天。
4. **断点续跑**：中途断了还能继续，与 [[断点续跑]] 概念直接对应。
5. **自我验证**：在提交最终报告前，Claude 会先行对自身输出进行严格验证。

## 使用方式

在提示中使用"workflow"关键词即可触发动态工作流模式。目前已面向 Claude Code 的企业版、团队版及 Max 版用户开放。

## 标杆案例

JavaScript 运行时 Bun 的原作者 Jarred Sumner 利用动态工作流将 Bun 从 Zig 移植到 Rust：
- Rust 代码量约 75 万行
- 现有测试套件通过率 99.8%
- 从首次提交到合并仅用 11 天

## 意义

动态工作流代表了 AI 编程从单次对话辅助到代码库级自主迁移的质变，是 [[1-n-agent调度]] 概念的产品化实现。同时也将 Token 消耗推向新量级，与 [[tokenmaxxing]] 趋势形成呼应。
