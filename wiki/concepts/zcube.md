# ZCube 架构

ZCube 是一种新型数据中心组网架构，由 [[智谱]]、[[驭驯网络]] 和 [[清华大学]] 联合研发，论文发表于网络领域顶会 ACM SIGCOMM 2025。论文标题为 *"From ATOP to ZCube: Automated Topology Optimization Pipeline and A Highly Cost-Effective Network Topology for Large Model Training"*。该架构从根本上重新设计了 AI 推理集群的网络拓扑，取消了传统 Clos 的 Spine 层，被评价为"显著改变整个行业对网络认知方式"。

## 核心理念

ZCube 的核心思路是**从架构层面消除"可避免的拥塞"**，而非在拥塞发生后通过协议层补救。这与传统 Clos/ROFT 架构依赖 ECMP 多路径负载均衡的思路根本不同。

## 三重设计逻辑

### 第一层：取消分层，全网扁平化

- 取消 Spine 层交换机，将所有 Leaf 交换机按序号奇偶分为两组
- 两组之间采用**完全二部图互联**（每台奇数交换机与所有偶数交换机相连）
- 网络直径为 2 跳，介于单层交换机（1 跳）和双层 Clos（3 跳）之间

### 第二层：单轨 + 多轨混合接入

- 每张 GPU 网卡双端口分别以不同方式接入两组交换机
- 第一个端口"多轨"接入：相同编号 GPU 连接同一台奇数交换机
- 第二个端口"单轨"接入：连续编号 GPU 连接同一台偶数交换机
- **关键特性：全网任意两张 GPU 之间有且仅有一条最优路径**，消除多路径选路不确定性

### 第三层：更低成本，更强扩展性，更高容错

- 相同规模下比 Clos/ROFT 减少约三分之一的交换机和光模块
- GPU 对不可达概率比传统双平面 Clos 网络低 50% 以上

## 与传统架构的对比

| 维度 | 传统 Clos / ROFT | ZCube |
|------|-----------------|-------|
| 拓扑层级 | 多层（Leaf-Spine） | 单层（仅 Leaf） |
| 网络直径 | 3 跳（二层组网） | 2 跳 |
| 路径数量 | 多路径（需 ECMP 选路算法） | 唯一最优路径 |
| 拥塞策略 | 被动控制（红绿灯） | 主动消除（重新规划路网） |
| 硬件成本 | 基准 | 减少约三分之一 |

## 扩展性

- 以主流配置（51.2T 容量交换机，128 个 400Gbps 端口）计算，ZCube 仅用一层 Leaf 交换机即可连接 **16384 块 GPU**
- 下一代 102.4Tbps 交换机 + 四端口网卡可支持 **65536 张 GPU**
- 通过更高容量交换机或更多平面划分，可支持数十万 GPU 互联

## 生产验证数据

在 [[智谱]] 千卡级 [[glm-5-1|GLM-5.1]] coding 推理集群中完成实测，实验条件为 GPU 型号、软件栈、业务代码均不变，仅替换组网架构：

- **推理吞吐**：提升 15% 以上
- **TTFT P99（首 Token 尾延迟）**：下降 40.6%
- **网络硬件成本**：减少三分之一
- **万卡集群成本节省**：2.1 亿至 6.4 亿元

控制变量实验（32 卡集群，仅提升网络带宽 100Gbps→200Gbps）：

- 推理吞吐提升约 19%
- 首 Token 时延下降约 22%

## 与 MRC 的互补关系

[[mrc协议|MRC]]（OpenAI 发布）和 ZCube 分别从协议层和架构层发力：

- **MRC** 优化"交通规则"——在拥塞出现后通过更聪明的调度缓解。
- **ZCube** 重新规划"路网本身"——从源头降低拥塞产生的概率。

两者技术路线不同但高度互补，形成"架构层无拥塞 + 协议层强容错"的组合，传递的信号一致：**网络是 AI 基础设施的下一个主战场**。

## 局限性

- 目前仅在推理集群验证，训练场景适用性未提及。
- 改造需重新设计布线模式、IP 编址、路由策略，基础设施层改造成本不可忽视。
- 生产环境稳定运行仅两周，长期可靠性待观察。

## 与现有概念的关联

ZCube 代表了 [[scaling-law]] 时代的效率补充——与其无限堆 GPU，不如让现有 GPU 跑得更顺。这与 [[批次不变性]] 和 [[DeepGEMM]] 同属"不增加硬件、通过底层工程创新提升效率"的叙事脉络，DeepSeek 在算子层，智谱在网络层。
