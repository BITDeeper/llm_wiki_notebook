# 过程可解释性

**过程可解释性**（Process Interpretability）是指在评估 AI 智能体（特别是代码 Agent）时，不仅关注其最终输出的结果（如代码是否通过测试），更深入分析其达成结果的中间推理步骤、检索路径和决策依据。

## 背景与动机
在自动化软件工程领域，传统的评测基准（如 [[swe-bench]]）主要依赖端到端（End-to-End）成功率。这种“黑盒”评价方式存在显著缺陷：它无法区分 Agent 是真正理解了问题并精准定位了代码，还是通过盲目试探、运气或过度生成测试用例来“蒙对”结果。

## 核心内涵
过程可解释性要求打开 Agent 的“黑盒”，关注以下维度：
1. **检索路径**：Agent 在解决问题的过程中访问了哪些文件和代码片段？
2. **决策依据**：Agent 是基于什么逻辑（如关键词匹配、语义理解）来决定下一步操作的？
3. **信息利用**：Agent 检索到的关键信息是否被有效整合到了最终的解决方案中？

## 应用实例
[[contextbench]] 是首个实现过程可解释性的代码评测基准。它通过追踪 Agent 的操作轨迹，并在文件、代码块、行号三个粒度上计算检索指标，从而量化 Agent 的“定位能力”。

## 意义
- **诊断瓶颈**：帮助开发者发现 Agent 是在“找代码”阶段出错，还是在“用代码”阶段出错（如 [[信息整合瓶颈]]）。
- **提升信任**：只有当 Agent 的推理过程可被观测和验证时，开发者才能真正信任其生成的代码。
- **优化方向**：指明了从单纯提升模型生成能力向优化检索与推理链路转变的技术路径。
