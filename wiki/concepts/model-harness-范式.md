# Model+Harness 范式

**Model+Harness 范式** 是一种将通用大模型能力转化为垂直行业生产力的核心架构公式，定义为 **Agent = Model + Harness**。

## 定义
- **Model（模型）**：提供智能潜力，包括理解、推理与生成能力。通常由大语言模型（LLM）或多模态模型构成。
- **Harness（驾驭/约束层）**：提供执行标准，作为连接模型与应用的中间层框架，负责上下文管理、工具集成、合规约束和风险控制。

## 解决的问题
通用大模型在垂直行业落地时面临三大局限：
1. **缺乏持久记忆**：无法直接调用业务系统 API 或保持长期状态。
2. **稳定性不足**：易出现“幻觉”输出，导致业务风险。
3. **缺乏业务约束**：不懂“权限”与“合规”，无法直接处理复杂的业务逻辑。

Harness 层通过给模型“划好规矩、守住底线”，将不确定的概率性输出转化为确定的业务结果。

## 与现有概念的关系
- **与 [[runtime-agent-os]] 的关系**：Model+Harness 范式是 runtime-agent-os 在具体业务场景（特别是金融等高合规行业）的工程化实现。Harness 对应 OS 中的控制与交互层。
- **与 [[任务执行范式]] 的关系**：该范式强调从单纯的模型开发转向“模型+工程化系统”的协同，是任务执行范式在 Agent 时代的具体体现。
