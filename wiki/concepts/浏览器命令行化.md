# 浏览器命令行化

浏览器命令行化是一种将网站操作从 GUI 交互转化为确定性 CLI 命令的技术范式。其核心思想是：将浏览器自动化从 AI 推理重新拉回系统调用，使 Agent 操作具备确定性、可重复性和零 Token 消耗的特征。

## 核心原理

传统 Agent 浏览器操作流程为：LLM 理解页面 → 决策操作 → 执行动作 → 解读结果，每一步都消耗 Token 且结果不确定。

浏览器命令行化的流程为：CLI 命令 → 本地浏览器直接执行 → 结构化输出，跳过 LLM 推理环节，结果结构一致、可管道化。

## 与浏览器 Agent 路线的对比

| 维度 | 浏览器 Agent | 浏览器命令行化 |
|------|-------------|---------------|
| 执行方式 | LLM 推理驱动 | 本地确定性执行 |
| Token 消耗 | 高 | 零（执行阶段） |
| 结果确定性 | 低（受模型输出影响） | 高（同一命令结果一致） |
| 适用场景 | 动态交互、未知页面 | 确定性任务、已知站点 |
| 可组合性 | 弱 | 强（可管道、可脚本、CI/CD 友好） |

两者并非完全互斥：CLI 化操作更适合确定性任务，浏览器 Agent 更适合动态交互场景。

## 技术实现要素

1. **登录态复用：** 通过 Chrome 扩展直接复用浏览器 cookie，无需手动配置凭证
2. **适配器层：** 为每个站点编写专用适配器，将页面操作映射为 CLI 命令
3. **结构化输出：** 统一输出 JSON/CSV/Markdown，便于下游消费
4. **CDP 协议扩展：** 通过 Chrome DevTools Protocol 将能力从网页延伸到 Electron 桌面应用

## 对 Agent 基础设施的意义

浏览器命令行化是 [[1-n-agent调度]] 的基础设施前提——确定性命令比浏览器自动化更适合批量并行调度。它呼应了 [[token作为生产资料]] 的现实紧迫性，为 Agent 提供了一种低成本、高确定性的操作层。
