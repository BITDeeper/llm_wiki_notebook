# 循环工程

**循环工程**（Loop Engineering）是由谷歌云AI总监 [[addy-osmani|Addy Osmani]] 系统提出的一种AI协作新范式。其核心理念是：不再由人工向AI发送单次提示词，而是设计一套包含自动化任务、子智能体等要素的系统，让AI在闭环中自我驱动、迭代直至完成目标。

## 与提示词工程的区别

| 维度 | 提示词工程 | 循环工程 |
|------|-----------|---------|
| 交互模式 | 人机一问一答 | 系统自动驱动 |
| 人工角色 | 每步下达指令 | 一次性设计系统 |
| 知识传递 | 每次会话重新解释 | 通过技能模块持久化 |
| 验证机制 | 人工逐项检查 | 子智能体自动验证 |

## 五大核心要素

一个完整的工作闭环需要以下组件（目前 [[claude-code|Claude Code]] 和 [[codex|Codex]] 已原生具备全部要素）：

### 1. 自动化机制
按预定计划自动运行，自主进行任务发现与分拣。在 Codex 中通过「自动化」标签页创建定时任务；在 Claude Code 中通过 `/loop`（按节奏重复）和 `/goal`（持续运行直到满足条件）命令实现。

### 2. 工作树隔离
基于 Git Worktree 的多工作树机制，确保并行工作的智能体互不干扰。一个智能体的修改不会影响另一个智能体的检出内容。

### 3. 技能模块
包含 `SKILL.md` 文件的文件夹，用于记录项目知识（约定规范、构建步骤、经验教训），避免智能体在每次会话中从零开始重新推导整个项目。

### 4. 插件与连接器
基于 MCP 标准构建的连接器，让智能体能够读取 Issue 追踪系统、查询数据库、调用预发布环境API、在 Slack 发送消息等，使循环能在真实环境中采取行动。

### 5. 子智能体
将「执行者」与「检查者」分离的协作模式。负责写代码的模型在评估自己的工作时往往过于宽容，而另一个拥有不同指令的智能体则能发现自我合理化忽略的问题。

### 第六要素：记忆存储
独立于单次对话之外的持久化载体（如 Markdown 文件或 Linear 看板），记录已完成工作及后续计划。模型在两次运行之间会遗忘所有信息，因此记忆必须存储在磁盘上。

## 三大风险

循环工程并未使工作变简单，而是转移了杠杆点，带来三大核心风险：

1. **验证责任仍在人类**：无人值守运行的循环也可能在无人监督的情况下犯错。「已完成」只是一种声明，而非确凿的证明。
2. **[[理解债务]]加速积累**：循环交付非人工编写代码的速度越快，现有代码与开发者实际掌握情况之间的鸿沟越大。
3. **[[认知投降]]**：开发者在自动化循环中容易放弃独立思考，全盘接受AI输出结果。

## 核心洞察

> 「循环本身无法区分加速理解和逃避理解，但你能。」

> 「并非工作本身变简单了，而是关键的杠杆点发生了转移。」

循环工程要求工程师怀着「立志深耕工程领域」的心态去构建，而不仅仅是做一个按下启动键的人。
