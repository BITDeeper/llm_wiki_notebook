# 智能体分析栈

**智能体分析栈（Agentic Analytics Stack）** 是 [[anthropic|Anthropic]] 内部搭建的四层架构，用于系统性解决 AI 数据分析中的概念歧义、数据过时和检索失败问题。该架构将 Claude 的数据分析准确率从 21% 提升至 95% 以上。

## 核心主张

让 AI 准确完成数据分析，瓶颈不在写 SQL（模型能力已足够），而在写 SQL 之前的**结构**——即上下文组织、知识固化与持续验证。Anthropic 的原话是："差的不是更强的模型，是这套结构。"

## 四层架构

### 第一层：数据基础层（Data Foundations）
数据仓库本身，包括数据模型、转换、测试、表及描述它们的元数据。核心动作是把同一个概念收敛到**唯一一张权威表**，专治"概念-实体歧义"。Anthropic 强调，维度建模等传统数据工程手艺在 AI 时代同样关键。

### 第二层：事实来源（Sources of Truth）
模型查数时参照的权威参考体系，按可信度从高到低排序：
1. **语义层** — 最高可信度
2. **血缘与转换图** — 数据流转关系
3. **查询语料** — 历史查询记录
4. **业务上下文** — 最低可信度

作用是将用户嘴里模糊的问法，翻译成系统里唯一正确、有人维护的数据口径。前两层合起来专门解决"概念对不上"的痛点。

### 第三层：技能（Skills）
将资深分析师的查询流程固化成可复用模块，主治"检索失败"。这是准确率从 21% 跃迁至 95%+ 的**最大贡献因素**。

Skills 是**程序性知识**（告诉模型"怎么查"），与事实来源的**声明式知识**（告诉模型"是什么意思"）形成互补。形态上，一个 Skill 就是一个装着 SKILL.md、脚本和资源的文件夹，Claude 按需读取。

### 第四层：验证（Validation）
离线评测、消融实验、在线验证，再加上维护流程。查出三类错误中还有哪一类在漏，也是对抗"数据过时"的主要方式。包括 [[对抗式审查]] 机制。

## 关键实验结果

| 实验 | 结果 |
|------|------|
| 无 Skills vs 有 Skills | 准确率从 ≤21% 跃升至 95%+ |
| 喂入数千条历史 SQL 检索 | 准确率提升不到 1 个百分点 |
| 80% 错误答案的正确信息 | 已存在于模型刚读过的语料中 |
| 自动生成指标定义 | 重新引入歧义，评测负分 |
| 对抗式审查 | +6% 准确率，但 token +32%、延迟 +72% |

## 与其他架构的关联

- 与商汤 [[办公技能框架]] 的理念高度一致：将流程知识从模型推理能力中剥离，固化为可复用模块。
- 与 [[模型-技能分离架构]] 形成跨行业验证：声明式知识（事实来源）与程序性知识（Skills）的区分框架。
- 与 [[vlm质检闭环]] 的验证思路一致：通过嵌入评审环节保障输出质量。
- 与 [[场景白盒化推理]] 理念相通：将 AI 过程从黑盒转为可干预、可验证。
