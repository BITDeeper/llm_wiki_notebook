# Token计费黑箱

Token计费黑箱是指 AI 服务提供商在计费过程中缺乏透明度、审计能力和细粒度监控的现象。这使得用户难以准确理解和控制其使用成本。

## 现状对比

与成熟的开发者工具（如 AWS、Stripe、Vercel）相比，AI 编程工具在计费透明度上存在巨大差距：

| 特性 | AWS / Stripe / Vercel | Claude Code (AI工具) |
| :--- | :--- | :--- |
| **计费粒度** | 按秒/按交易，明细清晰 | 按 Token，无单次请求明细 |
| **实时监控** | 实时仪表盘、指标 | 仅有额度进度条 |
| **审计能力** | 完整日志、可审计 | 无法验证缓存状态 |
| **成本预警** | 自动警报、支出限额 | 无实时成本跟踪 |

## 具体问题

1.  **不可见性**：用户无法看到每次请求的具体 Token 用量明细，无法确认缓存是否命中，也无法检查定价层级是否正确应用。
2.  **策略不透明**：服务商可能在后台静默更改影响成本的策略（如 [[prompt-caching]] 的 TTL），导致用户在不知情中面临账单爆炸。
3.  **缺乏标准**：目前没有开源的 Token 用量报告标准，也没有第三方的成本审计工具。

## 后果

这种信息不对称使得使用 AI 工具变成了一种“信任盲跳”。在正常情况下，这种不透明有利于服务提供商；但一旦出现计费异常或策略变更，就会给用户带来毁灭性的经济打击和信任危机。
