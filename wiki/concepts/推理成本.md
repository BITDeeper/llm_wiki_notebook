# 推理成本

推理成本是指运行 AI 模型生成输出（Token）所产生的费用，通常以"每百万 Token 的价格"作为衡量单位。它是 LLM 上线后持续产生的运营开销，涵盖显存、带宽、延迟、能耗和单 Token 成本。当 LLM 应用从演示走向生产系统后，成本压力从训练阶段的一次性投入转向长期运行的推理开销。推理成本是决定 AI 应用（特别是 [[Agent]]）能否商业化盈利的关键因素。

## 成本构成

模型每生成一个 Token，都要把权重、激活值和 [[kv-cache]] 放进存储、读取和计算链路：

- **显存**：权重、激活值、KV Cache 的存储占用
- **带宽**：数据在存储与计算单元之间的搬运
- **延迟**：单次推理的响应时间
- **能耗**：持续运行产生的电力消耗
- **单 Token 成本**：综合以上因素的单位输出成本

## 影响因素

推理成本受多种因素影响，主要包括：

1. **算力利用率 (MFU)**：在推理阶段，由于自回归解码特性，硬件往往处于"等待数据"状态，导致 MFU 极低（仅 5%-10%），这是成本高企的结构性根源。
2. **存储墙**：随着上下文长度增加，KV Cache 呈指数级增长，导致显存占用和访存功耗激增。
3. **网络通信**：在分布式推理中，跨节点通信延迟（如 RoCE、InfiniBand）会占据大量时间，增加系统开销。

### 应用场景驱动的成本上升

模型被接入客服、办公、代码生成、数据分析和 Agent 工作流后，以下因素持续推高成本：

- 调用量和并发请求上升
- 上下文长度增加
- 多步任务和工具调用次数增长

## 行业基准

- **主流价格**：Claude、Grok 等模型价格普遍在 10-15 美元/百万 Token。
- **突破性进展**：[[浪潮信息]] 的 [[元脑HC1000]] 服务器将成本降至 **1 元/百万 Token**。
- **规模化挑战**：尽管单价下降，但由于 [[杰文斯悖论]] 的存在，企业面临的总成本仍因消耗量的指数级增长而飙升。

## 优化策略

面对推理成本，部署团队需要从多个维度考量：

- **参数规模**：使用较小的语言模型（减少计算量）
- **文件压缩**：降低磁盘和传输环节的体积
- **[[低比特模型]]**：缩减数据位宽，降低运行时存储与搬运成本
- **架构重构**：从通用训练架构转向推理专用架构，支持 [[P/D分离]] 和 [[A/F分离]]
- **硬件优化**：开发专用 AI 芯片和直达通信架构（如 [[DirectCom架构]]），减少数据搬运和协议转换开销
- **算法硬件化**：通过软硬件深度协同优化，提升单位算力的产出价值

## 关联概念

- [[ai-subscription-crisis]]：推理成本是订阅制危机的底层驱动因素
- [[scaling-law]]：行业从"堆算力"转向寻找低成本方案，是对 Scaling Law 线性扩展假设的工程补充
- [[产业深水区]]：推理成本成为核心问题，标志着 LLM 从技术验证进入生产系统阶段
