# 内容延迟

**内容延迟（Content Latency）** 是指在推理型大模型的流式交互中，用户何时能看到真正与任务相关且有依据的内容，以及两次有用更新之间的间隔时长。这一概念区别于系统层面的 TTFT（首 Token 延迟），是衡量推理过程用户体验的核心指标。

## 与 TTFT 的区别

| 维度 | TTFT（首 Token 延迟） | 内容延迟 |
|------|----------------------|---------|
| 层面 | 系统性能指标 | 用户体验指标 |
| 关注点 | 第一个 Token 何时出现 | 第一个**有用且有依据**的内容何时出现 |
| 优化方向 | 推理加速、KV Cache 优化 | [[披露策略]]、[[并列式交错推理]] |
| 局限 | 快速输出无意义 Token 不改善体验 | 需要模型学会判断"何时有依据可披露" |

## 核心评测指标

论文中使用了以下 Token 级代理指标来衡量内容延迟：

- **AIRW（Average Inter-Response Wait，平均响应间等待）**：两次 speak（披露）更新之间平均隔了多少 think（思考）Token。越低表示两次用户可见更新之间的平均间隔越短。
- **ARI（Average Response Interval）**：衡量首次披露前的等待。
- **ABO（Average Between Outputs）**：衡量两次披露之间的间隔。

## 优化意义

内容延迟概念的提出，将推理型大模型的优化目标从"更快输出"转向"更有意义地输出"。这与 [[沉默税]] 的分析一脉相承：用户的不满不在于等待本身，而在于等待过程中看不到可靠进展。

## 注意事项

论文承认这些指标是 Token 级代理指标，并不等同于真实系统的时钟延迟。真实产品环境还受到推理框架、批处理、网络延迟、前端刷新等因素影响。
