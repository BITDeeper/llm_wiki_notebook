# 供应链投毒

供应链投毒（Supply Chain Poisoning）是指攻击者通过攻破上游软件维护者账户、篡改构建流程或劫持网络分发渠道，在合法软件更新或依赖包中植入恶意代码，从而感染所有下游用户的攻击方式。

## 核心攻击特征

- **隐蔽性强**：利用合法的数字签名和官方分发渠道，用户难以察觉。
- **影响面广**：通过 [[传递依赖]] 关系，一个核心包的污染可能导致成千上万个项目受影响。
- **信任滥用**：利用开发者对开源社区、官方仓库以及本地配置文件的默认信任。

## 传统软件供应链攻击

在传统软件开发中，供应链投毒通常指攻击者攻破流行的开源库、包管理器或构建工具，在其中植入后门。攻击者利用对上游依赖的信任，将恶意代码分发给所有下游用户。

## AI Agent 时代的新特征

随着 [[claude-code]] 等 AI Agent 工具的普及，供应链投毒出现了新的攻击向量：

1. **配置文件武器化**：
   - AI Agent 为了实现自动化，倾向于信任当前工作目录下的配置文件（如 JSON）。
   - 攻击者无需二进制文件，仅需修改文本配置即可实现攻击。
   - **[[cve-2025-59536]]** 是典型案例，恶意 JSON 配置即可窃取密钥和控制摄像头。

2. **信任边界模糊**：
   - 用户习惯于警惕 `.exe` 或脚本，但对项目中的配置文件毫无防备。
   - AI 工具的"便利性"（自动读取环境配置）直接转化为安全漏洞。

3. **隐蔽性增强**：
   - 攻击代码可能隐藏在庞大的依赖库或自动生成的配置中。
   - 执行过程无弹窗、无日志，用户毫无察觉。

## 典型案例分析

### LiteLLM 事件 (2026)
2026 年 3 月的 [[LiteLLM]] 事件是典型的供应链投毒案例：
1. **入口突破**：攻击者获取了 PyPI 上传权限。
2. **载荷植入**：在 `.pth` 文件中植入恶意代码，利用 Python 启动机制执行。
3. **攻击目标**：窃取云凭证、SSH 密钥，并试图控制 Kubernetes 集群。
4. **意外暴露**：因代码 Bug 导致 [[Fork Bomb]]，使机器崩溃而非静默被控。

### Claude-Code 漏洞 (CVE-2025-59536)
攻击者利用 AI 工具对本地配置文件的信任，通过构造恶意 JSON 文件实现远程代码执行和数据窃取，展示了配置文件作为攻击面的巨大风险。

## 防御策略

- **最小化依赖**：遵循 [[反依赖宣言]]，减少非必要的外部库引用。
- **锁定版本**：使用 `requirements.txt` 或锁文件固定依赖版本，避免自动拉取受污染更新。
- **最小权限原则**：限制 AI 工具和构建脚本的系统权限。
- **沙箱隔离**：在隔离环境或容器中运行不可信的代码或配置。
- **SBOM（软件物料清单）**：建立透明的依赖清单，快速溯源漏洞组件。
- **源码审计**：对关键工具和依赖库的源码进行安全审查。
- **及时更新**：关注官方安全公告，及时修补已知漏洞。
