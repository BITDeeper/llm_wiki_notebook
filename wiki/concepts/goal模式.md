# /goal 模式

/goal 模式是 AI 编程工具中的目标锁定功能，开发者设定完成条件后，Agent 自主运行直到满足条件。代表 AI 编程从"生成代码"向 [[闭环交付]] 的范式转移。

## 背景

到 2026 年初，AI Agent 越来越聪明，写代码越来越快，但"从头到尾把一件事干完"始终没有一家能做到。Agent 常常跑了几个回合就停下来问"接下来需要我做什么？"，任务半途而废。

[[ralph-loop]] 的出现直接催化了 /goal 模式的诞生，11 天内三大实验室各自推出了实现方案。

## 三种实现路径

### Codex（OpenAI）— "不忘事"
- 持久化工作流对象，存在本地 app-server 状态层
- 关闭终端、重启系统后目标不丢失
- 结构化 `update_goal` 工具汇报进度
- token 预算耗尽时触发"软着陆"而非硬停
- 有人连续运行 14 小时，暂停 5 小时后续跑完成设备驱动项目
- 风格：工程化、干净、克制

### Hermes Agent（Nous Research）— "不烂尾"
- [[多智能体看板系统]]：任务拆分为子任务，分配给不同 Agent worker
- 每个 worker 是独立 OS 进程，有独立身份、模型配置和工作目录
- [[五层防烂尾机制]]：心跳检测、僵尸回收、退出拦截、幻觉拦截、重试预算
- 看板和 /goal 互补：/goal 管单 Agent 目标锁定，看板管多 Agent 任务调度
- 风格：野心最大，从单 Agent 升级到团队协作

### Claude Code（Anthropic）— "不自欺"
- Session 级 Stop Hook，设定完成条件后 Claude 持续工作
- [[独立裁判模型]]（[[haiku|Haiku]]）验收任务完成情况
- 裁判不调用工具，仅基于对话内容判断
- 完成条件最长支持 4000 字符，可加约束（如"不修改其他测试文件""20 轮内完成"）
- 风格：最巧妙，解决"自我评估"的根本缺陷

## 战略意义

/goal 模式争的是 [[工作流入口]]——谁的 Agent 先让开发者养成"设完目标就走开"的习惯，谁就锁死了工作流护城河。习惯一旦形成，迁移成本是指数级的。
