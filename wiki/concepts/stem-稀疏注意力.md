# Stem 稀疏注意力算法

Stem（意为"树干"）是由[[腾讯混元]] AI Infra 团队提出的块级[[稀疏注意力]]算法，已被机器学习顶会 ICML-26 收录。该算法从"因果信息流"视角重新审视稀疏注意力，通过两大核心创新实现 25% 预算下的近无损精度。

## 核心洞察：初始 token 是信息流的"树干"

Stem 的命名来源于一个关键隐喻：在因果注意力架构中，初始位置的 token 如同一棵树的主干，支撑着所有后续信息的传递。

在因果自注意力中，位置 1 的 Value 向量出现在本层每一个位置的输出计算中，而位置 N 的 Value 仅参与最后一个位置的计算。这种不对称性在多层 Transformer 中被递归放大——一旦在某一层稀疏掉初始 token，误差将沿层扩散至所有后续 token；而稀疏掉末尾 token，影响仅局限于最后一个位置。

## 两大核心创新

### Token 位置衰减（TPD）
- **解决的问题**：给谁多一点预算？
- **机制**：线性衰减的预算分配——初始位置分配较大预算，充分保留递归依赖链上的关键 token；末尾位置预算线性衰减至最小值，对冗余信息激进剪枝
- **关键特性**：TPD 并不增加总计算量，而是在相同预算下重新分配资源，将计算集中在信息流的关键节点上

### 输出感知度量（OAM）
- **解决的问题**：在预算内选哪些 token？
- **机制**：结合注意力分数（路由概率）与 Value 向量幅值（信号幅值）评估 token 的真实信息贡献，而非仅依赖注意力分数
- **实现技巧**：通过对数变换将"乘法"转为"加法"，排序结果不变，可直接套用标准 Top-K 算子，几乎零开销

## 性能数据

| 指标 | 数值 |
|------|------|
| 算力预算 | 25%（即 75% 稀疏度） |
| 128K 上下文首字延迟降低 | 3.6 倍 |
| 精度 | 逼近稠密注意力 |
| 跳块额外开销 | < 2.5% |
| 相比 MIT-BSA 加速 | ~3.1 倍 |

## 工业级验证

Stem 已在[[腾讯混元]] Hy3 preview（W8A8-FP8 [[量化]]模型）的 vLLM 推理框架中完成端到端验证，证明其在量化后的工业级模型上同样有效。配套的 [[hpc-stem-hpc-bsa算子|HPC 算子]]将理论加速比转化为真实硬件性能。
