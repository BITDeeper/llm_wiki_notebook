# 上下文衰减

**上下文衰减**（Context Rot），又称"上下文漂移"，是指大语言模型在处理超长对话或文档时，随着输入 Token 数量的增加，模型性能（如信息检索准确性、推理能力、召回率）出现逐渐下降的现象。Anthropic 官方文档已明确确认这一现象的存在。

## 定义与表现

当对话历史或上下文窗口过长时，模型往往会"遗忘"早期的关键信息，或者在处理位于上下文中后部的信息时表现出注意力涣散。具体表现为：

- 回答准确性下降
- 信息召回率降低
- 出现与上下文不一致的输出
- 可能产生非预期的收尾性行为
- 长任务中出现逻辑断裂或答非所问

## 技术挑战

上下文衰减是限制长上下文模型（如 100k 或 1M Token 窗口）实际应用效果的主要瓶颈。即使模型支持更大的输入窗口，如果无法在长窗口中保持稳定的性能，其实际可用价值仍然有限。这一基础性挑战直接影响：

- 长对话场景下的用户体验
- 多轮复杂任务的可靠性
- 模型行为的可预测性

## Claude Opus 4.6 的突破

[[claude-opus-4.6]] 在缓解上下文衰减方面取得了显著进展。根据 MRCR v2 的"大海捞针"基准测试（8-needle 1M 变体）：

- **Opus 4.6 得分**: 76%
- **Sonnet 4.5 得分**: 18.5%

这表明 Opus 4.6 在保持峰值性能的同时，实现了实际可用上下文数量的质的飞跃，使其能够更可靠地在数十万 Token 中捕捉深埋细节并进行推理。

## 解决方案方向

缓解上下文衰减的技术方向通常包括：

- 改进注意力机制（如线性注意力、稀疏注意力）
- 上下文压缩与摘要
- 动态上下文窗口管理
- **服务端压缩（Server-side Compaction）**：Anthropic 官方推荐的机制，通过压缩历史对话内容，为新的交互腾出 Token 空间

## 与 Claude 催睡的关联

Mind Simulation Lab 联合创始人 Leo Derikiants 推测，Claude 在长会话接近上下文窗口上限时，会自发引入"收尾语"（如"晚安""去休息吧"），本质上是模型在为结束对话铺路——一种应对上下文衰减的涌现策略。这一假说尚未获得 Anthropic 官方确认。
