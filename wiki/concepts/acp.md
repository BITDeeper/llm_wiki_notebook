# ACP (Agent Client Protocol)

ACP 全称 Agent Client Protocol（亦称 Agent Communication Protocol），是 [[openclaw]] 中用于定义 Agent 与客户端交互、工具调用及外部指令处理的核心协议。其核心目的是解决智能体在执行指令时“盲目信任”带来的安全隐患，确保操作的合规性与可追溯性。

## 核心机制：溯源与身份验证

在 [[openclaw]] 3.8 版本中，ACP 引入了“身份身份证”机制，为每条发送给智能体的指令附加溯源信息。该身份信息通常包含：

- **发送者**：谁发出了指令。
- **入口**：指令从哪个渠道或接口进入。
- **权限**：该指令被允许执行的操作范围。

这一机制将系统策略从“见谁都放进来”的默认信任模式，转变为“先验码再放行”的验证模式，显著提升了系统的安全性。

## 安全演变：从名称到语义

在 [[openclaw]] 的发展初期，ACP 的危险工具审批机制存在严重漏洞。

### 早期漏洞
最初的逻辑是基于工具名称（如 `read_file`）进行白名单放行。这导致攻击者可以通过伪装工具名称来绕过安全检查，执行危险操作（如间接代码执行）。

### 语义类别审批
在 v2026.3.31-beta.1 更新中，ACP 的审批机制被完全重写，转变为基于 [[yu-yi-lei-bie-shen-pi]] 的模式。新机制不再单纯依赖名称，而是分析工具的语义类别：
- **自动批准**：仅限于窄范围的只读操作（如搜索、读取）。
- **显式确认**：对于具备间接执行能力的工具和控制平面工具，必须由用户显式确认。

这一改动封堵了 OpenClaw 最大的权限漏洞。

## 应用价值

1.  **权限管控**：智能体不再对所有指令一视同仁，而是根据 ACP 信息判断是否执行。例如，在多人协作场景下，可以阻止非管理员执行敏感操作。
2.  **问题溯源**：当发生误操作或安全事故时，可以通过日志中的 ACP 信息快速定位责任方（“谁改了谁触发的，一眼看清楚”）。
3.  **安全隔离**：结合语义审批，实现了从接口验证到操作级别的全链路安全管控。

## 行业意义

ACP 的出现标志着 [[任务执行范式]] 的成熟。随着 AI 智能体越来越多地介入实际生产环境，简单的 API 调用已无法满足企业级的安全需求。ACP 类似于传统软件中的身份认证与访问管理（IAM）体系，是 AI 智能体走向工程化、规范化应用的关键基础设施。
