# 基础设施级部署

[[基础设施级部署]] 指软件系统需要具备 Linux 运维、API 认证、密钥管理、网络安全等专业知识才能安全部署和运行，而非简单的“开箱即用”或“一键安装”。

## 核心特征
- **运维门槛高**：需要用户具备配置防火墙、管理 SSH 密钥、配置反向代理等能力。
- **安全责任自负**：默认配置往往不安全，用户需自行加固（如使用 [[Tailscale]]、[[fail2ban]]）。
- **成本复杂**：除了基础托管费用，还涉及 API 调用、流量、存储等隐性成本。

## [[ClawdBot]] 的误区
[[ClawdBot]] 被营销为“人人可用”的效率工具，但实际上属于 [[基础设施级部署]]：
- **技术要求**：需要理解 Token、API Key、环境变量及 Linux 权限。
- **风险后果**：配置错误可能导致端口裸奔、数据泄露或被 [[提示词注入]] 攻击。
- **对比 [[Claude Code]]**：两者都是技术惊艳但门槛极高的工具，不适合非技术背景用户。

## 适用人群
此类工具主要适合以下人群：
- 开发者和运维人员。
- 具备系统安全知识的高级用户。
- 愿意投入时间学习底层原理的早期采用者。
