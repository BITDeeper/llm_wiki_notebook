# 技术惯性认知误区

[[技术惯性认知误区]] 指的是用旧技术栈（如 K8s、Docker）的底层假设去生搬硬套新技术（Agent）的思维定势。

## 典型表现
很多云厂商和 IT 团队仅仅把 Agent 看作是下一个微服务或大数据升级，直接拿过去做微服务的 K8s 技术方案去硬接 AI Agent。

## 底层假设的冲突

| 传统架构 (K8s/Docker) | Agent 需求 |
| :--- | :--- |
| **无状态** (Stateless) | **有状态** (Stateful) |
| **同质化** (Homogeneous) | **异质** (Heterogeneous) |
| **随时销毁** (Ephemeral) | **长时运行** (Long-running) |

## 后果
拿着解决静态、无状态问题的旧锤子，去敲击自主、不确定性的 Agent 钉子，会导致系统架构无法支撑业务需求。例如，在 [[MiniMax]] 的 [[Agentic RL]] 训练中，传统 K8s 架构在几万并发沙盒下就会崩溃。

## 破解之道
必须认识到 Agent 时代是一次真正的范式转移，需要从底层重构基础设施（如 [[Agent Runtime]]），而不是修修补补。
