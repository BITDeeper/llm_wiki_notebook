# Token 级长度控制

**Token 级长度控制**是指在大语言模型（LLM）生成文本的过程中，将生成长度的约束粒度从传统的“序列级”细化到每一个“token”生成步的技术范式。

## 背景与局限
传统的生成长度控制方法存在显著局限：
-   **Prompt 指令**：本质上是一种“软约束”，依赖模型的理解和配合，无法保证严格遵守。
-   **序列级惩罚**：在训练时施加，但在推理过程中模型对“还剩多少长度”缺乏动态感知。
-   **预解码预测器**：仅在生成开始前进行一次性预测，无法根据生成过程中的内容变化进行动态调整。

这些方法的共同问题在于：**解码本身是逐 token 发生的，但控制信号却停留在序列层面**，导致控制精度不足。

## 核心原理
Token 级长度控制通过引入**价值函数**来解决上述问题。它将“剩余生成长度”建模为一个状态值，在每一个解码步 $t$，模型都根据当前上下文预测 $V(s_t)$（即剩余长度的期望值）。

基于这个预测，系统可以：
-   **筛选候选 Token**：选择那些能使预测长度最接近目标的 token。
-   **动态调整策略**：根据剩余预算实时调整生成风格（如更简洁或更详细）。
-   **精确终止**：在达到目标长度的瞬间停止生成，避免溢出或不足。

## 技术优势
1.  **硬约束能力**：相比 Prompt 的“祈求”，Token 级信号是模型内部数学逻辑的一部分，约束力更强。
2.  **资源感知**：模型能感知自身的资源消耗（Token 预算），从而在生成内容时进行内在的权衡。
3.  **可解释性**：通过分析每个 token 对长度预测的贡献（TD 残差），可以洞察模型的推理路径（例如识别“顿悟时刻”）。

## 应用实例
[[lenvm]] 是目前实现 Token 级长度控制的代表性工作。实验表明，这种精细的控制能力使得较小的开源模型（如 3B）在特定任务上能够超越缺乏此能力的顶级闭源模型（如 GPT-5.4）。

## 相关概念
-   [[折扣回报]]：将原始长度映射到固定区间的数学变换，是 Token 级建模的基础。
-   [[性能-效率权衡]]：利用 Token 级控制，在有限的计算预算内最大化模型输出质量。
