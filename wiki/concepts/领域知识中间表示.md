# 领域知识中间表示

领域知识中间表示是一种 AI 工程原则，指当 Agent 进入有成熟理论的垂直领域时，应在自然语言和工具调用之间加入基于领域理论的中间层（如图结构），而非仅依赖通用规划能力。

## 核心思想

通用 LLM Agent 的规划能力在垂直领域任务中容易出错。模型可以生成推理链并调用工具，但无法保证分析流程的正确性。领域知识中间表示的思路是：将领域内长期积累的理论知识转化为模型可理解、可操作的中间结构，作为"分析骨架"指导工具调用。

## 设计模式

```
自然语言问题 → 领域理论中间表示 → 工具执行 → 最终回答
```

中间表示不是普通的思维链文本，而是基于领域概念体系的结构化表示（如图、树、规则集等），具有以下特征：
- **可验证性：** 可以检查中间表示是否符合领域规则
- **可追溯性：** 可以定位问题出在哪个环节
- **可迁移性：** 中间表示的设计可以适配不同底层模型

## 实践案例

[[spatial-agent|Spatial-Agent]] 是这一原则的典型实践：
- **领域理论：** GIScience 中的空间信息核心概念和功能角色理论
- **中间表示：** [[geoflow-graph|GeoFlow Graph]]，将自然语言地理问题转化为包含空间概念和依赖关系的图结构
- **效果验证：** 引入中间表示后，在 MapEval-API 上相对提升 96.30%，远超单纯升级模型（如从 GPT-4o-mini 到 GPT-5）带来的增量

## 通用启发

这一原则不仅适用于地理空间领域，还可推广到其他有成熟理论体系的垂直领域：
- **医疗：** 临床指南和诊断路径可作为中间表示
- **法律：** 法律推理框架和要件分析可作为中间表示
- **金融：** 风险评估模型和合规检查流程可作为中间表示

## 与其他概念的关系

- 与 [[agentic-engineering]] 形成互补：领域知识中间表示是智能体工程在垂直领域的具体方法论
- 与纯端到端的通用 Agent 路线形成对比：强调"先搭分析骨架，再执行工具"而非"边想边调"
