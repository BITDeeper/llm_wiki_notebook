# Computer-Use Agent (CUA)

Computer-Use Agent（CUA）是指通过浏览器操作图形用户界面（GUI）完成任务的 AI 智能体。与编程型 Agent（如 [[claude-code|Claude Code]]、[[codex|Codex]]）不同，CUA 需要像人类一样"看"屏幕、"点"按钮、"填"表单，模拟人类的点击、输入、导航等操作，在真实的软件界面中完成工作流程。

## 与编程型 Agent 的区别

| 维度 | CUA | 编程型 Agent |
|------|-----|-------------|
| 操作方式 | 通过 GUI 点击、输入 | 通过代码生成和执行 |
| 反馈机制 | 需要视觉理解页面状态 | 编译器/测试提供即时反馈 |
| 错误恢复 | 困难（状态隐含在 UI 中） | 相对容易（版本控制、回滚） |
| 适用场景 | 通用办公、跨系统操作 | 软件开发、数据处理 |

## 当前能力边界

[[saas-bench|SaaS-Bench]] 的系统性评测揭示了 CUA 在真实办公场景中的严峻挑战：

- **最强模型端到端完全通过率仅 3.8%**：[[claude-opus-4-7|Claude Opus 4.7]] 在 106 个真实任务中仅完整通过 4 个
- **部分模型完全通过率为零**：Kimi K2.5、Gemini 3.1 Pro 全军覆没
- **执行极不稳定**：同一任务多次运行分数差异巨大
- **跨应用能力急剧下降**：跨应用数从 1 增至 4 时，平均分从 53% 降至 20%

## 系统性缺陷

[[saas-bench|SaaS-Bench]] 揭示了 CUA 的四种结构性失败模式，详见 [[反思闭环缺失]] 和 [[长程任务执行]]：

1. **通过率衰减（[[长程任务执行衰减]]）**：任务越长，做对的越少，呈不可逆下降
2. **错误级联（[[错误级联传播]]）**：一个微小决策错误可导致后续全部执行偏离
3. **验证缺失（[[意图-状态断层]]）**：Agent 执行操作后不验证结果，意图层面认为成功但状态层面实际失败
4. **路径依赖（[[路径依赖不稳定性]]）**：初始状态完全相同的情况下，微小决策差异导致执行轨迹完全分叉

## 底层缺陷

SaaS-Bench 指出当前 CUA 的底层问题不是模型不够大，而是范式层面的局限：

1. 缺少对持久状态的有效推理能力
2. 缺少操作后的闭环验证机制
3. 缺少从错误中恢复的能力
4. 在长程任务中缺少对全局状态的持续感知

## 未来方向

参见 [[面向agent的软件重设计]]：一个正在形成的共识是，当前 SaaS 是为人类设计的，当 Agent 成为主要用户时，软件界面需要从服务人类眼睛和手指转向服务 Agent 操作。这不是靠模型变大就能解决的问题，而是当前范式的天花板——未来不是让 Agent 学会操作人类的软件，而是软件本身要为 Agent 重做一遍。
