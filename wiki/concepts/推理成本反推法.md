# 推理成本反推法

## 概述
推理成本反推法是一种估算闭源大语言模型参数规模的常用技术手段。其核心逻辑是：模型的推理成本（API 价格）与吞吐量（Token 处理速度）同其激活参数量呈近似线性关系。

## 方法论
1.  **数据收集**：收集模型在云平台（如 Google Vertex, Amazon Bedrock）上的 Token 吞吐数据。
2.  **基准校准**：使用已知参数规模的开源模型（如 Mixtral, Grok）作为基准，计算有效内存带宽。
3.  **反推计算**：根据目标模型的吞吐量表现，结合校准系数，反推其激活参数量。

## 应用实例
技术博主 [[unexcitedneurons]] 使用此方法分析了 [[Claude Opus]] 4.6：
- 通过 3 个开源 MoE 模型校准，估算出平台有效内存带宽约为 4.0–4.5TB/s。
- 推算出 Opus 4.6 的激活参数量约为 93B-154B。
- 这一结论与 API 定价（降至 4.1 版本的 1/3）相互印证，否定了网传的“10T+ 激活参数”说法。

## 局限性
该方法主要估算的是**激活参数量**，对于采用 MoE 架构的模型，其**总参数量**可能远高于反推结果。
