# 推理并发调度经济学

**定义**：大模型推理服务中，批处理大小（并发量）与硬件经济效率、用户延迟之间的权衡关系，以及由此衍生的 API 定价逻辑和存储分级策略。

## 核心矛盾

| 维度 | 低并发 | 高并发 |
|------|--------|--------|
| 用户延迟 | 低（响应快） | 高（等待长） |
| 硬件利用率 | 极低（经济效率差数百至上千倍） | 高（吞吐量最大化） |
| 瓶颈 | [[显存带宽瓶颈]] | 计算能力 |
| 典型场景 | "快速模式" | 标准 API 调用 |

## 最优并发量

[[reiner-pope]] 推算的理想平衡点约为 **300 × 模型稀疏比例**：
- 低于此值：系统受限于访存，硬件利用率不足
- 高于此值：系统受限于计算，用户延迟增加

## 快速模式的经济学

Claude、Codex、Cursor 等平台提供"快速模式"：
- 用户支付约 **6 倍费用**，换取约 **2.5 倍**的 Token 流式生成速度
- 本质：厂商通过降低并发量牺牲硬件经济效率来换取低延迟
- 流式速度（Streaming Speed）：每个并发用户的解码 Token 生成率，决定文本在用户屏幕上显现的快慢

## 存储分级与排空时间

维持长上下文经济性的关键策略：将静置上下文从高成本介质疏散至低成本介质。

| 存储介质 | 排空时间 | 适用场景 |
|----------|----------|----------|
| HBM（高带宽内存） | ~20ms | 活跃推理 |
| DDR（主机内存） | ~1-10s | 短期静置上下文 |
| Flash（闪存） | ~1min | 长期静置上下文 |

**排空时间** = 存储介质总容量 ÷ 读写带宽，应与业务会话的读取间隔严格匹配。

## 商业现象解释

- **缓存命中费率下降**：长时间静置的上下文被疏散至低成本介质，厂商因此能提供更低的缓存命中价格
- **超长上下文涨价**：如 Gemini 3.1 超 20 万 Token 涨价 50%，因为 KV Cache 读取时间超越计算权重时间，系统再次陷入访存瓶颈
- **输入/输出定价差异**：输入阶段支持高并行矩阵计算（利用率高），输出阶段逐字生成依赖显存带宽（利用率低）

## 与训练侧的对比

本概念关注**推理侧**的并发调度与物理约束，与 [[批次不变性]]（关注**训练侧**的确定性输出）形成互补：前者追求经济效率与延迟的平衡，后者追求不同批次组织方式下的数值一致性。
