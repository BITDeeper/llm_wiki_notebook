# 上下文压缩

**上下文压缩** 是一种在对话接近 LLM 上下文窗口上限时，自动将旧对话总结为精简摘要并持久化，同时保留最近消息原样的技术。该机制旨在变相增加有效对话长度，是 [[Clawdbot]] 实现超长对话连续性的关键机制，同时也是 [[Claude Agent SDK]] 等智能体框架内置的核心能力，并已在 [[Claude Sonnet 4.6]] 的开发者平台开启测试。

## 工作原理

当对话历史接近模型的 Token 上限时，系统会自动对早期的对话内容进行摘要和压缩，释放出空间以容纳新的交互，同时保留关键信息。

### 触发条件
- **自动触发**：当上下文占用接近模型窗口上限（例如 200K Token 中的 180K）时。
- **手动触发**：通过 `/compact` 命令手动执行。

### 工作流程
1. **总结**：将早期的对话轮次（例如第 1-140 轮）总结成一个精简的摘要条目。
2. **保留**：保持最近的对话轮次（例如第 141-150 轮）原封不动。
3. **持久化**：将生成的摘要保存到硬盘上的会话 JSONL 实录文件中。

### 压缩示例
**压缩前**：包含 150 轮详细对话，占用 180,000 Tokens。
**压缩后**：
- **摘要**：“构建了带/users, /auth端点的REST API。实现了JWT认证...当前重点: 准备生产环境部署。”
- **近期**：保留最近 10 轮原始对话。
- **占用**：降至 45,000 Tokens。

## 优势

- **延长会话寿命**：允许单次会话处理更长的任务，减少因上下文溢出导致的会话中断。
- **节省成本**：减少每次请求需要传输的 Token 数量，降低 API 调用开销。
- **解决记忆与成本的平衡**：允许用户进行超长对话而无需手动清理历史。
- **保持连贯性**：确保模型在长对话中仍能记住之前的上下文和指令。
- **变相扩容**：配合原生上下文窗口（如 Claude 的 100 万 token），进一步提升处理长任务（如代码库审查、长篇合同分析）的实用性。

## 局限性与风险

### 有损压缩
基于 LLM 的压缩本质上是**有损**的，可能导致重要信息丢失。Anthropic 的实践表明，仅靠上下文压缩不足以支撑跨越数小时的复杂任务，压缩后的信息可能会丢失关键细节。

### 会话隔离
一旦会话结束，压缩状态通常无法被下一轮会话直接继承。因此，上下文压缩通常被视为一种“短期记忆”优化手段。

### 缓解措施
为了缓解数据丢失风险，必须将上下文压缩与“长期记忆”方案结合使用：
- **[[记忆刷新]]**：Clawdbot 引入的机制，在压缩前强制 AI 将关键信息写入持久化的 Markdown 文件，确保数据安全。
- **[[环境状态持久化]]**：结合 Git、文件日志等外部存储手段，构建稳健的长时运行智能体，确保关键状态在会话间可恢复。
