# 开源许可合规

**开源许可合规**（Open Source License Compliance）指在使用、修改或分发开源软件时，遵守其原始许可证所规定的法律义务的行为。在 AI 领域，随着模型权重的开源，合规性问题日益突出，特别是在商业变现场景中。

## 常见争议类型

1.  **未履行署名义务**：许多开源协议（如 MIT, Apache）要求在衍生产品中保留原作者的版权声明。在 [[cursor]] 事件中，Cursor 被指控未在显著位置标注其底层使用了 [[kimi-k2-5]]。
2.  **隐瞒技术来源**：即俗称的“套壳”或“洗代码”，指在开源模型基础上进行微调或封装，却对外宣称完全自研，误导投资者和用户。
3.  **收入门槛违规**：部分 AI 模型的开源协议设有商业条款，例如 Kimi K2.5 规定月收入超过 2000 万美元需显著展示来源。

## AI 时代的挑战

- **技术透明度**：由于模型权重和 API 接口可以被调试，技术来源难以完全隐藏。开发者可以通过简单的 API 调试（如查看模型 ID 或 Tokenizer）来验证技术来源。
- **价值分配**：当一家公司利用开源模型构建高估值产品（如 Cursor 估值 293 亿），而模型原作者（如 Kimi 估值 43 亿）获益有限时，会引发关于开源生态价值分配的伦理讨论。
- **法律执行**：开源协议的法律约束力在面对跨国商业巨头时往往显得脆弱，执行成本高昂。

## 相关案例

- **Cursor 套壳 Kimi 事件**：Cursor 未遵守 Kimi K2.5 的署名条款，引发社区质疑。
- **Hermes Agent 抄袭事件**：[[nous-research]] 被指控架构级抄袭 [[evolver]] 代码，涉及对开源贡献的尊重问题。
