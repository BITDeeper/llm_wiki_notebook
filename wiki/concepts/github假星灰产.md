# GitHub假星灰产

[[GitHub假星灰产]] 指通过自动化脚本、僵尸账号等手段批量购买或刷取 GitHub Star（点赞）的黑色产业链。这一现象破坏了开源社区基于 Star 数建立的信任机制，使得 Star 这一核心指标逐渐失效。

## 现象与规模
根据 [[ICSE 2026]] 顶会论文及 [[Socket Inc.]] 的研究：
- **总量**：估计 GitHub 上有约 **600 万** 颗疑似假星。
- **涉及范围**：涉及 **1.8 万** 个仓库和 **30 万** 个账号。
- **峰值**：2024年7月是假星活动峰值，当月热门仓库中 **16.66%** 涉及假星活动。
- **成本**：黑市上一颗假星的报价低至 **0.1 美元**。

## 运作模式
灰产商家通常利用以下方式进行操作：
1.  **僵尸账号农场**：批量注册低活跃账号（无头像、无简介）。
2.  **Lockstep 同步操作**：在极短时间内控制大量账号对目标仓库进行集中点赞。
3.  **定向投放**：将假星精准注入客户仓库，以骗取 Trending 榜单或提升虚假热度。

## 危害
1.  **信任机制崩塌**：Star 数曾是开发者评估项目质量的最直观指标，现在却容易被伪造，导致技术选型困难。
2.  **恶意软件温床**：约 30% 的涉事仓库被用于传播钓鱼或恶意软件。假星为恶意代码提供了低成本的信任伪装（如伪装成游戏外挂或加密货币工具）。
3.  **劣币驱逐良币**：利用假星注水的低质量项目挤占了优质项目的曝光机会。

## 理论解释
这一现象是 [[坎贝尔定律]] 和 [[古德哈特定律]] 的典型体现：当一个定量指标（Star 数）被广泛用作决策依据（如投资、招聘、选型）时，它就失去了作为指标的价值，并容易被操纵。

## 应对策略
- **平台层面**：引入 [[差异化Star]]，降低 Star 在排名中的权重，增加难伪造信号（如 Commit 频率、Contributor 分布）的考量。
- **开发者层面**：避免仅凭 Star 数做判断，应检查 Issue 回复质量、代码活跃度等。
