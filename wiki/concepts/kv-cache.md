# KV Cache

**KV Cache**（Key-Value Cache，键值缓存）是大语言模型（LLM）在自回归推理阶段用于存储注意力机制中间状态（历史 Token 的 Key 和 Value 矩阵）的内存机制。它相当于模型的"运行记忆"，用于加速计算并避免重复处理，是推理显存和带宽消耗的重要来源。

## 工作原理

在 Transformer 架构的自回归生成过程中，每生成一个新 Token 都需要对之前所有 Token 进行注意力计算。为了避免每次都从头计算所有历史 Token，系统会将每一层注意力机制产出的 Key (K) 和 Value (V) 向量缓存起来。当生成新 Token 时，模型只需计算新 Token 的 K 和 V，并与缓存中的历史 K、V 进行交互。

## 核心瓶颈：内存墙

KV Cache 是推理阶段最大的内存瓶颈之一。随着 AI Coding、Agent、Deep Research 等应用推动上下文长度从几万 Token 迈向几十万甚至百万 Token，KV Cache 已成为长上下文推理的"内存墙"，其挑战主要体现在：

*   **线性膨胀**：KV Cache 大小随上下文长度线性增长，输入越长，占用的 GPU 显存越多，推理速度越慢。
*   **显存占用**：对于长上下文（如 128k、1M 甚至 10M Token），在大型模型和高精度推理场景下，KV Cache 的显存占用往往会反超模型参数本身，可达数十到数百 GB，远超单张顶级 GPU 的显存容量。
*   **吞吐量限制**：巨大的内存需求限制了单卡能处理的并发请求数量（批量推理吞吐能力），使得显存容量和带宽，而非 GPU 的算力，成为了大模型推理的主要制约因素。
*   **部署成本**：高昂的内存需求限制了长上下文模型在低成本设备上的部署，也推高了 API 服务的成本。

## 上下文窗口竞赛的本质

2026 年初各大厂商的上下文窗口竞赛（Google Gemini 3 Pro 100 万 token、Meta Llama 4 Scout 1000 万 token），本质上是一场显存战争——上下文窗口的扩展受限于 KV Cache 的物理存储极限。这也是 [[scaling-law]] 在推理阶段显存瓶颈的直接体现。

## 在推理成本中的角色

在模型生成每个 token 时，权重、激活值和 KV Cache 都会参与推理过程。随着调用次数、上下文长度和并发请求的增加，KV Cache 的存储、搬运开销会持续累积，成为推理成本的重要组成部分。

## 压缩挑战与分配策略

KV Cache 压缩的核心难题在于：**两个输出完全相同的模型，其 KV 缓存的可压缩性可能截然不同**。标准训练过程没有激励模型选择更结构化、更易压缩的内部表示。

主流的 KV Cache 压缩与分配方案通常遵循"注意力分数高的 Token 更重要"的假设（如 SnapKV、KeyDiff）。然而，[[lu-kv|LU-KV]] 框架揭示了这种"看当前分数"策略的局限性——它忽略了不同注意力头在长期信息保留能力（[[长程边际效用]]）上的差异，导致预算错配。

已有的事后（post-hoc）压缩方案还包括注意力匹配（Attention Matching）等算法，但效果同样受限于模型内部表示的结构化程度。

## 优化技术

为了解决 KV Cache 带来的显存压力，工程界和学术界发展出了多种优化技术：

### 1. 量化

通过降低数值精度来压缩 KV Cache 的大小。例如，将 K 和 V 向量的精度从 FP16/BF16 降低到 INT8、INT4 甚至更低。[[TurboQuant]] 是其中的最新代表，它通过极坐标量化（[[PolarQuant]]）等技术将精度压至 2-bit/3-bit，在几乎不损失精度的情况下将显存占用减少数倍。在相同参数规模下，KV Cache 使用不同精度（如 BF16 vs 8-bit vs 4-bit）时，物理存储占用差异显著。

### 2. PagedAttention

由 [[vLLM]] 引入，借鉴操作系统的分页内存管理，将 KV Cache 分页存储。这不仅解决了 KV Cache 的碎片化问题，还显著提高了显存利用率。

### 3. 架构压缩

从模型架构层面进行优化。例如 [[DeepSeek V4]] 使用的 [[MLA]] (Multi-Head Latent Attention)，通过数学变换在架构层面压缩 KV 的维度。

### 4. 卸载

利用 [[FlexKV]] 等技术，将 KV Cache 从 GPU 显存卸载到 CPU 内存、SSD 甚至远程存储，以突破单卡显存的物理限制。

### 5. 共享缓存

在多轮对话或批量推理中，通过共享部分 KV Cache（如相同前缀）来减少冗余存储。

### 6. 训练时压缩（压缩感知型训练）

[[kv-cat]] 提出从训练阶段根本解决可压缩性问题，通过在训练时模拟压缩压力，使模型内化"压缩友好"的表示形式。这与 [[资源感知计算]] 的理念一致——让系统在训练时就感知推理时的资源约束，属于 [[压缩感知型训练]] 的范畴。

## 与其他概念的关系

*   **低比特技术**：[[低比特模型]] 通过缩减 KV Cache 的位宽，可以直接降低其在运行时的存储占用和显存搬运带宽，是推理降本的关键优化方向之一。
*   **长上下文性能**：与 [[context-rot]]（上下文过长导致性能下降）直接相关，KV Cache 的智能保留是缓解长上下文问题的工程解法之一。
*   **注意力加速**：与 [[dsa-稀疏注意力]] 互补，后者侧重于注意力计算的加速，而 KV Cache 优化侧重于显存分配与长程信息保留。

## 经济影响

KV Cache 的效率直接影响 AI 推理的成本。高效的压缩技术（如 [[TurboQuant]]）可以显著降低内存需求，从而缓解 [[ai-subscription-crisis]]，使长上下文应用更具商业可行性。
