# 地理空间分析工作流

地理空间分析工作流是指将自然语言地理问题拆解为包含空间对象、条件、度量和执行顺序的可验证分析步骤，而非单步 API 调用的分析范式。

## 核心问题

传统的地图 API 适合回答事实型问题（如"附近有什么餐厅"），但复杂地理空间分析问题需要多步有序操作。例如：

- "在某个区域内，哪些餐厅同时满足距离、评分、营业时间和路线约束？"
- "某个区域内某类设施的比例是多少？"

对于后者，如果先对全城数据做聚合再套空间范围，和先筛出目标区域再计算比例，结果完全不同。LLM 可能给出两种看似合理的流程，但从地理分析角度看只有一种是正确的。

## 与通用 Agent 规划的区别

通用 Agent 可以生成 thought-action-observation 链并调用工具，但**工具调用本身不出错并不能保证分析顺序正确**。对于复杂 POI 检索、空间过滤、多点路线规划和时间约束任务，组织顺序一旦出错，后续结果再完整也会偏离原问题。

## 工作流组成要素

一个完整的地理空间分析工作流需要明确：
1. **空间对象：** 问题中涉及哪些地理实体？
2. **条件：** 哪些是筛选条件（距离、评分、营业时间等）？
3. **度量目标：** 最终要计算什么指标？
4. **执行顺序：** 这些步骤应该按什么顺序组织？
