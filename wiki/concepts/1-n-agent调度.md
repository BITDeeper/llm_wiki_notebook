# 1:N Agent 调度

1:N Agent 调度是一种 AI 工作范式，指用户角色从与单个 AI "面对面对话"（1:1）转变为同时管理多个 AI Agent 任务（1:N）的"工头式调度"模式。

## 核心特征

- **角色转变**：用户从"对话者"变为"调度者"，核心工作是派活、扫表、回答必要问题、复核结果。
- **并行处理**：多个 Agent 同时在后台执行独立任务，用户通过状态一览表监控全局。
- **注意力杠杆**：突破单线程瓶颈，一个工程师可以同时推动多条并行工作线。

## 出现条件

1:N 调度并非随时可行，它依赖一个关键前提——**模型任务完成度达到独立性临界点**。当 AI Agent 能够独立完成从理解需求到交付结果的全流程（无需多轮人工干预）时，并行调度才有实际意义。在此之前，强行并行只会超出人类的注意力上限。

## 与相关概念的关系

- 是 [[任务执行范式]] 在产品层面的具体体现——从"单纯模型开发"到"智能体工程化系统"的落地。
- [[agent-view]] 是这一范式的首个产品级实现。
- 多 Agent 并行意味着 token 消耗成倍增长，强化了 [[token作为生产资料]] 的趋势，同时可能加剧 [[ai-subscription-crisis]]。

## 适应性挑战

用户初次接触 1:N 调度时可能产生"短暂的不适"——感觉不知道自己在跟谁说话。这种不适本质上是从对话模式到管理模式的心智切换，适应后反而是一种解放。
