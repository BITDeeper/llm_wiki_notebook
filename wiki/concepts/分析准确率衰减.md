# 分析准确率衰减

**分析准确率衰减** 是 [[anthropic|Anthropic]] 在内部实践中发现的现象：AI 数据分析系统的准确率会随时间自然下降，即使系统本身未被修改。

## 核心发现

Anthropic 团队观察到，离线准确率在**一个月内从约 95% 跌至约 65%**。原因是数据模型每天都在变化，而描述它的 Skill 文档未同步更新，几周后系统就开始"说错话"。

## 工程化解决方案

Anthropic 将维护当作正经工程来对待：
- **Skill 文档与数据模型同仓库**：将 Skill 文档和数据模型塞进同一个代码仓库。
- **同 PR 更新**：改模型的代码合并请求（PR），顺手把对应文档也改了。
- **效果**：约 90% 的数据模型改动现在都带着一处 Skill 更新一起提交。

## 核心洞见

> "95%不是搭出来的，是养出来的。一旦松手，几周就可能塌回去。"

这一洞见与 [[断点续跑]] 中"长链路任务需要中间产物持久化和持续维护"的思路一致，强调了 AI 系统**上线只是起点、维护才是常态**的工程现实。

## 更深层含义

分析准确率衰减现象暗示：AI 分析系统不是一次性交付的软件，而是需要持续运营的"活系统"。这对团队组织、流程设计和资源分配都有深远影响——需要建立类似 DevOps 的"AI 分析运维"能力。
