# 前缀缓存优化（Prefix-Cache Optimization）

前缀缓存优化是一种利用请求间字节级前缀匹配来复用已计算的 KV 缓存，从而避免重复计算、降低 API 调用成本的技术策略。

## 原理

大模型推理服务（如 [[DeepSeek V4]]）通常提供自动前缀缓存（prefix-cache）功能：当新请求的精确字节前缀与先前请求匹配时，服务端可直接复用已缓存的 KV 计算结果，跳过重复的注意力计算，从而降低延迟和成本。

## 在 Agent 场景中的挑战

大多数智能体循环在每次交互时会：

- 重新排序上下文消息
- 重写或修改已有内容
- 注入新的时间戳或元数据

这些操作会破坏字节前缀的一致性，导致缓存命中率大幅下降。

## 解决方案：Append-Only 架构

[[reasonix]] 提出的核心方案是将上下文划分为三个区域：

1. **固定前缀区**：系统提示和项目上下文，永不修改
2. **只追加历史区**：已确认的对话历史，只往后追加
3. **草稿区**：临时内容，归入历史前需提炼为稳定格式

通过这种架构，前缀在每个会话中仅计算一次，历史消息只追加不重写，从而将缓存命中率推至 **99.82%**。

## 成本效果

- 输入 token 成本降至原来的 1/5（约 2 折）
- 长会话缓存命中率稳定在 90%+
- 4 亿+ token 账单从 61 美元降至 12 美元

## 普适性

社区实践表明，前缀缓存优化思路具有普适性。通过微型桥接程序在 [[codex]] 中使用 DeepSeek V4 Pro，同样可实现 95%+ 的缓存命中率，但不同 harness 之间效果存在差异。
