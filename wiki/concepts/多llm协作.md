# 多LLM协作

多LLM协作是指通过组合多个各有所长的"专家模型"来完成生成任务的技术范式，而非追求单一"无所不能"的大模型。其核心直觉在于：现实中往往不存在一个在所有任务上都同样出色的模型，而是会涌现出大量各有所长的专家模型。

## 发展脉络

### Sequence-level 协作
在整段生成完成后再进行模型融合、讨论或选择。多个模型需要生成完整回答，再通过 reranking 或辩论得到最终结果。这种方式简单但计算开销大、协作粒度粗。

### Token-level 协作
将协作粒度细化到每一步生成，通过在多个模型之间进行 token 级别的选择来决定下一个 token。能够实现更灵活的专家切换，但纯选择方法存在 [[不可识别性]] 的理论瓶颈，误差容易累积。

### 补充生成式协作
以 [[fusionroute]] 为代表，路由器不仅选择专家，还输出额外的 logits 参与生成过程。既保留了 token-level 的细粒度优势，又通过 [[补充生成]] 修正专家在不擅长场景下的输出。

## 核心优势

- 更充分地利用已有模型的能力
- 避免单一模型在所有维度上都需要做到极致的训练成本
- 即插即用，新专家可快速纳入协作框架
- 多个专门化小模型的协作成为通用大模型之外的现实技术路径

## 与相关概念的关系

- 与 [[多agent协作架构]] 的区别：多 Agent 协作关注应用层的智能体协同，多 LLM 协作深入到模型底层推理过程中的 token 级协同
- 与传统 MoE 的区别：专家可以是结构各异、已训练完成的独立模型，工程灵活性更高
