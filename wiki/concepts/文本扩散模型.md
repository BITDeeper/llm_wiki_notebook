# 文本扩散模型

与自回归模型逐 token 顺序生成不同，文本扩散模型通过多轮迭代去噪/精炼一次性生成整块文本的生成范式。[[diffusiongemma|DiffusionGemma]] 是该范式的代表性开源实现。

## 核心原理

传统自回归语言模型像一台**打字机**：从左到右，一个 token 接一个 token 地生成。在云端批处理场景下效率很高，但在本地单用户请求时，GPU 大部分时间在等待下一个「按键」，硬件利用率低。

文本扩散模型将这个问题反过来：一次性起草整个文本块（如 256 token），让处理器每次拿到更大的计算任务，将模型推理从「顺序打字机」升级为「并行印刷机」。

## 关键技术特征

1. **解码瓶颈转移**：从内存带宽转向计算本身，在专用 GPU 上 token 输出速度最高可提升 4 倍
2. **[[双向注意力]]**：每个 token 可见其他所有 token，使非线性任务更易处理
3. **[[自我修正能力]]**：多轮迭代精炼输出，可实时发现并修正错误
4. **并行生成**：每次前向计算同时生成整块文本

## 优势

- **速度**：本地推理场景最高 4 倍加速
- **非线性任务**：行内编辑、数独、代码补全、氨基酸序列、数学图结构等场景优于自回归模型
- **硬件利用率**：本地低并发场景下 GPU 利用率更高
- **硬件门槛**：MoE 架构 + 量化可降低部署门槛

## 局限性

- **质量权衡**：以速度换取输出质量，整体质量低于同级别自回归模型
- **云端劣势**：高 QPS 云端场景中自回归模型的批处理效率更高，并行解码优势被削弱
- **成熟度**：仍处于实验性阶段，尚未进入生产级推荐序列
- **服务成本**：在云端部署可能带来更高的服务成本

## 与自回归模型的对比

| 维度 | 自回归模型 | 文本扩散模型 |
|------|-----------|-------------|
| 生成方式 | 逐 token，从左到右 | 整块并行生成 |
| 云端批处理 | 高效，充分利用硬件 | 优势被削弱 |
| 本地推理 | GPU 利用率低 | 最高 4 倍加速 |
| 非线性任务 | 受限（token 只见前文） | 优势（双向注意力） |
| 输出质量 | 生产级 | 实验性，较低 |
| 成熟度 | 成熟 | 实验性 |
