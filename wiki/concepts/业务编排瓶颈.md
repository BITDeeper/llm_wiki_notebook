# 业务编排瓶颈

指 Agent 在处理涉及多个系统（如 HR、财务、跨系统对账）的任务时表现出的极度困难，远超单纯的技术操作（如终端命令）。

## 发现背景

[[claw-eval-live]] 的评测结果显示了一个反直觉的现象：
*   **技术任务（简单）**：终端操作、环境修复等 Development/Terminal 任务，强模型通过率接近 100%。
*   **业务任务（极难）**：HR / People、Management / Ops 以及跨系统 Workflow 任务，通过率极低（HR 平均仅 6.8%，甚至有模型为 0）。

## 核心难点

业务编排瓶颈主要体现在：
1.  **跨系统证据收集**：需要从多个来源精确提取数据。
2.  **实体关联**：正确链接不同系统中的记录。
3.  **执行闭环**：确保所有必需的写操作和状态变更真正发生。

## 行业启示

这表明当前 Agent 的主要瓶颈已不再是「会不会用 terminal」，而是「能不能在多个系统之间把一件业务真的做完」。这是下一阶段技术攻坚的重点方向。
