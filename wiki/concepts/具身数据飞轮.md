# 具身数据飞轮

真实业务场景中任务执行→数据产生→模型迭代→能力提升→更多场景的闭环正反馈机制。区别于传统"采集型数据"模式，是[[场景型数据vs采集型数据|场景型数据]]的自然结果。

## 飞轮机制

```
任务越多 → 数据越多 → 模型越强 → 效率越高 → 更多仓库/SKU → 新数据回流
```

关键前提：数据生成必须与真实业务绑定在一起，数据不再是专门设置环节额外采出来的训练材料，而是从真实场景中自然流出来的生产副产物。

## 与Coding飞轮的类比

Coding飞轮：代码生成→运行→报错→修改→再运行，每一步都有反馈，失败沉淀为优化素材。

Picking飞轮：抓取成功/失败/掉落/误识别/放置偏差/路径卡顿/节拍变化，都可以被系统记录，成为模型继续优化的素材。

## 实现条件

[[原力灵机]]与[[atomix|Atomix]]的合并提供了实现条件：
- 场景侧（Atomix的仓储产线）每天产生海量真实Picking数据
- 模型侧（[[dm0|DM0]]）具备合并消化海量异构数据的能力
- 两者在同一组织体内运转，数据飞轮从"外部合作调度"变为"内生机制"

## 战略意义

- 是解决[[具身智能数据困境]]的具体路径
- 标志着具身智能从"采集型数据"向"场景型数据"的范式转型
- 大模型公司（智谱、阶跃星辰、[[商汤科技]]、阿里）集体押注，看中的是可能率先跑通的物理世界数据飞轮
