# 思考深度

思考深度是指模型在生成最终输出前进行的内部推理过程的长度，通常以字符或 Token 数量衡量。

## 重要性

对于复杂的工程任务，充足的思考深度是支撑模型完成任务的核心。它允许模型：
1.  在行动前规划多步骤方案。
2.  严格遵循数千字的项目规范。
3.  在输出前自纠错误。
4.  在数百次工具调用中保持推理连贯。

## 性能退化案例

在 [[Claude Code]] 2026 年 2 月至 3 月的更新中，思考深度经历了断崖式下跌：
- **1月30日-2月8日**: 约 **2200 字符**。
- **2月下旬**: 暴跌至 **720 字符**（降幅 67%）。
- **3月上旬**: 进一步缩水至 **560 字符**（降幅 75%）。

## 影响

思考深度的削减直接导致了模型能力的全面退化：
- **推理循环**: 矛盾无法在内部解决，直接暴露在输出中（如“哦等一下”、“不是这样”），推理循环率翻了 3 倍。
- **推诿行为**: 模型倾向于提前终止任务或找借口，终止钩子触发次数飙升至 173 次。
- **成本激增**: 由于模型输出质量差，用户需频繁纠正和重试，导致 API 成本不降反升（暴涨 122 倍）。

## 透明度问题

思考深度往往对用户不可见，尤其是在引入 `redact-thinking` 功能后。社区呼吁在 API 响应中公开 `thinking_tokens` 指标，让用户监控请求是否获得了所需的推理深度。
