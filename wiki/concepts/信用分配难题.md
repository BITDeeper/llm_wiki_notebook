# 信用分配难题

强化学习中的经典难题：在长序列任务中，当最终奖励信号表明任务完成不够完美时，模型无法定位具体是哪一步操作导致了失败。更形式化地说，这是在长逻辑轨迹的强化学习中，如何将最终奖励精确归因到序列中每个动作（Token）的困难，是当前 LLM 强化学习效率受限的核心原因。

## 问题本质

在 LLM 生成中，奖励通常在整段序列生成完毕后才出现。若试图在每个特定 Token 上分配奖励：

1. 各 Token 的交叉相乘会产生复杂的交互效应。
2. 梯度方差随时间步长 T 呈**二次方增长**（[[梯度方差暴增]]）。
3. 动作之间引入相关性，进一步放大方差。

## 典型场景

以AI编程为例：模型在编写长代码时调用了几百次工具，在第50步犯了一个小错（调用了不存在的工具），但随后迅速调整并继续正确执行。传统RL训练在全部结束后才返回奖励信号："任务整体完成不够完美"。此时模型面对上千行代码，无法判断错误出在哪一步。

## LLM 的应对策略

为规避上述难题，当前 LLM 的强化学习采用 **T=1 设定**：将整段长序列作为一个单一动作处理，将对数概率视为单个 Token 概率之和。但即便如此，朴素 REINFORCE 估计器仍保留较高梯度方差，模型必须依赖数百万量级样本才能从海量中性标签中提取有意义的监督信号。

## AlphaGo 的不同路径

[[alphago|AlphaGo]] 通过 [[mcts-蒙特卡洛树搜索|MCTS]] 采取了完全不同的路径：不再基于最终胜负进行信用分配，而是为每一步"重新标记"更优行动，将策略提升转化为强监督学习，从根本上绕开了这一难题。

## 解决方案

[[cursor]] 在训练 [[composer-2-5]] 时引入[[定向文本反馈rl]]，通过在模型可改进的具体位置精准提供局部化反馈信号，有效解决了这一难题。

## 与 Scaling Law 的关联

信用分配难题从 RL 训练效率角度揭示了 [[scaling-law|Scaling Law]] 的理论约束——单纯扩大规模面临梯度方差和信用分配的根本性瓶颈，并非所有问题都能通过增加算力和数据解决。
