# KV Cache与长上下文成本

**定义**：在大模型推理中，随着并发用户增加，每个请求携带的独立 KV Cache（键值缓存）会膨胀并占满物理显存，成为长上下文推理的核心成本来源。

## 机制

1. **KV Cache 的作用**：存储注意力机制中的 Key 和 Value 矩阵，避免重复计算已生成 Token 的表示
2. **膨胀效应**：上下文越长，KV Cache 越大；并发用户越多，总 KV Cache 占用越高
3. **显存竞争**：KV Cache 与模型权重争夺有限的 HBM 容量，当 KV Cache 占比过高时，可用于承载并发请求的空间不足

## 对定价的影响

- 当上下文拉长到特定阈值时，读取 KV Cache 的时间会超越计算权重的时间
- 系统再次陷入 [[显存带宽瓶颈]]，厂商必须通过涨价弥补效率损失
- 典型案例：Gemini 3.1 在上下文超 20 万 Token 时价格上浮 50%

## 缓解策略

- **存储分级**：将静置上下文的 KV Cache 从 HBM 疏散至 DDR/Flash（参见 [[推理并发调度经济学]]）
- **缓存命中优化**：对重复或相似前缀的 KV Cache 进行共享和复用
- **量化压缩**：对 KV Cache 进行低精度量化以减少显存占用
