# KV Cache 压缩

KV Cache（键值缓存）压缩是指在自回归生成过程中，通过裁剪或压缩注意力机制中的键值缓存来降低显存占用和计算开销的技术领域。在长序列推理场景中，KV cache 往往是压垮显存的"最后一根稻草"，压缩 KV cache 直接决定了模型"能跑还是不能跑"。

## 背景

在自回归模型中，为了保证生成内容的连贯性，模型必须将之前生成的所有 token 或帧的键值对存储在 KV Cache 中。随着序列长度增加，KV Cache 的显存占用呈线性增长，计算复杂度呈二次方增长。在视频生成场景中，30 秒视频的 KV Cache 就可能占用 60GB 以上显存。

## 核心数据

以100万token上下文、8bit KV精度、16bit索引精度为基准（数据来源：kvcache.ai）：

| 模型 | KV Cache HBM占用 |
|------|-----------------|
| [[deepseek-v4\|DeepSeek V4]]（1.6万亿参数） | **5.48GB** |
| 其他顶级开源模型 | **~60GB** |

DeepSeek V4体量远大于竞品，但KV Cache占用仅为竞品的约**1/10**。

## 战略意义

KV Cache压缩是[[deepseek|DeepSeek]]整个战略论证的技术起点，直接连接了以下所有下游论点：

1. **API定价优势：** 缓存命中价仅0.025元/百万Token，不到Claude Sonnet 4.6同类价格的3%
2. **[[ssd卸载|SSD卸载]]可行：** 压缩后的KV Cache可高效卸载到SSD，减少对昂贵HBM的依赖
3. **[[lpddr流式加载|LPDDR流式加载]]基础：** 整体内存压力下降使LPDDR作为权重暂存区成为可能
4. **国产硬件生态入口：** 降低硬件门槛，使中国现有存储和芯片生态"足够用甚至好用"

## 主要方法

### 架构级压缩：MLA（多头潜在注意力）

[[deepseek|DeepSeek]]通过MLA（Multi-head Latent Attention）架构实现，将传统的KV Cache从原始维度压缩到低维潜在空间，大幅减少存储需求。这是架构层面的根本性创新，而非后处理式的压缩。

### 量化派

通过降低 KV cache 的 bit 数实现压缩，不丢弃 token 但降低精度。代表方案为 Google Research 的 [[turboquant]]，定位为"零精度损失下实现极致压缩"。

类比：把所有行李都塞进压缩袋，不管里面是羽绒服还是砖头一律压扁。

### 选择性保留派

直接判断哪些 token 的 KV 值得保留、哪些可以丢弃，不改变保留 token 的精度。代表方案为 MIT/英伟达/浙大联合开发的 [[triattention]]，在 pre-RoPE 空间中利用 Q/K 三角集中度评估 token 重要性。

类比：先翻一遍行李箱，把砖头扔掉，只给羽绒服打包。

### 视频领域的差异化方法

大语言模型领域已有较多 KV Cache 压缩研究，但直接迁移到视频模型往往导致"闪烁"或块间衔接断裂。[[forcing-kV]] 提出了基于 [[注意力头动静分工]] 的混合压缩策略：

- **静态结构剪枝**：对静态头直接删除远距离历史缓存，仅保留转换锚帧和当前块
- **动态相似性剪枝**：对动态头基于相邻帧片段余弦相似度进行自适应冗余删除

## 路线对比

各路线方法论不同，但终点一致：让大模型跑在消费级硬件上，显存不炸，精度不掉。理论上多种路线可以叠加使用——先选择性保留减少 token 数量，再量化降低每个 token 的 bit 数，架构级压缩则从源头降低维度。

目前尚无严格的同模型、同硬件、同任务 head-to-head 对比。

## 与其他优化技术的兼容性

KV Cache 压缩可与 [[量化]]（如 FP8 量化）等技术叠加使用，进一步提升推理效率。Forcing-KV 已验证与 FP8 量化的兼容性。
