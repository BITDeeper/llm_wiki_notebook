# Tile级推理调度

Tile 级推理调度是由 [[tile-rt]] 团队提出的大模型推理优化技术，将推理调度单元从传统 operator/kernel 级别进一步下沉到 tile 级别，是实现 [[glm-5-1-highspeed]] 400 tokens/s 推理速度的核心技术手段。

## 技术原理

传统大模型推理调度以 operator 或 kernel 为单位，每次调度都需要 host 参与，存在大量调度开销和跨算子同步等待。Tile 级调度通过以下方式压缩这些开销：

1. **编译期静态编排**：在编译阶段预先排好所有 tile 的执行路线、分工和节奏，减少运行时动态调度
2. **常驻 GPU 的 persistent Engine Kernel**：推理 kernel 常驻 GPU，减少 host 与 device 之间的频繁通信
3. **减少跨算子同步**：通过静态编排消除不必要的同步点

## 类比理解

- **传统方式**：一群工人每搬一块砖都要等工头发一次指令
- **Tile 级调度**：提前把路线、分工、节奏排好，让工人持续在工地里流水线协作

## 与其他优化技术的对比

- **vs. [[DeepGEMM]]**：DeepGEMM 从算子层面优化矩阵乘法（如放弃 [[Split-K 优化]] 以保证 [[批次不变性]]），TileRT 从调度层面压缩空转环节，两者代表推理系统优化的不同切入点
- **vs. 传统动态批处理**：动态批处理优化请求级别的并行度，Tile 级调度优化算子内部的执行效率

## 行业意义

Tile 级推理调度证明了大模型推理速度的提升不只来自更强的芯片，也来自对系统里每一个空转环节的精细压榨。这种系统工程的思路是 [[高速推理api]] 竞争的核心壁垒之一。
