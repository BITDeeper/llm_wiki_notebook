# 视觉编程

[[视觉编程]]（Visual Programming / Vision Coding）是指利用人工智能模型，通过理解非代码的视觉输入（如手绘草图、设计稿、网页截图或界面链接）来直接生成软件代码或用户界面的技术范式。

这一能力标志着AI从辅助内容生成向执行复杂工程任务的跨越，是 [[千问3.5-Plus]] 等 Agent 模型在生产力工具领域的重要落地场景。

## 核心特征

-   **输入模态转变**：从传统的“文本描述 → 代码”转变为“视觉意图 → 代码”。
-   **高保真还原**：模型能够理解版式、配色、空间布局等视觉要素，并在生成的代码中予以还原。
-   **交互式迭代**：支持用户在生成的过程中通过自然语言或视觉反馈进行多轮修改。

## 技术基础

视觉编程的实现依赖于模型的 [[原生多模态]] 特性，即模型在统一的参数空间内同时处理图像和文本信息，消除了模态间的转换损耗。

具体技术组件包括：
-   **强大的视觉编码器**：如 [[cogvit]]，用于精确解析图像细节。
-   **原生多模态融合**：模型在预训练阶段即对齐视觉与逻辑空间，而非后期拼接。
-   **代码生成能力**：具备强大的纯文本编程基座，确保生成代码的可运行性。

## 应用场景

-   **草图转代码 / 快速原型开发**：开发者或设计师手绘界面草图，模型直接生成对应的高质量前端代码或可交互 Demo。
-   **网页复刻**：根据现有网页截图快速生成代码，用于迁移或学习。
-   **UI 修复与测试**：通过一张应用截图，模型定位并修复界面中的逻辑或样式问题；结合 GUI 操控能力，自动生成测试脚本。
-   **Agent 执行**：结合 [[vla-视觉-语言-动作]] 能力，模型不仅能“看”懂界面，还能操作 GUI（点击按钮、填写表单）。

## 代表性模型

-   [[glm-5v-turbo]]：智谱AI 发布的多模态 Coding 基座模型，强调草图生成前端的能力。
-   [[claude-code]]：Anthropic 推出的 AI 编程工具，虽以文本为主，但也具备视觉理解能力。

## 局限性与挑战

-   **逻辑完整性**：模型可能擅长生成“看起来像”的界面，但背后的复杂业务逻辑（如状态管理、异常处理）可能不完整。
-   **幻觉风险**：在解读模糊草图时可能产生误解，导致生成的代码不符合预期。
-   **后端支持**：目前的视觉编程主要集中在前端界面生成，对后端逻辑和数据库交互的支持相对较弱。
