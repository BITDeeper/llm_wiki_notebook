# 计算机使用

「计算机使用」是指 AI 模型不仅生成代码或文本，还能直接接管计算机的外设（鼠标、键盘、屏幕）和操作系统界面，像人类用户一样操控应用进行端到端任务执行的能力。

## 技术特征

### 从「建议」到「操作」
传统的 AI 编程助手（如 GitHub Copilot）主要扮演「建议者」角色，提供代码片段或修改意见。而具备「计算机使用」能力的 AI（如 [[claude-code]] 的更新版）则进化为「操作者」，能够：
- **跨应用交互**：打开并操作各类桌面 App（浏览器、IDE、系统工具）。
- **UI 自动化**：模拟点击、滑动和输入，进行图形界面测试。
- **自主调试**：直接观察程序运行界面，发现视觉或逻辑漏洞并修复。

### 实现方式
在 Claude Code 中，这一能力通过 `/mcp` 指令或特定的「自动驾驶」模式开启。模型通过 API 接收屏幕截图和 UI 元素信息，输出鼠标坐标和键盘指令，形成感知-决策-执行的闭环。

## 应用场景

### 软件开发全闭环
开发者只需输入一条指令，AI 即可完成：`写代码 -> 编译 -> 启动 App -> UI 自动化测试 -> 发现 Bug -> 修复代码 -> 再次验证`。这极大地降低了在不同工具间切换的认知成本。

### 具身智能的数字延伸
这一概念可视为 [[vla-视觉-语言-动作]] 模型在数字世界（虚拟环境）中的应用。与物理世界的机器人不同，这里的「具身」表现为对操作系统这一虚拟环境的操控。

## 挑战与风险

### 资源消耗
「计算机使用」通常涉及高频的屏幕采样和多轮交互，导致 Token 消耗量远超纯文本交互。在 [[claude-code]] 的案例中，这种高消耗叠加底层 Bug，直接引发了 [[ai-subscription-crisis]]。

### 安全与控制
赋予 AI 直接操作电脑的权限带来了潜在的安全风险，如误操作删除文件或触发不可逆的系统命令。因此，目前的实现通常包含权限确认机制（如 Hooks 中的 PermissionRequest）。
