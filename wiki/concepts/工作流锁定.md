# 工作流锁定

AI编程竞争从模型能力转向占据开发者日常工作流入口的战略逻辑。

## 核心论点

- GitHub Copilot式的代码补全只是一个功能，"用完即走"
- [[codex]]和[[claude-code]]争的是另一个层面：开发者日常工作的调度中心
- 谁的工具深入开发者的项目、线程、凭证、任务队列，谁就能在工作流里扎根

## 竞争动态

- [[anthropic]]通过Claude Code Remote Control率先占据远程控制场景（2026年2月）
- [[openai]]通过Codex快速补课，从桌面到移动端全面铺开控制面
- 奥特曼宣布补贴策略（两个月免费），以价格战加速工作流锁定
- 战场从开发者的工位烧到了口袋

## 与其他概念的关系

- 是[[ai-infrastructure-flywheel]]在AI编程赛道的具体表现
- 与[[token作为生产资料]]形成呼应：锁定工作流意味着锁定token消耗入口
- 代表AI编程从工具竞争升维为平台竞争
