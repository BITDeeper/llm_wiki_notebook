再见，人类程序员！OpenAI自曝：一行代码都不写了，100%用Codex §

概述 §

本文报道了 OpenAI 在 AI 编程领域的最新进展，重点介绍了 codex 模型的“复活”及其 CLI 工具的重大更新。文章指出，OpenAI 研究员 roon 声称其 100% 的代码编写工作已由 Codex 接管，并爆料内部利用该工具在三天内搭建 MCP 服务器、三周内发布 Sora 安卓应用。同时，文章深入探讨了 plan-mode 这一新交互范式，以及 AI 编程带来的 生产与审查的不对称 和 软件工程琐碎化 等行业隐忧。

核心要点 §

1. OpenAI 的反击与 Codex 的进化 §

  • 研究员证言：OpenAI 研究员 roon 表示，编程的痛苦时代已经结束，他已完全不再手写代码，转而由 Codex 接管。
  • 内部效率：爆料称，利用 Codex，团队仅用 3 天搭建了 MCP 服务器，3 周发布了 Sora 安卓应用。
  • CLI 更新：codex CLI 更新至 0.9+ 版本，引入了备受期待的 plan-mode（计划模式）。

2. Plan Mode：从“补全”到“规划” §

  • 两阶段拆解：
    1. 理解意图：明确目标、范围、约束和验收标准。
    2. 技术规格：生成决策完备的实施方案。
  • 证据优先探索：在提问前，AI 会先在代码库中进行针对性搜索（配置、Schema 等），以获取上下文。
  • 交互优化：使用 request_user_input 工具进行结构化询问，提供选项并推荐默认项，仅在关键歧义处暂停。

3. 行业竞争与对比 §

  • 对标 claude-code：文章多次提及 boris-cherny（Claude Code 之父）此前关于“100% AI 编写代码”的言论，视其为行业风向标。
  • 社区反馈：部分开发者认为 GPT-5.2-Codex 在 90% 情况下能一次性完成任务，且比 Claude 更“开箱即用”。

4. 隐忧与风险 §

  • 生产与审查的不对称：AI 生成代码的速度（毫秒级）远超人类审查速度（分钟/小时级），导致 Code Review 流于形式，技术债务像“癌细胞”一样扩散。
  • 软件工程琐碎化：开发者可能为了追求 GitHub 提交记录（绿格子）而生成大量低价值代码，忽视了高价值的架构思考。
  • 信任度下降：AI 代码正跨越“恐怖谷”，错误变得更加隐蔽（如引用不存在的库），导致开发者使用量上升但信任度下降。

精彩引述 §

“编程一直很痛苦，然而却是必经之路。我很高兴，它终于结束了。” — roon

“100个提交，可能让GitHub的绿格子很好看。1个架构变更，可能需要三天思考，零行代码产出。前者廉价如尘土，后者珍贵如黄金。” — 文章观点
