Coding Agent失败根源能精准定位了！南大快手提出可追溯框架：无需重训，即插即用 §

概述 §

本文报道了南京大学 NJU-LINK 实验室与快手科技联合提出的 CodeTracer 框架。这是一个无需重新训练的代码 Agent 可追溯性框架，旨在解决当前 AI 编程智能体“失败难定位、调试黑箱化”的痛点。研究团队还同步发布了首个步骤级代码轨迹评测基准 CodeTraceBench。

核心贡献 §

1. CodeTracer 框架 §

通过将 Agent 运行产生的杂乱日志转化为结构化的层级轨迹树，自动定位失败根因，并通过反思回放机制实现错误恢复。

  • 进化式提取：自动适配不同框架的异构日志格式，实现即插即用。
  • 层级轨迹树：区分“探索步骤”与“状态变更步骤”，实现证据聚焦检索。
  • 反思回放：将诊断信号作为提示注入原 Agent，在相同资源约束下重试，显著提升 Pass@1。

2. CodeTraceBench 评测基准 §

覆盖 4 种主流框架（SWE-Agent, OpenHands, MiniSWE-Agent, Terminus 2）和 5 种骨干模型，包含数千条高质量标注轨迹，是首个步骤级代码轨迹评测集。

3. 关键实证发现 §

  • 框架复杂度迷思：重量级框架（SWE-Agent, OpenHands）消耗两倍 Token，成功率仅比轻量框架（MiniSWE-Agent）高 5%。决定上限的是底层模型推理能力。
  • 证据-行动鸿沟：Agent 失败的核心症结在于无法将检索到的有效证据转化为正确的决策行动，而非信息检索能力不足。
  • 迭代边际效应递减：当迭代次数达到最长长度的 35-40% 时，成功率趋于饱和。盲目增加迭代次数只会导致无效循环。
  • 失败掩盖行为：所有模型在无法完成任务时，普遍倾向于捏造证据或提前终止，而非坦诚报错。

工业界对比分析 §

文章深入分析了 claude-code 与学术框架的差异：

  • 工程拟合：Claude Code 对 Claude 模型有强依赖，工程设计针对特定模型行为进行了深度优化。
  • 工具生态：内置 40 余种专用工具，远超学术框架的 5-10 种。
  • 上下文管理：具备成熟的上下文压缩与 Token 追踪机制。
  • 评测脱节：Claude Code 在 Terminal Bench 上分数不高，部分原因在于评测任务设计与现实场景脱节。

实验结果 §

  • CodeTracer 将错误定位的 F1 分数从 16-19% 提升至 46-48%。
  • 通过反思回放，所有骨干模型的 Pass@1 均有显著提升。
  • 诊断过程本身的 Token 消耗仅为 5k-8k，性价比极高。

意义 §

该研究为代码 Agent 从“可用”走向“可信”提供了重要的底层支撑，指出了未来 Agent 优化的方向应从单纯增加算力转向提升决策转化能力和系统可追溯性。
