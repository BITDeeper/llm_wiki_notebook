通用 AI Agent 驱动网关路由安全审计实践 §

本文介绍了得物技术如何利用 ai-agent 构建网关路由安全审计系统，通过“通用 Agent + 业务 Skill”分层设计，实现了 API 安全审计的全量覆盖与成本优化。

核心观点 §

  • 覆盖面与时效性：利用 AI Agent 实现了 100% 的路由覆盖和分钟级检测响应，解决了传统人工抽样审计覆盖面不足（~20%）和时效性差的问题。
  • 成本控制：通过 mcp-protocol 到 CLI 的转换（mcp2cli）、精准代码提取和 Early-Exit 模式，整体 Token 成本降低了 95% 以上，单条审计成本降至 ¥0.23。
  • 人机协同：采用“AI 批量筛查 + 人工深度验证”的模式，既保证了效率，又解决了 AI 误报问题。

技术架构 §

系统采用“通用 Agent + 业务 Skill”分离的架构设计：

  • 通用 Agent：负责代码语义理解、逻辑推理与自动化执行（基于 Claude Code/OpenCode 或 qwen）。
  • 业务 Skill：封装具体的检测规则、分析流程和报告模板，支持快速迭代。

关键技术点 §

  1. 越权漏洞精细化分类：将越权漏洞细分为“越权读取”（关注数据敏感性）和“越权操作”（关注利益流向），以实现更精准的危害评估。
  2. Early-Exit 模式：在检测流程中设置短路退出机制（如发现标准认证路由直接信任），跳过后续冗余代码审计，大幅降低 Token 消耗。
  3. MCP → CLI 转换：将 mcp-protocol 工具封装为 CLI 命令，避免每次会话加载完整的 MCP 上下文，节省了 61% 的 Token 消耗。
  4. 模型选型：在安全审计场景下，qwen3.5-plus 在召回率 100% 的前提下，性价比优于其他模型。

误报分析与改进 §

文章分析了误报的主要根因：

  • 信任边界追踪不完整（35%）：AI 在中间层停止分析，未追踪到最终数据操作层。
  • 上下游参数不一致（25%）：下游方法存在越权可能，但上游调用时未传入资源 ID。
  • 配置信息缺失（10%）：内部网关转 Dubbo 传参信息 AI 无法获取。

针对这些问题，提出了相应的改进方案，如强化信任边界追踪、增加 Dubbo 配置信息补充等。

结论 §

该实践证明了 AI 在代码审计场景的有效性，单条成本 ¥0.23，某大型业务集群全量扫描一轮不到 1 万元，成本完全可控。人机协同模式有效平衡了效率与准确性。
