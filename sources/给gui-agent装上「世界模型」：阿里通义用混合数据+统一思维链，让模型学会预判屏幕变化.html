给GUI Agent装上「世界模型」：阿里通义用混合数据+统一思维链，让模型学会预判屏幕变化 §

概述 §

本文详细介绍了阿里巴巴通义实验室开源的新一代多平台 GUI Agent 框架 Mobile-Agent-v3.5 及其原生基座模型家族 GUI-Owl-1.5。该工作通过构建混合数据管线、注入世界模型能力以及提出 MRPO 算法，解决了跨平台 GUI Agent 在长轨迹数据收集、多平台梯度冲突及状态预测等方面的工程难题。

核心技术架构 §

1. 模型变体：Instruct 与 Thinking §

为了兼顾响应延迟与推理深度，GUI-Owl-1.5 提供了两种架构侧重点：

  • Instruct 模型：专注极速响应与轻量化执行，不输出思考链，直接基于当前上下文决策。适合部署在算力受限的端侧设备。
  • Thinking 模型：专攻长程复杂任务，具备完整的思维链能力，能进行详尽的规划、反思与纠错。

这两种形态支持 端云协同 模式：云端大参数 Thinking 模型作为规划者拆解任务，端侧 Instruct 模型作为执行者完成原子操作。

2. 混合数据管线 §

针对真实环境长轨迹数据难收集的问题，团队构建了混合数据生产管线：

  • Grounding 数据：利用多模态模型结合参考界面合成高分辨率复杂 UI 截图；通过轨迹挖掘和字幕解析抽取交互问答。
  • 不可行查询：引入大规模负样本，训练模型在找不到目标控件时主动拒绝操作。
  • 轨迹合成：引入基于 DAG 的任务合成机制，设计了截断与任务修复机制，将失败轨迹转化为高质量的前缀监督数据。
  • 虚拟环境：基于 Web 渲染构建虚拟环境，低成本生成专家轨迹。

3. 世界模型与统一思维链 §

  • 世界模型：训练模型进行状态转移预测，要求模型在执行动作前预判下一屏 UI 的变化（如焦点转移、弹窗出现），降低试错成本。
  • 统一思维链：对所有多端轨迹数据进行思维扩充，强制模型输出结构化的中间状态（观察、记忆提取、反思、决策），赋予模型全局任务规划能力。

4. MRPO 算法 §

针对多平台强化学习中的工程瓶颈，提出了 MRPO (Multi-platform Reinforcement Policy Optimization) 算法：

  • 解决结果坍塌：通过在线过采样和条件替换机制，解决了 GRPO 在 GUI 任务中因组内方差为零导致训练组被丢弃的问题。
  • Token-ID 对齐：环境端与训练端直接传输 Token ID 序列而非文本，规避分词器差异导致的概率计算偏差，保证策略梯度估计的严格一致性。
  • 交替优化：采用交替多平台优化策略，隔离不同平台间的梯度干扰，避免混合训练导致的“拉锯战”。

评测表现 §

GUI-Owl-1.5 在 20 多个主流 GUI Benchmark 上取得了开源领域领先的测试结果：

  • OSWorld-Verified：32B-Instruct 取得 56.5 分（开源 SOTA）；8B-Thinking 达到 52.9，展现了极高的参数效率。
  • AndroidWorld：8B-Thinking 取得 71.6 分。
  • ScreenSpot-Pro：32B-Instruct 在 Base 设置下达到 72.9，结合 Zoom-In 策略后飙升至 80.3。
  • WebArena / VisualWebArena：32B-Thinking 分别达到 48.4 和 46.6。
  • WebVoyager：Thinking 变体（82.1）显著高于 Instruct 变体，证明了思维链在长程规划中的价值。

复杂场景案例 §

  • 移动端跨域协同：模型成功执行了跨小红书和抖音统计粉丝数的任务，展示了跨应用信息提取与长程记忆管理能力。
  • 桌面端多窗口流转：在 Windows 桌面端完成了“网页搜索+资料整理”任务，利用世界模型先验知识精准预判系统反馈（如弹窗、光标位置），在复杂多窗口环境中保持了低错误率。

关键意义 §

该工作标志着 GUI Agent 从演示 Demo 走向工程级应用。通过开源底层基座模型、多端统一动作空间设计及经过工程验证的 RL 训练范式，为技术社区提供了重要的基础设施。
