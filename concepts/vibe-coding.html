Vibe Coding §

Vibe Coding（氛围编程/凭感觉编程）是一个多义术语，主要包含以下两层含义：

  1. 编程范式：指一种由 Zevi Arnovitz 提出并经 Andrej Karpathy 推广的开发模式，强调利用自然语言和直觉驱动 AI 生成全栈应用，将开发者角色从“代码编写者”转变为“审美法官”。
  2. 网络俚语：带有讽刺意味，指依靠直觉、氛围感或 AI 辅助工具进行草率决策或操作，缺乏严谨的工程规范。

历史注脚：随着 2026 年 GLM-5 等具备强大系统工程能力模型的出现，Vibe Coding 的早期定义被认为已经终结，被更严谨、更强调架构的 Agentic Engineering（智能体工程）所取代。

此外，Vibe Coding 也是涂鸦智能（Tuya）推出的同名自然语言编程功能，集成于其 Hey-Tuya 生态中，用于全屋智能的自动化定制。

核心定义与特征（编程范式视角） §

在作为编程范式讨论时，Vibe Coding 标志着软件开发从“手工作坊”向“智能体协作”的初步转移。在这一模式下，用户仅凭一句简单、模糊的自然语言提示词（“大白话”）或视觉输入，即可让 AI 自动生成兼具视觉设计、交互逻辑和完整功能的代码或应用。

意图描述与直觉驱动 §

开发者利用 AI 工具（如 cursor）绕过传统编程训练，凭直觉或感觉快速生成产品。开发者不再需要学习底层语法（如从 “Hello World” 学起）或精确记忆 API 语法，不再深入理解代码逻辑，不再关注底层的逻辑构建、语法细节和逐行实现，而是专注于通过自然语言清晰地表达“想要什么”或“我要这种感觉”。

开发者像甲方一样输出需求，而非编写技术规范，将“怎么做”留给 AI。在这种模式下，开发者更像是一个产品经理或审美法官，负责判断结果是否符合预期，而非编写具体实现。

核心特征 §

  • 极低门槛：用户无需具备深厚的编程知识或复杂的提示词技巧，仅需使用自然语言描述需求。
  • 全栈生成：AI 能够一次性覆盖前端视觉、后端逻辑、交互设计乃至动画效果。
  • 所见即所得：生成的代码通常可直接运行，快速将抽象想法转化为可视化产品。

角色转换：从生成到辨别 §

这一范式强制改变了人类的大脑工作模式：

  • 旧模式：生成模式——大脑负责构思逻辑并转化为代码。
  • 新模式：辨别模式——大脑负责审查 AI 生成的代码，判断其是否符合意图和美学标准。

在 Vibe Coding 模式下，人类的角色从繁琐的代码编写者转变为 审美法官。用户的核心价值在于判断“做什么”以及“好不好看/不好用”，而“怎么做”则交给 AI 完成。

工作流比例逆转 §

andrej-karpathy 的个人经历展示了这一转变的剧烈程度：

  • 2025 年 11 月：80% 人工编写 + 20% AI 辅助。
  • 几周后：80% AI 生成 + 20% 人类审查。

极速迭代与黑盒生成 §

  • 反馈循环：速度是传统手工编码的 50-100 倍，开发周期从月级压缩至天级（24小时）。
  • 黑盒操作：代码由 AI（如 Claude 3.5 Sonnet）在黑盒中生成，开发者往往不阅读具体逻辑，仅负责结果的验收（如 UI 美观度）。
  • 审美优先：逻辑的正确性有时让位于用户的视觉爽感和交互体验。

交互模式演变 §

Vibe Coding 的交互方式正在从单纯的文本对话向多模态实时协作演进。

1. 文本/语音驱动（主流模式） §

这是目前最普遍的形式。用户通过自然语言（大白话）描述需求，AI 理解意图并生成代码。

  • 工具：Claude 3.5 Sonnet、Cursor、Windsurf。
  • 特点：擅长处理模糊指令，快速生成 UI 和逻辑。

2. 视频流实时交互（前沿模式） §

随着多模态模型（如 qwen3-5-omni）的出现，Vibe Coding 进化到了“视频通话”阶段。

  • 视觉输入：用户开启摄像头，展示手绘的 UI 草图、实体环境或物理对象。
  • 实时理解：AI 实时分析视频流，识别布局、元素和意图。
  • 现场生成：AI 根据画面逻辑直接生成代码（如 HTML/CSS、Python），并可能调用 WebSearch 填充内容。
  • 即时反馈：用户在视频通话中直接看到生成的预览或代码，并进行迭代修改。

这种模式代表了 AI 交互从“文本对话”向“现场协作”的范式转移，进一步降低了非专业用户通过直观视觉表达进行软件开发的门槛。

演进阶段 §

Vibe Coding 作为一种范式，经历了从辅助工具到全栈自动化的演进过程：

1. 代码片段生成 §

早期的 Vibe Coding 主要指利用 AI（如 GitHub Copilot）辅助生成函数或代码片段。开发者仍需负责环境配置、依赖安装、调试和部署。

2. Agent 辅助开发 §

随着 AI Agent 技术的发展，AI 开始具备自主规划、调用工具和修复 Bug 的能力。开发者可以通过对话让 AI 配置环境或解决特定错误，但基础设施（服务器、域名）仍需人工管理。

3. 终极进化：全栈自动化 §

以 Meoo (秒悟) 为代表的工具标志着 Vibe Coding 进入新阶段。这一阶段实现了“说话即上线”：

  • 零基础设施操作：服务器、数据库、存储等完全由后台自动配置。
  • 全流程闭环：从需求理解到最终交付可访问的 URL，无需人工干预代码层面。
  • 并行处理：利用 蜂群模式 等技术，将复杂任务拆解并行执行。

应用场景 §

软件开发与视觉创作 §

Vibe Coding 强调代码运行的最终视觉效果或交互体验，而非代码本身的规范性。根据 google-ai-studio 的官方示例库及社区实践，其典型应用包括：

  • 视觉与交互创作：如 4K 高清壁纸生成器、3D 粒子特效、漫画生成器、像素艺术场景生成。
  • 游戏与娱乐：如网页版跑酷游戏、电商产品摄影棚模拟。
  • 业务系统：非技术人员（如 SemiAnalysis 的分析师）也能通过 Vibe Coding 开发视频游戏或生成复杂的财报分析图表。毫无编程背景的人（如焊工、律师、全职奶爸）也能构建复杂的业务系统。
  • 全栈构建：AI 不仅生成前端 UI，还处理后端逻辑和数据库结构，实现从“设计→切图→编码”向“描述→生成→对话”的转变。

智能家居与 IoT §

在涂鸦智能的生态中，Vibe Coding 允许用户通过自然语言对话，结合自身使用场景与全屋智能硬件，自主定制专属 Skill、个性化 Agent 与自动化工作流。它支持零代码开发、深度定制（如自定义搭建居家设备控制面板），并能串联数字与实体场景，快速搭建量产级应用。

设计领域的延伸 §

随着 ChatGPT Images 2.0 等具备推理能力的模型出现，Vibe Coding 的概念延伸至设计领域。设计师不再需要手动调整每一个像素、图层或参数，而是通过自然语言描述想要传达的氛围、风格或核心信息，由 AI 模型自动完成具体的构图、配色和细节渲染。这代表了设计工作流从“手工操作”向“意图驱动”的转变，设计师的角色从“执行者”转变为“审美法官”和“创意指挥”。

移动端与平台集成 §

在 字节扣子 2.5 等平台中，vibe-coding 被用于快速构建 Web 应用、小程序和自动化工作流。它代表了 任务执行范式 的一种极致形式，即人类仅负责意图表达，AI 负责所有工程实现细节。这一阶段特别强调移动端（手机）的可用性，使得非技术人员也能随时随地进行开发。

工具生态 §

Vibe Coding 的实现依赖于特定的工具组合：

  • 灵魂：Claude 3.5 Sonnet（擅长 UI 和模糊指令）。
  • 外骨骼：Cursor、Windsurf（AI 原生 IDE）。
  • 刺客：DeepSeek R1（极致性价比，降低试错成本）。
  • 新势力：Google Antigravity（Karpathy 测试后认为比一年前工具强大 10 倍）。
  • 后起之秀：kimi-k2-6（支持 Vibe Coding 的通用模型，博主 @Viktor Oddy 曾利用其在不写一行代码的情况下，通过对话构建包含复杂动效和响应式布局的品牌网站）。
  • 国产力量：Qwen3.6-Plus（在实测中展现出强大的 Vibe Coding 能力，如一句话生成可交互的 3D 雪山场景、包含状态管理的虚拟宠物养成网页、具备核心玩法的消消乐小游戏等）。
  • 多模态先锋：qwen3-5-omni（支持实时视频流交互，能够理解摄像头画面并现场生成代码）。
  • IoT 平台：Hey-Tuya（涂鸦智能的“超级入口”，利用 Vibe Coding 实现主动服务与个性化体验）。

此外，这一范式的落地也依赖于 Expo、Supabase、Vercel 等“AI Native”工具链的成熟，这些工具消除了样板代码、配置细节和基础设施搭建的负担。

行业共识与影响 §

技术领袖的观点 §

Vibe Coding 迅速获得了技术领袖的广泛认可，被视为“人类写代码时代终结”的标志：

  • Ryan Dahl（Node.js 之父）：直言“人类写代码的时代已经结束”。
  • DHH（Ruby on Rails 创造者）：认为手写代码已成为一种“奢侈的复古行为”。曾激烈批评 AI 编程，后在 2026 年初承认其可用性。
  • Linus Torvalds（Linux 之父）：开始在 GitHub 上测试这种新模式。他在 audionoise 项目中使用该技术生成 Python 可视化工具，并承认效果优于手动编写。

市场与阶级重塑 §

  • 应用爆发：被认为是导致 2024 年下半年 App Store 新应用提交量暴涨 60% 的核心驱动力。
  • 工具市场：催生了年收入 10 亿美元的 Cursor �
