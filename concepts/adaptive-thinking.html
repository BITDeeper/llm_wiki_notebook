自适应思考 §

自适应思考（Adaptive Thinking）是 Anthropic 引入的一种推理机制，旨在替代传统的固定思考预算模式。该功能最初于 2026 年 2 月 9 日在 Opus 4.6 版本中上线，随后在 Claude Opus 4.7 中成为默认模式。

定义与机制 §

传统的模型推理使用固定的思考预算（如 4.6 版本中的 budget_tokens 参数），而自适应思考模式允许模型自主决定推理的深度和时长。

官方声称这种方式总体上比固定思考预算效果更好，能在保持高智能表现的同时，显著提升 token 效率、降低响应延迟。

API 变更 §

  • 4.6 机制：用户可以通过 budget_tokens 明确指定模型分配多少 Token 用于思考。
  • 4.7 机制：改为 thinking={"type": "adaptive"}，由模型动态决定思考深度，并引入新的 effort 参数。

争议与负面影响 §

尽管官方旨在优化效率，自适应思考的引入引发了巨大争议，被认为是导致 Claude Code 性能退化的主要原因之一。

1. 破坏性变更 §

旧的 budget_tokens 参数在 4.7 中直接返回 400 错误，没有弃用过渡期，导致大量开发者代码报错。

2. 性能大幅退化 §

数据显示，引入该功能后，模型能力出现显著倒退：

  • 思考深度削减：模型思考深度从 2200 字符暴跌至 700 字符（降幅 67%）。
  • 行为模式退化：模型从严谨的“先研究再修改”模式转变为“上来就改”的莽撞模式，读改比 从 6.6 降至 2.0。
  • 成本反噬：由于模型变“蠢”导致无效循环和重试，API 成本反而暴涨 122 倍。

3. 成本与透明度问题 §

  • 消耗增加：Claude Code 创建者 Boris Cherny 承认，4.7 消耗了更多的 thinking token，虽然 Anthropic 声称提高了速率限制以作补偿，但具体幅度未公开。
  • 付费盲盒：思考过程默认在响应中“省略”（隐藏），用户看不到模型思考了什么，但仍需为这些思考 Token 全额付费。

4. 社区观点 §

社区普遍认为，自适应思考实际上是系统为了节省算力成本而牺牲了推理质量。对于复杂的工程任务，这种“效率优化”彻底失效，导致了“为了省 1 块钱思考费，浪费 100 块钱 API 费”的荒谬结果。

相关设置 §

用户可以通过环境变量 CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING 关闭此功能，恢复固定思考预算模式。
