一、 引子与背景 (The Hook & Background)
近年来，多模态大语言模型（Multimodal Large Language Models, MLLMs）的发展日新月异。随着模型底层能力的不断进化，我们正见证着一次重大的范式转移：从被动的“标准视觉问答（VQA）”向主动利用外部工具处理高级视觉任务的“视觉智能体（Visual Agentic Models）”演进。当前的 MLLM 被赋予了调用外部工具的能力，通过编写代码或调用 API 来处理复杂的视觉工作流，从而极大扩展了其在现实世界中的应用潜力。
然而，在这个看似繁荣的赛道背后，隐藏着一个致命的痛点：精确执行并有效地组合多种工具以完成复杂任务，仍然是一个持久的瓶颈。
现有的视觉工具调用评测基准普遍存在严重的局限性：
工具集极度稀疏：
现有基准往往受限于稀疏的工具集，这与真实世界中复杂的计算机视觉流水线相去甚远。
工具调用轨迹过于简单：
大多数任务的工具调用轨迹非常简单，未能充分测试高级视觉推理所需的多工具组合（Multi-tool Composition）和长程多步规划（Long-horizon Planning）执行。
由于缺乏对“多工具组合”和“长程多步规划”能力的有效考察，现有的基准测试在评估实际、真实世界条件下的模型性能时显得力不从心。这种局限性掩盖了当前模型的真实操作极限，无法为开发更可靠的视觉智能体提供充分的指导。
为了彻底打破这一瓶颈，揭开视觉 Agent 的真实面纱，研究团队隆重推出了 Visual Tool Chain-Bench (VTC-Bench)。这是专门针对 MLLM 在真实视觉任务中，进行高级多步工具组合能力评估的综合性硬核基准。
二、 核心创新点概览 (Core Innovations Overview)
与以往简单的测试不同，VTC-Bench 是一块真正的试金石。它的核心创新可以总结为三大支柱：对齐真实的工具箱、递进式的认知层级体系，以及基于真实轨迹的过程评估。

三、方法详解 (Methodology Deep Dive)
1. 对齐真实的 32 种硬核 OpenCV 工具箱
为了让测试环境尽可能贴近人类专家的实际计算机视觉工作流，VTC-Bench 摒弃了生造的简单 API，直接集成了 32 种基于 OpenCV 的多样化视觉操作工具。这些工具作为解决复杂视觉任务的基本构建块，赋予了模型极高的探索与组合空间。
这 32 种工具被科学地划分为四大逻辑模块：
几何变换（Geometry）：
用于空间维度的转换，如调整大小（Resize）、旋转（Rotate）、裁剪（Crop）、放大（Zoom In）等。
信号增强（Enhancement）：
用于信号优化和环境干扰消除，如色彩空间转换（Convert Color）、模糊（Blur）、去噪（Denoise）、阈值化（Threshold）、形态学操作（Morphology）等。
特征提取（Feature Extraction）：
用于推导结构和语义基元，包含 Canny 边缘检测（Canny Edge）、梯度计算（Compute Gradients）、分水岭算法（Watershed）、霍夫变换（Hough Transforms）等高级算子。
绘制与测量（Drawing/Measure）：
用于推理验证和属性量化，如绘制轮廓（Draw Contours）、绘制图形、计算轮廓面积（Contour Area）和弧长（Arc Length）等。
这种丰富的工具集自然地支持了反映现实世界挑战的高级工具组合和多步推理策略，使得 VTC-Bench 能够严格评估多工具组合和长程规划执行能力。
2. 九段递进式认知层级体系 (Task Taxonomy)
VTC-Bench 并没有将问题随机堆砌，而是构建了 680 个精心设计的问题，并将其严密地划分为三个渐进的梯队（Tiers）、九大认知类别，以映射多模态智能体从被动视觉感知到主动建构性推理的演进过程：
Tier 1: 视觉感知增强 (Visual Perception Enhancement)
鲁棒 OCR (Robust OCR)：在极度模糊、畸变的条件下，要求模型展示战略规划，通过链式二值化和锐化工具后再进行识别。
感知恢复 (Perceptual Restoration)：在雾霾或低光等恶劣条件下恢复场景，要求模型充当“预处理器”来中和环境干扰。
注意力聚焦 (Attention Focusing)：处理几何畸变（如倒置、镜像），要求模型通过工具辅助的空间归一化来重新定向其“焦点”。
Tier 2: 定量视觉估计 (Quantitative Visual Estimation)
测量 (Measure)：评估模型感知和精确量化物理属性（如提取尺寸、位置和形状）的能力，通常需要亚像素级的精度。
颜色 (Color)：检查色度信息的精确提取，迫使模型摆脱原始 RGB 感知，转而使用色彩空间操作（如 HSV/LAB）。
计数 (Counting)：面对遮挡和密集重叠的物体（如米粒），直接计数是不可行的，模型必须学会组合形态学工具进行“分割并计数”。
Tier 3: 组合视觉推理 (Compositional Visual Reasoning)
图表 (Chart)：一项综合任务，要求同时进行恢复、感知和推理，通常需要逻辑辅助构建和精确采样。
数学 (Math)：评估辅助几何元素的构建，模型必须识别并绘制辅助线来解决复杂的多边形问题。
空间推理 (Spatial Reasoning)：测试在过度曝光或严重模糊等极端条件下空间关系的稳健分析，要求将定性的视觉线索转化为精确的空间坐标。
图2：VTC-Bench 概览。基准测试的渐进式设计将 9 个 VQA 任务组织成一个三层的认知层次结构，评估 MLLM 从基本的视觉恢复到高级的逻辑推导的多工具编排能力。每个任务都提供一个参考工具链，以实现细粒度的诊断分析。
3. 基于真实轨迹的双轨过程评估
为了保证严谨的评估，VTC-Bench 的每一个问题都配有人工标注的 Ground-truth (GT) 执行轨迹。这确保了模型是基于其潜在的逻辑推理被评估的，而不仅仅是看最终的预测结果。
VTC-Bench 支持两种主流的智能体交互范式进行评估：
代码驱动 (Code Interpreter)：
模型综合 Python 代码作为原始工具来处理图像。
接口驱动 (Atomic OpenCV Toolbox)：
模型在沙盒环境中迭代调用预定义的接口。

四、 实验结果与分析 (Experimental Results & Analysis)
研究团队对 19 款领先的 MLLMs（涵盖闭源大厂模型和开源先锋模型）进行了极其详尽的摸底评估。实验结果打破了行业的普遍乐观，暴露出当前模型在视觉智能体能力上的严峻局限性。
1. 极低的性能天花板
VTC-Bench 对当前的 MLLMs 构成了重大挑战。在基础（Base）设置下，模型的整体表现普遍偏低，得分范围仅在 22.06% 到 46.47% 之间，大部分模型集中在 30% 左右。即使是加入了工具调用能力，表现最顶尖的 Gemini-3.0-Pro 模型，在基准上的最高准确率也仅仅达到了 51.18%。
这说明，从被动的视觉感知过渡到主动的、多步的工具编排，仍然是一个未被解决的重大难题，即便是目前行业最先进的架构也难以轻易跨越。此外，单纯地扩大模型参数量并不能本质上解决这个问题（例如 Qwen3-VL 的 235B 版本虽然比 8B 版本基础能力强，但加上工具后依然难以突破 40% 的得分瓶颈）。
2. 闭源与开源的“工具调用鸿沟”
实验揭示了闭源模型与开源模型在利用外部工具能力上存在明显的分歧。
闭源专有模型 (Proprietary Models)：如 GPT-4o, GPT-5.2, Gemini 系列，它们不仅基础性能较强，而且在配备工具后展现出了实质性的性能激增。例如，GPT-4o 在接口设置下获得了 +9.56% 的显著提升，GPT-5.2 在代码设置下获得了 +8.53% 的提升。
开源模型 (Open-source Models)：令人遗憾的是，开源模型通常未能有效地利用工具集成，在增加工具使用能力后往往只获得极小的收益，有时甚至遭受性能退化（准确率出现负增长）。这表明开源模型和专有模型在原生的工具使用能力上存在着巨大的鸿沟。
3. 基础视觉感知是工具调用的“地基”
分析具体任务表现可以发现，模型在需要粗粒度工具调用的“视觉感知增强（Tier 1）”任务中表现较好，仅仅通过旋转或镜像等基本操作就能实现性能提升。
相反，在“定量视觉估计（Tier 2）”任务中，由于该层级严格测试细粒度的工具选择和参数配置，暴露出模型无力执行精确的工具操作，导致性能明显下降。
在“组合视觉推理（Tier 3）”中，基础感知能力更强的模型（如 Gemini-3.0-Pro 在空间推理上提升了 +17.78%）表现更为出色，这凸显了一个核心事实：强大的内在视觉感知是进行高级工具调用的不可或缺的先决条件。

4. 深度诊断实验
通过对模型工具调用率、效率以及数千条调用轨迹的深度分析，研究团队抓住了当前 AI 作为 Agent 存在的几个“致命缺陷”。
极度偏科，工具利用分布极不均匀： 通过分析代表性模型（如 Gemini 和 GPT 系列）的工具使用分布饼图，研究发现一小部分基础工具（如 Zoom In 放大、Crop 裁剪、Rotate 旋转、In-range Color 等）占据了总调用量的极大比例。这种高度集中的使用模式表明，现有模型在工具选择上缺乏多样性，它们主要依赖于可能在训练期间被过度强调的简单和常见操作，无法适应多样化的工具集。
图4：不同模型的工具利用分布。不同模型的使用模式基本一致，最常调用的工具包括放大、范围内颜色、旋转、直方图和连通分量。
偷懒走捷径，缺乏多步组合耐心： 多工具组合仍然是一个高度持久的障碍。分布统计结果显示，尽管真实专家轨迹（Ground Truth）往往需要 4 到 6 步的深度，但模型生成的工具链长度却始终显著短于 GT 需求，大部分预测序列仅在 1 到 2 步后就触顶并过早终止。例如，GPT-5.2 的工具使用效率（

五、 案例定性分析 (Case Study)
对模型输出的定性分析揭示了两种主要的失败模式：
工具选择和执行的复合错误：模型有时会完全基于有缺陷的内在视觉直觉来调用工具，而绕过必要的先决条件。例如，在一道需要测量瞳距的题目中，模型没有去精确提取坐标，而是毫无根据地调用 Draw Circle（画圆）和 Draw Line（画线）工具在图像上乱画，导致得出猜测性的错误答案。这突显了模型在理解特定工具功能及其正确应用上下文方面的关键缺陷。
对未经验证的工具输出过度依赖：模型往往对工具返回的中间结果进行表面分析，并直接采纳为最终答案。例如，在形态学计数任务中，工具返回了明显包含噪声的错误掩码（Mask）图像，但模型完全没有将这些中间结果与原始视觉输入进行交叉验证，盲目采纳了错误的输出。这种缺乏关键验证的步骤阻碍了模型识别和纠正工具生成错误的能力。

六、 全文总结 (Conclusion)
赋予多模态大模型调用外部 API 的能力只是第一步。要让 AI 真正成长为能够应对真实世界计算机视觉流水线的智能体，我们还有很长的路要走。
在本文中，研究团队引入了 VTC-Bench，这是一个精心设计的基准测试，旨在评估 MLLMs 的多步工具组合能力。通过整合跨越 9 个真实世界类别的 32 种多样化 OpenCV 工具，VTC-Bench 的全面性大大超越了以往的评估体系。
通过对 19 种主流 MLLMs 的广泛实验，VTC-Bench 揭示了当前模型在工具编排方面的显著缺陷：模型倾向于使用狭窄的工具子集，导致执行效率低下；模型经常在精确的工具调用上挣扎，或者过度依赖工具输出而忽视了自身的内在感知能力。这些发现强调了在基础视觉感知和主动的智能体推理之间存在着严重的脱节。
VTC-Bench 通过系统地暴露这些根本性的挑战，建立了一个极其严格的基线，为指导未来开发更具泛化能力的视觉智能体架构指明了清晰的前沿方向。
