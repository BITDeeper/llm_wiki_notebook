在自动驾驶领域，多模态大模型（Vision-Language Models, VLMs）正逐渐从实验室走向实车，成为感知与决策的“超级大脑”。然而，要把这些动辄数十亿参数的模型塞进车载计算平台并不容易，尤其是当车辆需要同时处理来自 6 个摄像头的环视图像时，庞大的视觉标记（Token）数量会让推理速度慢如蜗牛。
为了解决这一痛点，来自上海交通大学、上海人工智能实验室、美国卡内基梅隆大学、四川大学、中国科学院大学以及香港大学的研究者们，共同提出了一套名为
Prune2Drive
的即插即用加速框架。
该框架的名字
Prune2Drive
寓意直观——“为驾驶而裁剪”。作者将其定位为一个无需重训、即插即用的视觉 Token 裁剪方案。它通过精简冗余的视觉信息，让模型在保持驾驶决策准确性的同时，能够更轻快地运行。

环视影像：VLM 难以承受之重
目前的自动驾驶系统通常依赖 6 个环视摄像头（前、后、左前、右前、左后、右后）来构建全方位的环境感知。当 VLM 处理这些高分辨率图像时，视觉 Token 的数量会呈爆炸式增长。例如，单张图像可能产生几百个 Token，六路环视加起来就是数千个。
由于 Transformer 架构中注意力机制的计算复杂度是序列长度的平方级，这不仅导致了极高的推理延迟，还占用了海量的显存。之前的研究虽然也尝试过“裁剪”Token，但大多是针对单张图像设计的，忽略了多视角场景下的两个关键特性：
空间与语义的多样性
：不同视角的图像之间存在重叠，且背景信息（如天空、路面）存在大量冗余。
视角重要性差异
：在驾驶任务中，前向视角通常比后向视角包含更多关键决策信息（如红绿灯、行人）。
此外，传统的裁剪方法往往依赖注意力权重，这不仅计算开销大，还无法兼容 Flash Attention 等现代硬件加速技术。
Prune2Drive
正是在这种背景下应运而生，试图寻找一种更智能、更高效的“瘦身”方案。
核心技术：如何聪明地“扔掉”Token？
Prune2Drive
的核心思想非常明确：既然不能全都要，那就只选最有代表性的，并且把更多的资源分配给最重要的视角。

1. 标记级最远点采样 (T-FPS)
为了保证裁剪后的 Token 依然能覆盖场景中的关键信息，作者引入了
标记级最远点采样（Token-wise Farthest Point Sampling, T-FPS）
。
这个灵感来源于点云处理中的经典算法。简单来说，它不是看哪个 Token 的“注意力分数”最高，而是在 Token 的嵌入空间里进行“排队”。
输入与流程
：输入是原始的视觉 Token 序列
。算法首先随机选一个起始 Token，然后迭代地计算剩余 Token 与已选集合之间的余弦距离，每次都贪心地选择距离最远的那个 Token 加入。
语义覆盖最大化
：通过这种方式，T-FPS 能够选出语义最不重复、覆盖面最广的 Token 集合，从而保留了最丰富的场景特征。
轻量高效
：它不需要访问模型的注意力矩阵，单张图像（729 Token）的处理时间仅需 0.02s，计算开销不到总推理时间的 0.1%。

写在最后
Prune2Drive
通过对物理世界的先验知识（如视角重要性）和数学采样技巧（如 T-FPS）的结合，我们完全可以在不损失智能的前提下，让模型变得更轻盈。
当然，作者也提到了一个有趣的挑战：当某些关键物体（如大巴车）在图像中占据巨大且颜色均匀的区域时，T-FPS 在处理占据大面积且颜色均匀的物体（如大巴车）时可能存在采样稀疏的风险。这为未来的研究指明了方向——如何结合语义分割等先验，进一步优化采样策略。
