通义实验室这次把矛头对准的，正是 GUI 自动化在真实环境里最常见、也最难彻底解决的那些翻车点。

Mobile-Agent v3.5
，并同步开源新一代多平台 GUI Agent 基座模型家族
GUI-Owl-1.5
。该家族覆盖
2B/4B/8B/32B/235B
多种参数规模，提供
Instruct
与
Thinking
两条产品化取向不同的路线，目标是让 Agent 在
移动端、PC端与网页端
之间实现统一执行与稳定泛化。
开源地址：https://github.com/X-PLUG/MobileAgent
真实落地最难的，不是“会点”，而是“能做完”
GUI Agent 一到线上环境就会暴露三类硬问题：
高质量轨迹数据太难拿
长任务需要长轨迹监督，成本高；采集时又经常遇到验证码、反爬、页面反馈不确定等干扰，导致成功样本稀缺、失败样本噪声大。
多端差异导致训练互相“拉扯”
手机、PC、网页在交互范式、控件密度、动作空间上差别巨大，直接混在一起学，容易出现梯度冲突与泛化不稳定。
任务闭环不止 GUI 点击
真实工作流往往还需要工具调用、知识检索、记忆记录、跨系统协作与错误恢复。
GUI-Owl-1.5 的定位是把能力补齐到更接近工程系统：
能规划、能执行、能纠错、能记忆，也能在需要时调用工具完成闭环
。
低延迟执行与强规划思考
GUI-Owl-1.5 采用“家族式”发布策略，方便在不同成本与场景下部署：
Instruct 版（2B/4B/8B/32B）
：面向实时交互与边端部署，强调执行效率，不强制输出显式思维链，更适合高频、短链路操作。
Thinking 版（8B/32B/235B）
：面向复杂任务，强化计划、反思与纠错能力，适合长链路、多分支流程。
同时，它也支持更贴近产品形态的
端云协作
：端侧模型负责即时执行与隐私友好的交互，云侧模型负责复杂规划与复盘。
GUI 操作 + MCP 组合成工作流
在任务建模上，GUI-Owl-1.5 将 GUI 操作抽象为持续的“观察—决策—执行—反馈”循环，并采用更工程化的输出组织方式：
先用自然语言给出当前步骤意图（做什么、为什么做）
再输出可执行的结构化调用（点击、输入、滚动、拖拽等），并支持对外部** **MCP 能力的调用
这意味着它既能沿着 UI 完成步骤，也能在合适的节点跳出 GUI，调用工具做校验、查询、写入记忆或跨系统联动，从而更容易形成可组合、可扩展的自动化链路。
复杂界面“点得准”：用数据合成补齐高分辨率 grounding 能力
要在 4K 屏、多窗口遮挡、专业软件等高难界面中准确定位元素，关键在于 grounding 数据覆盖与质量。
GUI-Owl-1.5 团队构建了一套专门面向 GUI 痛点的增强方案，大体包含两条主线：
高难样本合成
：面向专业/复杂应用，借助多模态模型生成更贴近真实的软件截图与元素关系，并配合质量校验迭代；面向多窗口高分辨率场景，则通过窗口布局组合与空间约束检查，降低目标被遮挡、坐标漂移等问题。
规模化扩展与负样本建设
：从真实/仿真轨迹中挖掘 grounding 对并过滤低质样本；从教程与知识库构造 grounding 问答；同时加入不存在控件的负例，让模型学会在找不到目标时减少误触。
DAG 组织子任务与检查点
长链路任务最怕中途某一步失败导致整段监督失效。为此，团队用
DAG（有向无环图）
方式组织任务结构：把长任务拆成可组合的子任务节点，并为节点设计可验证的完成条件。
自动采集时，如果某一步失败，会在最后一个正确检查点处截断，保留干净的成功前缀，再把未完成部分交给修复流程；极少数特别难的 case 再用少量人工示范补齐。
此外，针对验证码、反爬与反馈不精确等线上常见障碍，团队还引入
虚拟环境
，用更可控的方式获得精确的子任务完成信号，并以 RPA脚本 低成本批量产出高质量成功轨迹。
知识、预判与复盘机制
为避免模型只学到下一步怎么点，团队进一步增强了三类关键能力：
GUI 常识注入
：从文档、教程、社区问答中整理并改写为 QA/VQA，提升用户语言—软件功能—操作路径的对齐。
动作后果预测
：从轨迹构造给定动作后的界面变化描述，训练模型学会动手前预判弹窗、焦点变化、内容更新等细节。
统一的推理过程合成
：为每一步补齐观察要点、记忆写入、偏差反思与进度更新，并在涉及 MCP 时给出选择依据，以提升长程稳定性与自我纠错能力。
MRPO 稳定跨平台强化学习
多平台强化学习常见两类不稳定：平台间更新方向冲突，以及 grouped rollout 在某些方法下出现整组全成或全败的信号坍塌。为此团队提出
MRPO（Multi-platform Reinforcement Policy Optimization）
，核心包含：
以设备条件统一策略建模多端差异
在线 rollout 缓冲与抽样成组，降低组坍塌带来的无效训练
推理 token-id 对齐传输，减少不同 tokenizer/离散事件定义导致的估计偏差
多平台交替优化，缓解梯度拉扯，稳定收敛并保持泛化
评测结果：覆盖 20+ 基准，多个方向实现开源 SOTA
