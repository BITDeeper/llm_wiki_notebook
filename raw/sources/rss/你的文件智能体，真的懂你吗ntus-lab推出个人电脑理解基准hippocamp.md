AI Agent 真的能“读懂你”吗？当用户的问题不再来自公开网页，而是藏在日历、邮件、文档、图片、音频和视频等长期积累的个人文件中，Agent 是否还能准确理解、调用并整合这些线索？南洋理工推出的
HippoCamp
，正是这样一个面向真实个人电脑场景的 benchmark。它聚焦 Agent
的个性化记忆与长时程多模态推理能力，系统揭示了当前方法在回答私人定制化问题时的真实瓶颈。
在大模型与 Agent 快速发展的今天，AI 已经越来越像一个“会做事的助手”：它会检索、会调用工具、会处理文档，甚至能完成多步任务。但距离真正有用的个人 AI Agent，还有一个更根本的问题没有被充分回答：
它真的能读懂“你”吗？
“读懂”并不是会读一篇 PDF、看一张图片，或者回答一个孤立问题，而是指：当信息长期分散在你的日历、邮件、文档、图片、音频、视频和文件夹结构中时，Agent 能否把这些线索串起来，形成可调用、可验证的个性化记忆，并据此回答与你本人相关的定制化问题。HippoCamp 正是围绕这一问题提出的benchmark：它面向真实个人电脑环境，系统评测Agent在长期、多模态、个性化文件系统中的
search、perception 和 reasoning
能力，以及由此体现出的
personalized multimodal memory
。

个人 Agent 的盲区：现有评测不足
现有大量 Agent benchmark 主要关注网页交互、工具调用、代码执行，或者边界较清晰的公开任务环境；但真实个人电脑完全不是这样。这里的信息是长期积累的、文件类型是异构的、线索是跨模态分散的，很多答案甚至不会明确写在某一份文件里，而是需要结合时间规律、文件层级和跨文件关系去推断。论文明确指出，当前评测普遍忽略了个人文件系统中这种长期连续性、跨文件验证和个性化推理需求，因此无法真正反映现实个人计算场景中的 Agent 能力边界。

HippoCamp 的意义，就在于把评测环境从“公开网页”真正推进到了“用户自己的电脑”。它不是在问模型会不会做单个任务，而是在问：当 Agent 面对一个长期演化的私人文件系统时，能不能像回忆一个人一样，理解并调用与用户有关的上下文。
HippoCamp 在测什么？
HippoCamp 是一个面向真实个人电脑场景的 benchmark。论文显示，它基于真实用户数据构建了三个原型化的长期个人计算环境，总计包含
42.4 GB 数据、超过 2K 个真实文件、581 个 QA 任务，以及 46.1K 条密集结构化标注
。这些任务不是普通的文件问答，而是围绕用户的长期上下文展开，用来评测 Agent 能否在庞杂的个人文件中完成 grounded retrieval、证据感知和多步推理。
图2：HippoCamp 的层级化标注体系。从原子级证据定位、结构化轨迹，到 factual retention 与 profiling 任务，benchmark 以多粒度监督支持对 Agent 个性化记忆能力的细粒度诊断。
更重要的是，HippoCamp 不把“记忆”理解为静态存储，而是把它落实为一种 Agent 能力：面对长期、大规模、多模态的个人痕迹，系统能否在需要时准确找回、理解、整合并验证相关信息。论文首页的 Figure 1 就展示了这种能力的典型形式：为了回答用户“我周三通常做什么”，Agent 需要把日历事件、文档元数据以及文件夹更新规律等多条线索综合起来，形成用户级推断。
三个长期用户原型，还原真实个人电脑生态
为了让 benchmark 贴近真实个人电脑，而不是简单拼接文件，HippoCamp 构建了三个长期存在的 archetypal personal computing environments。论文说明，这些环境来自真实世界用户数据，并经过聚合、筛选和匿名化处理，用来暴露设备级文件系统中的关键难点，包括深层目录结构、长尾文件类型和跨模态证据依赖。
图3：HippoCamp 中的三个原型化个人电脑环境。Bei、Adam 与 Victoria 分别对应不同的用户背景、文件生态和任务分布，共同构成长期、多模态个人文件系统的代表性场景。
这也是 HippoCamp 和很多传统 benchmark 的一个本质区别：它不是把问题放在一个“平面化”的文档集合里，而是把问题放回一个真正有生活痕迹、有时间延续、有个人风格的文件系统中。在这种环境里，Agent 要回答的不是抽象知识题，而是和“这个用户”直接相关的问题。
从记住事实到理解用户：两类核心任务
围绕真实个人电脑中的长期、多模态信息，HippoCamp 将 Agent 的个性化记忆能力拆分为两类互补任务：
Factual Retention
和
Profiling
。
Factual Retention 关注 Agent 能否从大量个人文件中，找回并回答与用户本人相关的具体事情。这类任务通常具有明确、可验证的文件证据，考察的是系统能否在个人文件系统中准确定位相关线索，理解异构内容，并将多文件信息整合为可靠答案。

相比之下，Profiling 更进一步，关注 Agent 能否从长期分散的多模态线索中，形成对用户更高层次的理解，例如偏好、习惯、行为模式、时间安排以及工作流程。这类任务不再只是回答某个具体事实，而是要求系统在跨文件、跨时间的证据中提炼出稳定的用户级推断。
滑动查看更多Profiling示例
Factual Retention 更侧重“能不能记住用户的具体事情”，而 Profiling 更侧重“能不能真正记住并理解这个用户”。两类任务共同构成了对 Agent 个性化记忆能力的系统评测。
HippoCamp 定位 Agent 的错误
HippoCamp 的另一个重要价值，在于它不是单纯做排行榜。论文特别强调，这个 benchmark 配套提供了 46.1K 结构化轨迹标注，可以把错误定位到搜索、感知和推理等不同阶段，从而支持细粒度 failure diagnosis。换句话说，它不仅告诉你模型答得对不对，还能进一步告诉你：它到底是没找到文件、没看懂内容，还是没把证据整合对。
图4：HippoCamp benchmark 概览。左侧为数据采集与人机协作标注流程，中间为 factual retention 与 profiling 的任务分布，右侧为数据集在 search、perception 与 reasoning 三阶段上的能力标签分布。
这种设计很关键，因为个性化 Agent 的难点本来就不是单点能力，而是一个完整 pipeline：先找，再看，再整合，再验证。任何一步出问题，最终答案都可能失真。

HippoCamp进一步阐述现有agent的问题：
主导性失败来源，并不只是检索本身，而是检索之后的整条后处理链。
论文分析指出，很多方法其实能够找到“部分相关文件”，但随后会在证据筛选、内容 grounding、实体绑定和最终验证上连续出错。也就是说，问题并不只是 recall 不够，而是 Agent 缺少一套真正可靠的 personalized-memory pipeline：它还不会把找到的文件稳定地转化为用户级理解。

这也解释了为什么有些 search-heavy 方法在 factual retention 上还能取得一定分数，但到了 profiling 就明显掉队。原因并不是它们完全找不到线索，而是找到候选文件并不等于形成用户级推理。Profile 层面的回答，本质上仍然需要更强的长时程聚合能力。
HippoCamp 解决的瓶颈问题
从整体上看，HippoCamp 揭示的不是一个单纯的“模型精度问题”，而是一个更接近未来个人 AI 本质的问题：当 Agent 进入真实个人电脑后，它面对的不再是公开网页或单个文档，而是一个长期、多模态、结构复杂、充满私有上下文的文件生态。要在这里工作，它必须具备的不只是检索能力，也不只是视觉理解能力，而是将二者与长时程推理结合起来的
个性化记忆能力
。也正因此，HippoCamp 的贡献不只是“又提出了一个 benchmark”，而是给 personal AI agent 提出了一个更真实、更严格的检验标准：
它能不能在长期个人文件系统中，真正理解并记住一个用户。
迈向真正理解用户的 Agent
HippoCamp 面向真实个人电脑环境，系统评测 Agent 在长期、多模态、个性化文件系统中的能力边界。它以三个原型化的长期个人计算环境为基础，构建了
42.4 GB、2K+ 文件、581 个 QA 和 46.1K 结构化标注
的 benchmark，并通过
Factual Retention
与
Profiling
两类任务，分别考察 Agent 对个人具体事实的回忆能力，以及对用户长期行为模式与偏好的建模能力。
实验结果表明，即便是当前最先进的 Agent 系统，在这一场景下仍然远未达到真正可靠的水平；其主要瓶颈不只是“搜不到”，更在于检索之后的证据感知、跨模态 grounding 与长时程综合推理。如果说过去很多 benchmark 评测的是 AI 会不会“完成任务”，那么 HippoCamp 评测的，是一个更接近未来个人 AI 的核心问题：
AI Agent，究竟能不能真正读懂你。
