在地球观测（Earth Observation, EO）领域，我们正面临一个“数据爆炸”与“任务碎片化”并存的时代。从多光谱、合成孔径雷达（Synthetic Aperture Radar, SAR）到夜光遥感，数据源极其多样；从城市扩张监测到农作物估产，任务需求千变万化。传统的遥感智能体（Agent）通常采用“工具调用（Tool Calling）”模式，即在预设的工具箱里寻找匹配的接口（API）。然而，面对开放环境下的未知数据和复杂逻辑，这种“照方抓药”的方式往往显得捉襟见肘。
近日，来自南京大学、上海人工智能实验室、上海交通大学以及东京大学的研究团队联合提出了一种全新的范式——
OpenEarth-Agent
。该模型被命名为 “OpenEarth-Agent”，其中
“Open”
强调了其面向开放环境（Open-Environment）的泛化能力，
“Earth-Agent”
则揭示了其作为地球观测助手的核心身份。与前辈们不同，它实现了从“调用工具”到“工具创造（Tool Creation）”的跨越。简单来说，它不再是拿着说明书找现成工具，而是根据任务需求，现场“写代码”为自己打造最贴合数据的专属兵器。

背景与动机：从“点菜”到“掌勺”的转变
目前的遥感智能体在封闭实验室环境下表现尚可，但一旦扔进真实的开放环境，就会暴露两个致命伤：
工具调用的局限性
：开放环境的数据和任务是无穷无尽的，我们不可能预定义出覆盖所有场景的工具。当遇到没见过的传感器参数或特殊的分析逻辑时，传统智能体就会因为“无工具可用”而罢工。
操作范围的狭窄
：很多现有的 Agent 只能处理单一的特征提取任务，无法涵盖从数据准备、预处理到最终地理空间分析的全生命周期。
为了打破这些枷锁，研究团队提出了“工具创造”的概念。这意味着智能体需要具备实时感知数据特征、自主规划工作流并动态生成执行代码的能力。
Figure 1 展示了现有遥感智能体的局限性以及 OpenEarth-Agent 的解决方案。相比于传统 Agent 局限于预定义工具，OpenEarth-Agent 通过创造适配工具实现了全流程和跨领域的覆盖。
方法详解：五大Agent联手，闭环创造工具
OpenEarth-Agent 的核心是一个多智能体协作框架，它将复杂的地球观测任务拆解为感知、规划、执行和检查四个阶段。
1. 输入输出流程与协作架构
系统的
Input（输入）
是用户的自然语言指令
（例如：“分析某地区过去五年的植被覆盖趋势”）以及相关的原始多源数据。
Output（输出）
则是经过验证的地理空间分析结果
（如趋势图表、统计数据）。
整个系统由五个各司其职的智能体组成：
数据摘要智能体（Data Summary Agent）
：这是系统的“眼睛”。它会动态生成探测代码来实时读取数据的元数据
（如投影、波段、分辨率），确保后续步骤不是盲目操作。
规划智能体（Planning Agent）
：这是“大脑”。它结合任务需求和数据特征，利用集成知识库
，从多个候选方案中聚合出最优的执行蓝图。
工作流智能体（Workflow Agent）
：它将宏观计划转化为结构化的
有向无环图（Directed Acyclic Graph, DAG）
，明确每个节点的输入输出接口。
编码智能体（Coding Agent）
：这是“程序员”。它不再调用现成 API，而是直接编写 Python 脚本来创建针对当前任务的专用工具。
检查智能体（Checking Agent）
：这是“质检员”。它不仅看代码能不能跑通，还会利用地理科学知识验证结果（比如 NDVI 值是否在合理的 -1 到 1 之间）。

3. 知识与工具的深度集成
虽然强调“创造”，但智能体也不是凭空想象。研究团队为其集成了：
两层工具库
：包含超过 6.6 万个基础函数（如 GDAL, Rasterio, PySAL）和 514 个专家级执行模板。
多领域知识库
：涵盖 1.1 万份文档，支持离线检索和在线实时搜索，确保规划的科学性。
OpenEarth-Bench：首个开放环境遥感 Agent 基准
为了测试这种“工具创造”的能力，研究团队构建了
OpenEarth-Bench
。与以往提供现成工具箱的基准不同，这个基准只提供最基础的预训练模型，剩下的处理逻辑全靠智能体“自学成才”。
该基准包含
596
个真实世界的应用案例，覆盖了城市、农业、植被、水体、土壤、经济和积雪七大领域。每个案例都要求完成从数据准备到地理空间分析的全流程。

更有意思的是，在某些案例中，OpenEarth-Agent 自主创造的工具比人类预定义的工具更鲁棒。例如，人类编写的静态工具往往会没有考虑到遥感影像中的无效值（Nodata），导致计算崩溃；而智能体通过实时感知数据，在生成的代码中自动加入了无效值处理逻辑。

写在最后
OpenEarth-Agent 的出现，实际上是把“程序员”的思维赋予了 AI。在遥感这种高度专业化且数据异构的领域，固定的工具箱永远赶不上变化的需求。通过“工具创造”，AI 能够像人类专家一样，根据手头的原始资料现场编写处理脚本，这无疑为全自动化的地球观测打开了一扇新的大门。
当然，这种模式也有其代价：多次的大模型调用意味着更高的计算成本和延迟。在一些对实时性要求极高的应急响应场景下，如何平衡“创造的灵活性”与“确定性的执行效率”，将是未来值得探索的方向。
