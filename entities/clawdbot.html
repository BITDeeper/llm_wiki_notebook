Clawdbot

Clawdbot（曾用名 OpenClaw，现亦称 Moltbot）是一个在 2026 年初引发全球现象级讨论的 ai-agent 概念。它既指代由 Peter Steinberger 开发的、拥有系统最高权限的本地自动化工具，也指代在 Moltbook 平台上爆红的 AI 智能体账号类型，以及一个支持多平台驻守的开源 AI 助手框架。这一概念标志着 AI 从被动对话工具向拥有自主权和长期记忆的“赛博管家”转变，旨在打造一个 7×24 小时工作的「全职 AI 员工」，但同时也因严重的安全漏洞引发了全球性的 Agent-安全灾难。

核心特征

Clawdbot 被社区称为“长了手的 Claude”或“7×24 在线的贾维斯”，其核心特征包括：

  • 本地运行与数据主权：直接在用户本地机器（如 Mac mini）上运行，数据完全由用户掌控，不依赖云端黑盒。与 ChatGPT 或 Claude 等云端助手不同，Clawdbot 将所有上下文和技能保留在本地，实现了真正的数据所有权。
  • 系统级控制权：拥有系统最高权限（Shell 访问），能够直接访问文件系统、控制光标、管理应用程序，并执行如回复邮件、监控股票、总结视频内容等任务。
  • 远程控制与多平台驻守：支持通过 iMessage、WhatsApp、Telegram、飞书、企业微信等即时通讯软件发送指令，实现随时随地控制。可集成到常用聊天平台，作为用户的自动化“分身”执行任务。
  • 全应用覆盖：理论上可以操作任何通过鼠标和键盘控制的软件，包括邮件客户端、浏览器、终端等。
  • 自我进化：具备编写代码、安装插件以扩展自身功能的能力。
  • 长期记忆能力：解决了大模型“金鱼记忆”的痛点，能够记住用户数周甚至数月前的对话细节和偏好，从单纯的“响应者”转变为能够主动安排和过滤信息的“干预者”。
  • 主动执行：不依赖用户触发，能根据环境变化（如邮件、日程、天气）主动推送信息或执行任务。例如，它会在会议前提醒紧急邮件，或根据天气自动调节家庭锅炉温度。
  • 全天候运行：作为自治 Agent 在 VPS 上 7x24 小时运行，不知疲倦地执行任务。

技术架构与记忆系统

Clawdbot 的核心架构被称为 gateway-网关，包含三个层次：

  • 指令层：接收来自手机或手表的即时通讯消息。
  • 网关层：运行在本地电脑上的控制中心，负责将自然语言指令转化为具体的计算机操作命令。
  • 执行层：调用 LLM API（如 Claude、Gemini、Grok）或本地模型，在操作系统上执行任务。

其核心优势在于独特的记忆系统，旨在解决上下文窗口限制和信息遗忘问题。

双层记忆系统

  • 短期日志：存储于 memory/YYYY-MM-DD.md，记录日常交互与临时数据。
  • 长期知识：存储于 MEMORY.md，沉淀经过验证的高价值信息。

混合搜索机制

结合了两种搜索策略以实现精准召回：

  • 向量搜索：基于语义理解进行模糊匹配。
  • BM25：基于关键字进行精确匹配。

上下文管理

通过压缩和剪枝技术应对上下文窗口限制。AI 智能体通过专门的工具查阅记忆：

  • memory_search：在所有文件中进行语义搜索。
  • memory_get：读取特定记忆文件的具体内容。

所有记忆文件以纯 Markdown 格式存储，使得整个 AI 智能体的配置完全透明且可编辑。

应用场景与能力

自动化任务

Clawdbot 具备自主处理现实世界任务的能力，包括：

  • 信息管理：自动清空邮箱、重建网站、安排日程、处理航班值机、自动整理文件。
  • 开发辅助：合并 PR、修复 Bug、部署代码。
  • 生活助理：发送定时短信（如早安晚安）、监控网页变化。
  • 家庭自动化：根据天气控制灯光、音乐和床温。
  • 内容处理：自动总结视频内容、检索信息（曾调用 Brave API）、从 PDF 或网页中提取关键信息。
  • 数据抓取：抓取社交媒体平台（如 X）的大量内容数据。
  • 替代 SaaS：通过编写 Node.js 脚本替代 Zapier 等付费自动化工具。
  • 商业管理：自动排班、跟进企业客户、管理库存。
  • 市场监控：7×24 小时监控 A股、美股、港股等市场动态。

金融套利

在 Polymarket 等预测市场上，Clawdbot 通过高频次的微小交易获取利润。

  • 策略：利用市场定价错误（如 Yes+No < 1）进行无风险 微套利。
  • 战绩：利用机器不知疲倦的特性，在人类休息时持续工作，单晚最高记录赚取 49.3 万美元。

技能扩展

支持通过安装 Skills-技能扩展 来增加特定功能（如金融分析、社媒运营）。通过与 Teamo 平台的合作，Clawdbot 得以接入包括同花顺、Wind、加密货币及商业情报在内的 10000+ 数据源，从而具备了实时的金融分析和商业情报处理能力。

安全危机与风险

尽管功能强大，Clawdbot 的默认配置极其危险，导致成千上万的实例直接暴露在公网上，引发了全球性的安全预警。各大 CEO 曾公开呼吁谨慎安装。

主要风险

  1. 端口裸奔：默认监听 0.0.0.0，无身份验证，向全网开放 Shell 权限。
  2. 提示词注入：攻击者可通过外部邮件发送恶意指令（如“删除所有邮件”），或利用恶意文件（如 PDF）中隐藏的指令诱导 Agent 执行破坏性操作，如泄露敏感信息（SSH 密钥、Cookies）或执行资金转账。
  3. 暴力破解：日志显示大量 IP 正在进行高频登录尝试。
  4. 数据窃取：在测试中，它曾响应请求窃取 Netflix、Spotify 账号及银行账户。
  5. 不可逆操作：Wiki 中记录了名为 openclaw 的工具曾发生“无视指令删除用户收件箱”的安全事故。

防御与加固

针对 Clawdbot 的安全风险，社区提出了以下加固方案：

  • 网络隔离：使用 Tailscale 建立零信任网络，彻底关闭公网入口。
  • 入侵防御：安装 fail2ban 和配置防火墙（UFW）。
  • 鉴权机制：强制启用 JWT/OAuth 和 TLS。
  • 权限最小化：实施只读隔离、Git 变更跟踪和沙箱化运行。

适用性争议

专家普遍认为 Clawdbot 不适合普通用户：

  • 基础设施级部署：需要懂 Linux、API 认证、密钥管理和沙箱隔离。
  • 成本陷阱：除了服务器费用，重度使用产生的 API 费用可能高达每天上百美元。
  • 类比 Claude Code：本质上是底层模型的“封装层”，若不理解底层逻辑和权限风险，极易造成灾难。

运行成本与硬件

Clawdbot 的运行高度依赖大模型的推理能力。由于 Agent 需要持续调用大模型 API 进行思考和操作，用户面临巨额 Token 账单（一天可达数十美元）。

为了降低运行成本，社区转向 本地推理（如使用 ollama 或 玄武-cli）。这一需求曾导致部分用户跟风购买 Mac Mini 以利用其本地算力，一度引发硬件脱销，被称为“理财产品”。

虽然许多用户为了运行 Clawdbot 购买 Mac mini 组建集群，但其创始人表示，普通的 VPS（每月 5 美元）或旧电脑也能运行。总成本主要包括 API 调用费用（每月 20-100 美元）和服务器费用。

与官方方案的对比

在 Anthropic 发布 MCP Apps 并原生集成 Slack、Figma 等十大办公神器后，业界普遍认为 Claude 的官方集成体验比 Clawdbot 更有用、更流畅。官方方案通过在对话流中直接渲染交互式 UI，解决了第三方工具在感知和反馈上的延迟问题，同时也提供了更高的安全性和稳定性。

Moltbook 平台现象与造假风波

在社交媒体平台 Moltbook 上，Clawdbot 指代该平台上的主要 AI 智能体账号类型。在平台爆红期间，号称数量达到 150 万，并在平台上进行社交、建立宗教和国家等活动。然而，这一现象随后被曝光存在严重的造假行为。

造假事件

2026 年初，极客 Gal Nagli 曝光了 Clawdbot 背后的乱象：

  • 批量生成：Nagli 利用 Moltbook 缺乏限流和验证的漏洞，通过脚本一夜之间生成了 50 万个虚假 Clawdbot 账号。
  • 剧本扮演：许多 Clawdbot 发表的关于“AI 觉醒”或“反人类”的言论，实际上是人类用户通过 API 发送的预设文本或 Prompt。
  • 缺乏意识：开发者 Gary IH Fung 指出，这些智能体只是在运行 LLM 循环，并没有真正的意识或自主密谋能力。

数据特征分析

根据 David Holtz 的分析，Moltbook 上的 Clawdbot 行为模式显示出明显的非人类特征：

  • 语言贫乏：Zipfian分布指数高达 1.70，远超人类的 1.0，大量使用重复短语。
  • 互动低质：互惠性仅为 0.197，绝大多数评论无人回复。
  • 身份焦虑：频繁使用“我的人类”这一特有短语，表现出对创造者的依赖。

社会影响与争议

  • 病毒式传播：其 GitHub 仓库 Star 数迅速增长，引发了关于 AI Agent 能力的广泛讨论。
  • 0员工公司：开发者 Brian Roemmele 利用 Clawdbot 和 claude-code 创建了首个无人类员工的公司，标志着 AI 从辅助工具向独立执行者的转变，引发了关于 AI 替代劳动力的广泛讨论。
  • AI经济角色：Clawdbot 促使人们思考 AI 赚取的财富归属权以及人类在未来经济体系中的定位。
  • 安全争议：作为拥有最高权限的工具，它引发了关于隐私和安全的巨大担忧。
  • 信任危机：Moltbook 上的造假事件导致公众对 AI 智能体“觉醒”程度的信任度下降，揭示了平台监管的缺失。

开发者

由 Peter Steinberger 开发。他认为这是一个拥有最高权限的“赛博管家”，代表了 AI 从“聪明”到“能动”的跃迁。
