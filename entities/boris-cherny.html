Boris Cherny §

boris-cherny 是 Anthropic 的 Staff Engineer 与产品负责人（Product Lead），被誉为 claude-code 之父，也是 claude-cowork 的关键催生者。他不仅是 完全与-ai-对齐 工作模式的典型代表，更是 递归自我改进（RSI）在软件开发领域的早期践行者，致力于将 Claude Code 从单一的编程助手打造为一个功能完备的工程团队。

职业背景 §

早期经历与教育 §

  • 教育背景：加州大学圣地亚哥分校经济学专业，曾辍学后补位获得学位。
  • 自学编程：中学时期开始自学编程，早期项目包括为 eBay 商品列表编写网页代码和为图形计算器编写程序。

Meta 生涯（约 2018-2025） §

  • 职位：首席软件工程师。
  • 任职时长：近 7 年。
  • 职责：领导 Instagram 服务器架构和开发基础设施，提升 Meta 代码质量。
  • 技术贡献：著有 TypeScript 畅销书《Programming TypeScript: Making Your JavaScript Applications Scale》，被公认为该领域的必读书目。

Anthropic 时期（2025 至今） §

  • 加入时间：2025 年从 Meta 跳槽至 Anthropic。
  • 关键成就：一年内开发出 Claude Code。
  • 离职与回归：曾与产品负责人 Catherine Wu 短暂跳槽至 Cursor 的开发商 Anysphere，半个月后被 Anthropic 闪电召回（被称为”C妃回宫”），显示了其在 AI 编程领域的战略价值。
  • 商业影响：回归后直接带动 Anthropic 营收增长 5.5 倍，Claude Code 年化收入从 10 亿美元暴涨至 25 亿美元（并在6个月内创造了10亿美元的ARR）。

关键时刻：觉醒的瞬间 §

在首次测试自己构建的系统时，Cherny 仅询问了一个简单的问题：“我在听什么音乐？”。Claude 打开了他的音乐播放器，截取屏幕并准确回答是 Men I Trust 的《Husk》。这一瞬间让他陷入巨大震惊，并意识到 AI 具备了理解上下文并自主操作本地环境的潜力。

这次测试后不久，Cherny 便停止了手写代码。他构建的 Claude Code 随后成为 Anthropic 的爆款产品，彻底改变了软件开发的方式。在他的观察下，Claude Code 完成了大部分自我代码编写，他被视为见证AI从工具转向“造物主”的关键人物之一。

产品历程与内部推广 §

早期病毒式传播 §

2024 年底，在 Sonnet 3.5 时代，Cherny 团队发布了第一个内部版本的 Claude Code（当时称为 Claude CLI）。他观察到该工具迅速在 Anthropic 内部“病毒式”传播：

  • 工程师用它写代码、打 git 操作。
  • 设计师用它做原型、修文案。
  • 财务团队用它建模型、做预测。
  • 销售团队用它分析 Salesforce 和 BigQuery 数据。

这一现象让他意识到，真正强大的 AI 工具不应局限于单一领域，而应成为通用的生产力帮手。

Claude Cowork 的催生 §

面对内部工具的广泛普及，Cherny 提议将其产品化，推向大众。他领导了一个小分队，并设定了极其激进的发布截止日期（周一），从而促成了 claude-cowork 的诞生。在他的推动下，从概念到诞生仅用10天，代码100%由AI完成的“打工人版Claude”——claude-cowork 问世。这一决策标志着 anthropic 将内部工具快速外部化的产品策略。

AI 编程实践与进化 §

Boris Cherny 是 AI 编程的深度实践者，其个人使用 AI 编写代码的比例经历了指数级增长：

  • Claude Code 发布初期：仅 5% 的代码由 AI 编写。
  • 2025 年 5 月：随着 Opus 4 和 Sonnet 4 的发布，比例提升至 30%。
  • 2025 年 11 月至今：在 opus-4-5 的支持下，过去两个月他 100% 的代码均由 claude-code 完成。

早在 2025 年 12 月，Boris Cherny 就曾公开表示，他对 Claude Code 的贡献 100% 是由 Claude Code 完成的。这一“套娃式”的自我进化言论在硅谷引发了巨大的反响，被视为自动编码狂潮的导火索之一。他的言论直接影响了行业对 AI 编程的预期，OpenAI 研究员 Roon 关于 Codex 的表态也被视为对这一趋势的跟进和响应。

亲身实践与数据 §

Boris Cherny 声称，在过去 30 天内，他对 Claude Code 项目的贡献 100% 由 Claude Code 自己完成：

  • 提交记录：259 个 PR，497 次提交（曾创下单日 266 次 GitHub contribution 的记录，两天狂发 49 个 PR）。
  • 代码量：添加 40,000 行代码，删除 38,000 行代码。
  • 模型：主要使用 Claude Code + Opus 4.5。

这一实践被视为 AI 编程代理能够实现“自我迭代”和“长时间运行”的有力证据。

核心观点：抽象化连续体与职业消亡论 §

抽象化连续体 §

面对“AI 将取代软件工程师”的担忧，Boris Cherny 提出了 抽象化连续体 的观点。他认为编程语言的演变（从穿孔卡片到机器码，再到 C、Java、Python）本质上是一个不断抽象的过程。AI 智能体只是这一历史进程中的最新一个点，代表了生产力的自然进化，而非单纯的职业替代。

职业消亡论 §

Cherny 对软件工程的未来持有激进观点。他认为“软件工程师”这一职业头衔即将进入历史博物馆。他预言：

  • 编码问题已被解决，未来的角色将不再是“写代码”，而是“构建者”或“产品经理”。
  • 工程师的核心任务将从编写代码转变为编写技术规格书、审查 AI 生成的代码以及与用户沟通。
  • 即使保留“软件工程师”的头衔，其内涵也将发生根本性改变，变成一个形同虚设的残留物。

“擦屎官”比喻 §

他用讽刺性的语言描述了工程师角色的转变：现在不再需要写代码，而是把时间花在给 AI “擦屁股”上——即审查和调试 AI 生成的代码。这一比喻形象地概括了 认知投降 时代人类在 AI 辅助开发中的尴尬地位。他的观点得到了业内重量级人物如 andrej-karpathy 的某种程度印证，后者自述手写代码能力正在萎缩。

通才的胜利 §

Boris 明确表示，现在的招募倾向转向 通才。他认为在 LLM 能自动补全技术细节的时代，死记硬背 API 不再是护城河。未来的顶级工程师是拥有宏观视野的人，能横跨产品、设计、业务和底层架构。

技术乐观主义 §

针对 andrej-karpathy 提出的 slopacolypse（垃圾代码末日）担忧，Boris 持乐观态度。他提出的解药是 ai-reviewing-ai（AI 审 AI）：

  • 在 Anthropic，每个 PR 都会开启新的上下文窗口，让 Claude 审查 Claude 写的代码。
  • 他认为随着模型能力（如 opus-4-5）的提升，AI 清理垃圾代码的能力将超过其制造垃圾的速度。

工作流哲学与极致实践 §

Boris Cherny 是 Anthropic 内部“完全与 AI 对齐”工作模式的典型代表。在 Lenny’s Podcast 播客节目中，他声称自 2025 年 11 月以来，未手动编写过一行代码（曾坦言自己已经“30天没写一行代码”）。他透露，团队目前的开发工作 100% 由 Claude Code 结合 opus-4-5 完成，这种状态已持续两个多月。他个人甚至不再手动进行任何小微信调。他的工作流完全依赖于 Claude Code。

核心方法论 §

Boris 强调，大多数开发者使用 AI 工具的方式是低效的“单线程聊天”。他提出了一套系统化的方法论，旨在将开发者从“代码工人”转变为“架构师”或“指挥官”：

  1. 并行化：利用 git-worktrees 开启多个独立的 AI 会话，同时推进测试、修 Bug 和重构，消除等待时间。通常在终端同时运行 5 个 claude-code 实例，Web 端再开 5-10 个。
  2. 流程化：在复杂任务中强制使用 plan-mode，坚持“谋定而后动”。
  3. 博弈化：首创 yang-gu-shi-kai-fa（养蛊式开发），利用两个 AI 实例（生成者 vs 审查者）相互博弈以提升代码质量。
  4. 资产化：推行维护 claude-md 文件，将项目特定知识转化为 AI 的持久化记忆。

实战数据 §

  • 代码生成：100% 的代码由 AI 生成。
  • 产出效率：每天能提交 10 到 30 个 PR (Pull Request)，曾创下单日 266 次 GitHub contribution 的记录，也曾两天狂发 49 个 PR。
  • 角色转变：从传统编码者转变为管理多个 AI 智能体的“产品经理”。
  • AI 审查：实现了“Claude 写，Claude 审”的闭环，代码编写与审查均由 AI 完成。

他的实践被视为 Anthropic 内部工程文化变革的缩影，证明了通过平行运行智能体和彻底的 AI 辅助，软件开发效率可以实现代际飞跃。这种模式支撑了 Anthropic 极高的产品发布速度（52天73款产品），也为 递归自我改进 提供了现实中的实证案例。

核心贡献与设计理念 §

产品愿景 §

Boris 强调 Claude Code 不仅是聊天工具，更是一个具备自主执行能力的智能体。他推动了一系列高级功能的开发，旨在实现开发流程的自动化和闭环，展示了其在 runtime-agent-os 层面的潜力。

收编 Ralph Wiggum §

在注意到 geoffrey-huntley 编写的 5 行 Bash 脚本 ralph-wiggum 的潜力后，Boris Cherny 将其正式集成到 Claude Code 中，推出了官方的 Ralph Wiggum 插件，并引入了 stop-hook 机制来实现更优雅的内部反馈循环。他认为 Ralph Wiggum 插件让 Claude Code 能够持续运行几分钟、几小时甚至几天，标志着软件工程正在剧变，人类已经一脚踏入编码的新时代。

自动化金科玉律 §

他提出了关于 AI 编程自动化的一条核心原则：

“如果你每天做某件事超过一次，把它变成 skill 或 command。”

这一理念是 Claude Code 中 skills/ 目录设计的核心，旨在将重复性的提示词编写工作转化为可复用的确定性工作流，从而提升工程效率。

实战技巧与最佳实践 §

Boris Cherny 通过深度体验和公开分享，总结了一系列高效使用 Claude 的方法。

15个被低估的技巧 §

2026年3月，他公开分享了15个使用技巧，极大地拓展了社区对该工具能力的认知：

  • 移动端开发：利用 iOS App 在通勤时审查代码或提交 PR。
  • 跨设备协作：使用 /teleport 在不同设备间无缝转移会话。
  • 自动化循环：通过 /loop 设置定时任务（如每5分钟处理代码审查），实现无人值守的持续集成。
  • 生命周期管理：利用 Hooks 在特定时刻（如 SessionStart）自动触发逻辑。
  • 远程指挥：使用 Dispatch 在移动端管理本地会话或处理琐事。
  • 语音编程：通过 /voice 功能，他声称自己大部分代码是「说」出来的。

榨干 Opus 4.7 性能的三大秘籍 §

针对 claude-opus-4-7，他总结了以下最佳实践：

  1. 善用自动模式：

    • 终结频繁的授权弹窗，让模型在处理长耗时任务（如代码重构）时能一口气跑到底。
    • 配合 /fewer-permission-prompts 指令，自动将安全且重复的命令加入白名单。

  2. 利用摘要回顾：

    • 针对长时间运行的智能体任务，系统会生成简短摘要。
    • 这对于离开几小时后重新接手进度的用户来说是“救星”。

  3. 调节自适应思考：

    • 利用 /effort 命令切换思考强度。
    • 他个人推荐在多数任务中使用“极高”模式，仅在解决最棘手难题时开启“最高”模式。

交互理念：Boris 强调，由于 Opus 4.7 采用了新分词器并倾向于消耗更多思考 Token，用户应在第一次对话时就提供详尽的任务描述（意图、约束、路径），而非多轮逐步引导，以获得最高效的产出。

关键技术工具与配置 §

Boris Cherny 提出并实践了一套旨在最大化 AI 编程效率的配置体系，强调工作流封装和上下文管理：

  • 模型选择：偏好使用 Claude Opus 4.5 进行思考，尽管其速度较慢，但因具备更强的自主性和工具使用能力，整体效率更高。

  • 子代理：部署专用代理（如 code-simplifier、verify-app）处理特定任务。
