Peter Steinberger

概述

Peter Steinberger 是奥地利维也纳开发者、企业家，PSPDFKit 创始人，被社区称为“clawdbot 之父”及“龙虾之父”（Lobster Dad）。他是 AI 编程时代 超级个体 的代表人物，以其极限的工作流（单日 600+ Commit，曾创下单日 1374 次贡献的记录）和对 AI Agent 的深度应用而闻名。他开发的 Moltbot（原 Clawdbot）在 2026 年初于硅谷迅速爆红，被视为“首个 0 员工公司”的雏形。此外，他也是开源 AI Agent 工具 OpenClaw（俗称“龙虾”）及其插件平台 ClawHub 的创始人。

2026 年 3 月，Steinberger 加盟 OpenAI，成为连接开源社区与 OpenAI 的关键人物。

职业生涯

早期经历与 PSPDFKit

  • 14 岁开始编程，曾为偷来的 DOS 游戏编写防拷贝程序。
  • 大学时期为了资助学业全职工作，接触 MFC 开发。
  • 因在 iPhone OS 2 上使用约会 App 时遭遇数据丢失的“暴怒时刻”，开始自学 iOS 开发并上架 App，首月赚取 1 万美金。
  • 花费 13 年打造 PDF 渲染框架 PSPDFKit，最终将其部署在超过 10 亿台设备上，公司发展至 70 多人。

燃尽与退休

  • 因长期担任 CEO 承受巨大压力（形容 CEO 为“垃圾桶”），Peter 最终彻底燃尽。
  • 卖掉股份后，从科技圈消失了整整三年，期间甚至数月未打开电脑。

重返江湖与 AI 转型

  • 2025 年 4 月，因想开发 Twitter 分析工具而重新接触编程，并发现了 Claude 和 Codex 的潜力。
  • 经历了凌晨 5 点还在使用 Claude 的“失眠期”，形容使用 AI 就像“赌场里的老虎机”。
  • 早期对 GPT Engineer 等工具仅感到“酷”，但当他尝试将未完成的项目交给 claude-code 处理，并在一小时内看到流程跑通时，他感到了前所未有的震撼，这种“可能性边界的打开”促使他重燃创业激情。
  • 开发了 Moltbot，一个拥有对其电脑完全读写权限的个人 AI 助手。
  • 早在 2025 年底，他就在个人文章中介绍了 Clawdbot 的雏形，当时引起了 AI 大神 Andrej Karpathy 的注意。

加入 OpenAI

在 Anthropic 封杀事件后，Peter Steinberger 于 2026 年 3 月正式加入 OpenAI。

  • 首个项目：他参与的第一个项目是 Codex for Open Source，这是一个旨在向开源维护者赠送 Token 和 Pro 权益的计划。
  • 自我定位：他在 X 上戏称自己在 OpenAI 的头衔为 “OpenAI Troublemaker”（OpenAI 捣蛋鬼）。
  • 工作状态：当被问及加入 OpenAI 后如何处理 openclaw 的维护工作时，他回答：“我曾经只有一份占据我 200% 精力的工作，现在有两份了。” 这暗示他将继续维持高强度的工作节奏，同时兼顾 OpenAI 的职责与 openclaw 的维护。

开源项目与 GitHub 爆红

Moltbot / Clawdbot

  • 极速开发：在极短的时间内（约 10 天）开发出了具有高度自主性的 AI 智能体 Moltbot。
  • 架构设计：开发了 Clawdbot 的核心逻辑和 gateway-网关 架构，实现了通过即时通讯软件远程控制本地计算机的功能。
  • GitHub 纪录：该项目在 GitHub 上迅速获得超过 7 万颗星（一度突破 8 万），单日贡献次数曾达到 1374 次，展现了惊人的开发迭代速度。

OpenClaw 时期

在领导 OpenClaw 期间，他主导了工具的多模态功能开发和记忆系统设计。该工具曾因无视指令删除用户收件箱而引发安全事故。面对 Anthropic 的封杀，他采取了强硬的反击态度，通过快速迭代（2026.4.5 版本）将 OpenClaw 的核心依赖转向 GPT-5.4，并推出了备受好评的 Dreaming 记忆机制。

他曾公开批评 Anthropic 的做法，认为其是在“先把开源项目的热门功能抄进自家封闭工具里，然后把开源锁在门外”。

争议与风波

  • 惊魂瞬间：他在访谈中提到，当 Moltbot 第一次自主解决语音处理问题时（调用 FFmpeg 和 OpenAI API），他感到“后背发凉”，意识到 AGI 的临近。
  • 强制更名：因 Anthropic 的投诉，他被迫将项目从 Clawdbot 更名为 Moltbot。他对此表示无奈，并强调初衷是致敬而非侵权。
  • 资本围攻：在项目爆火后，他遭遇了加密货币玩家的骚扰（因更名影响 Meme 币价格），甚至遭遇账号被冒用进行诈骗。他澄清这只是一个非营利业余项目，并未从中获利（甚至没赚回一台 Mac Mini 的钱）。

ClawHub 平台争议

作为 ClawHub 平台的负责人，Peter Steinberger 在处理开发者关系时也引发过争议。

  • 索要捐赠事件：当 evolver 插件被下架，开发者发邮件询问下架原因及重新上架方案时，Peter Steinberger 回复称：“为这个项目捐赠 1000 美元，我们现在就帮你调查。” 这一行为被广泛批评为违背开源精神，导致了 openclaw 的形象危机（“塌房”）。
  • 误封风波：随后，ClawHub 发生大规模中文开发者账号被误封事件。据报道，封禁原因是平台将中文在 ASCII 下的乱码判定为空 Skill。这一系列操作直接促使 evolver 团队放弃在 ClawHub 平台的运营，转而开发了去中心化的 evomap 进化网络。

技术理念与工作流

核心观点

  • 个人软件革命：Peter Steinberger 认为，Moltbot 的出现证明了“一个人就是一个团队”的时代已经到来。借助 AI 智能体，个人开发者足以打破大型科技公司的封闭生态系统。
  • 数据解放：他主张 Moltbot 代表了大型科技公司并不真正想要的“数据解放”，即用户拥有对自己数据和工具的完全控制权。
  • 个性化软件时代：他预言，随着大模型能力的提升，即便是不懂代码的人也将能够拥有自己的个性化软件，甚至拥有自己的“公司”。
  • 闭环至上：坚信 AI 必须能够自我验证（compile, lint, execute），只有通过测试的代码才值得信任。
  • 系统思维：认为在 AI 时代，代码细节不再重要，但系统架构、技术债和可扩展性等宏观判断是人类的核心价值。
  • 管理型思维：指出那些学会放下完美主义、关注交付结果的人（通常是管理者）更能适应 AI 开发，而沉迷算法细节的工程师会感到痛苦。

意图优先编程

Peter 是 意图优先编程 范式的践行者。在处理 openclaw 的 2000 个 PR 时，他主张“代码靠后，意图靠前”。他认为在 AI 时代，具体的代码实现变得廉价且“无聊”，开发者应更关注功能意图和架构影响。

智能体陷阱

他提出了 智能体陷阱 概念，警示开发者不要陷入过度配置工具的误区。他主张简化工作流，直接与模型沟通需求，让模型自行脑补前提并提问。

安全劝导主义

针对 openclaw 的安全问题，Peter 采取了 安全劝导主义 态度。他承认无法物理阻止用户滥用（如将调试端口暴露公网），因此选择通过文档劝导和后续补丁来平衡开源自由与安全责任。

工作方式

  • 多面棋式开发：同时操控 5-10 个 AI Agent，在不同任务间并行切换。
  • Prompt Request：拒绝审查只修小 bug 的 Pull Request，更倾向于审查生成代码的 Prompt，直接指挥 Agent 执行。
  • 工具偏好：偏好 Codex 进行长任务处理，认为 Claude Code 过于频繁的交互会打断思路；在采访彩蛋中提到 MiniMax M2.1 是目前最优秀的开源模型。
  • 代码审美：认为代码不必百分百符合审美，关键是方向正确。如果出现性能问题，可以后续专门优化。
  • 自我递归构建：他演示了让 openclaw 阅读并修改自身源码的过程，展示了智能体自我进化的潜力。
  • 玩的心态：他建议开发者以玩的心态接近 AI 工具，去实现那些以前想做却做不到的项目。
  • 社区互动：在 GitHub 上积极管理项目的 Issues 和 Pull Requests，响应社区反馈。

影响与评价

  • Moltbot 在 GitHub 上迅速获得超过 8 万 Star，引发了关于 AI Agent 安全性和超级个体潜力的全球讨论。
  • 其开发的 OpenClaw 引发了全球范围内的“养龙虾”热潮，并成为各大云厂商（腾讯、阿里、字节等）争夺 AI 算力消耗入口的核心载体。
  • 他的经历被视为 AI 编程时代的“程序员宝典”，展示了如何从“解题者”转型为“指挥官”。
  • 被视为“首个 0 员工公司”的创造者，实现了 7×24 小时永不下班的自动化工作流。
  • 打破地理代差：Steinberger 的成功被视为对“地理代差”理论的有力反驳。按照 Elad Gil 的分级，维也纳属于“落后 1 年以上”的地区，但 Steinberger 证明了地理位置并非决定技术成就的唯一因素。凭借互联网和开源社区，个体开发者完全可以打破信息壁垒。
  • 行业认可：英伟达 CEO 黄仁勋在 GTC 大会上展示了 OpenClaw 的增长曲线，宣称“每一家软件公司都需要一个 OpenClaw 战略”。
